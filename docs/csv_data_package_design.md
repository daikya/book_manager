# Version 2.6 CSVデータパッケージ設計

## 開発中の形式3（2026年10月22日）

以下のVersion 2.6設計は旧形式の履歴として残す。著者管理を追加した開発ソースの出力は形式3で、形式1・2も読込可能。公開済み2.7.0では形式3を読み込めない。

形式3はZIP直下に以下の8ファイルを格納する。エントリ数・展開後サイズ・パス・圧縮率・同名エントリ等の安全検査は全ファイルに適用する。

| ファイル | 内容 |
|---|---|
| manifest.csv | 形式・版番号・各CSVの件数 |
| book_items.csv | 従来の原著者名と参照ISBNを含む書籍 |
| tags.csv | タグ |
| book_item_tags.csv | 書籍タグ関連 |
| reading_histories.csv | 日付・年月精度の履歴 |
| authors.csv | author_key（A000001等）・表示名・識別メモ・登録日時・更新日時 |
| author_aliases.csv | author_key・別名 |
| book_item_authors.csv | book_key・author_key・表示順（0以上の整数） |

manifestへauthor_count・author_alias_count・book_item_author_countを必須追加し、物理行数と照合する。表示名と別名は別人間で重複できる。人物キーの重複、同一人物内の別名の重複、不正な参照先、同じ書籍・著者の重複、同じ書籍内の表示順重複、不正な名前・メモ・日時を拒否する。

復元先の空判定と復元後件数検査は7テーブルを対象とする。著者だけ存在するDBも空とは扱わない。全データをバックアップ後に1トランザクションで復元し、失敗時は著者を含む全テーブルをロールバックする。外部キー整合性を確認してからcommitする。検索用キーは復元時に表示名・別名から再生成する。

旧形式1・2は従来の5ファイルだけを受け付け、管理著者・別名・関連は空で復元する。旧版を名乗るZIPに著者ファイルがあれば、黙って破棄せず拒否する。書籍の原著者名は保持し、自動分割・著者作成・人物統合はしない。

詳細は[著者管理設計](author_management_design.md)を参照。

## 1. 文書の目的

Version 2.6で追加する「完全なデータ移行用CSVパッケージ」と、既存の単一CSV入出力の安全性改善について設計を定める。

本設計の最優先事項は、次の4テーブルに保存される利用者データを、関係を壊さず別環境へ移行できることである。

- `book_items`
- `tags`
- `book_item_tags`
- `reading_histories`

単一CSVは、表計算ソフトで書籍一覧を編集する用途と旧形式との互換性のために残す。完全移行は、アプリケーションが生成・読込するZIP形式のCSVデータパッケージで行う。

## 2. 背景と課題

現在の単一CSVは、書籍の主要項目とタグを入出力できる。一方で、完全な移行手段としては次の不足がある。

- 読書履歴を入出力できない。
- 表紙画像URLを入出力できない。
- 登録日時と更新日時を復元しない。
- CSV全体を検査する前に登録を開始する。
- 行単位でコミットするため、途中失敗時に一部だけ登録され得る。
- インポート直前のバックアップが保証されない。
- 複数テーブル間の関係を表現できない。

このため、単一CSVを無理に多目的化せず、完全移行専用のパッケージ形式を追加する。

## 3. 設計原則

1. **既存の単一CSVを維持する**
   表計算ソフトとの連携と旧ファイルの読込を継続する。
2. **完全移行はZIPパッケージで行う**
   テーブルごとにCSVを分離し、関連をパッケージ内キーで表現する。
3. **移行先の主キーを持ち込まない**
   元DBの整数IDは移行先IDとして使用しない。
4. **全件検査後にだけDBを変更する**
   構文、値、重複、参照関係を事前検査する。
5. **インポートは空のDBだけを対象にする**
   既存データとの統合や競合解決はVersion 2.7以降の検討事項とする。
6. **バックアップ後、1トランザクションで復元する**
   途中失敗時は全変更をロールバックする。
7. **ローカルキャッシュは移行しない**
   表紙画像URLを移行し、画像ファイルは必要時に再取得する。

## 4. 対象範囲

### 4.1 対象

- 完全移行ZIPのエクスポート
- 完全移行ZIPの事前検査
- 空DBへの完全移行ZIPのインポート
- 書籍、タグ、書籍タグ関連、読書履歴の復元
- 登録日時と更新日時の保持
- 表紙画像URLの保持
- インポート前バックアップ
- 1トランザクションによる一括登録
- 既存単一CSVインポートの事前検査と原子性改善
- GUIからのエクスポート、プレビュー、確認、実行、結果表示

### 4.2 対象外

- データが存在するDBへの完全パッケージ統合
- 重複データの対話的マージ
- 元DBの整数主キーの復元
- `cover_image_path` と表紙画像キャッシュファイルの移行
- APIキー、設定ファイル、ウィンドウ状態、一覧表示状態の移行
- バックアップファイル群の移行
- API応答のRawデータの移行
- パッケージ形式の手作業による作成支援

## 5. 既存単一CSVとの役割分担

| 方式 | 主用途 | 書籍 | タグ | 読書履歴 | 日時保持 | 既存データへの追加 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 単一CSV | 一覧編集、他ソフト連携、旧形式互換 | ○ | ○ | × | × | ○ |
| CSVデータパッケージ | アプリ間の完全移行 | ○ | ○ | ○ | ○ | Version 2.6では× |

単一CSVの列構成と旧ヘッダー互換は維持する。完全移行で必要な列を単一CSVへ追加して複雑化しない。

## 6. パッケージ形式

### 6.1 ファイル名

```text
book_manager_data_YYYYMMDD_HHMMSS.zip
```

日時はエクスポート開始時点のローカル時刻を使用する。同名が存在する場合は上書き確認を行い、承認後に置換する。

### 6.2 ZIP内構成

```text
book_manager_data_YYYYMMDD_HHMMSS.zip
├─ manifest.csv
├─ book_items.csv
├─ tags.csv
├─ book_item_tags.csv
└─ reading_histories.csv
```

ZIP直下に上記5ファイルだけを格納する。ディレクトリ、追加ファイル、同名重複、暗号化エントリは認めない。

### 6.3 共通CSV規則

- 文字コード: UTF-8 BOM付き（`utf-8-sig`）
- 改行: `csv`モジュールに委ね、読込時はCRLF/LFの両方を許容
- 区切り文字: カンマ
- 引用符: ダブルクォート
- 先頭行: 必須ヘッダー
- 空値: 空文字列
- Boolean: `はい` / `いいえ`
- 日付: `YYYY-MM-DD`
- 日時: `YYYY-MM-DD HH:MM:SS`
- 行順: エクスポート結果を再現可能にするため、元テーブルのID昇順を基本とする
- ヘッダー名、列数、列順は形式Versionごとに固定する

## 7. manifest.csv

### 7.1 ヘッダー

```csv
key,value
```

### 7.2 必須項目

| key | 値 | 用途 |
| --- | --- | --- |
| `package_format` | `book_manager_csv_package` | 別形式の誤読込防止 |
| `format_version` | `1` | パッケージ仕様Version |
| `application_version` | 例: `2.6.0` | 生成元アプリVersion |
| `database_schema_version` | 例: `7` | 生成元DBスキーマVersion |
| `exported_at` | 日時 | エクスポート日時 |
| `book_item_count` | 0以上の整数 | 書籍件数 |
| `tag_count` | 0以上の整数 | タグ件数 |
| `book_item_tag_count` | 0以上の整数 | 関連件数 |
| `reading_history_count` | 0以上の整数 | 読書履歴件数 |

未知のkeyは将来拡張として警告扱いにし、必須keyの欠落・重複・不正値はエラーとする。

## 8. book_items.csv

### 8.1 ヘッダー

```csv
book_key,ISBN,雑誌コード,書籍名,著者名,出版社,出版形態,内容紹介,表紙画像URL,読了年月,読書状態,お気に入り,評価,備考,登録日時,更新日時
```

### 8.2 項目規則

| 列 | 必須 | 規則 |
| --- | ---: | --- |
| `book_key` | ○ | パッケージ内で一意な `B` + 6桁以上の連番 |
| `ISBN` |  | 形式検証し、同じコードの別書籍は保持する |
| `雑誌コード` |  | 形式検証し、同じコードの別書籍は保持する |
| `書籍名` | ○ | `BookItem`と同じ文字数・空白規則 |
| `著者名` |  | `BookItem`と同じ規則 |
| `出版社` |  | `BookItem`と同じ規則 |
| `出版形態` |  | 定義済み値または空 |
| `内容紹介` |  | `BookItem`と同じ規則 |
| `表紙画像URL` |  | URLまたは空。`cover_image_path`は移行しない |
| `読了年月` |  | 定義済み書式または空 |
| `読書状態` |  | 未読・読書中・読了。空欄は未設定（NULL） |
| `お気に入り` | ○ | `はい` または `いいえ` |
| `評価` |  | 1～5または空 |
| `備考` |  | `BookItem`と同じ規則 |
| `登録日時` | ○ | 正しい日時 |
| `更新日時` | ○ | 正しい日時。登録日時より前は不可 |

`book_key`は関係復元専用であり、移行先の`book_items.id`には使用しない。

## 9. tags.csv

### 9.1 ヘッダー

```csv
tag_key,タグ名,登録日時,更新日時
```

### 9.2 項目規則

| 列 | 必須 | 規則 |
| --- | ---: | --- |
| `tag_key` | ○ | パッケージ内で一意な `T` + 6桁以上の連番 |
| `タグ名` | ○ | 1～30文字、`|`・CR・LFを含まない、名前重複不可 |
| `登録日時` | ○ | 正しい日時 |
| `更新日時` | ○ | 正しい日時。登録日時より前は不可 |

## 10. book_item_tags.csv

### 10.1 ヘッダー

```csv
book_key,tag_key
```

### 10.2 項目規則

- 両列とも必須とする。
- `book_key`は`book_items.csv`に存在しなければならない。
- `tag_key`は`tags.csv`に存在しなければならない。
- 同じ組合せは重複不可とする。
- 関連自体には日時がないため、追加列を持たない。

## 11. reading_histories.csv

### 11.1 ヘッダー

```csv
history_key,book_key,読書開始日,読了日,読書メモ,登録日時,更新日時
```

### 11.2 項目規則

| 列 | 必須 | 規則 |
| --- | ---: | --- |
| `history_key` | ○ | パッケージ内で一意な `H` + 6桁以上の連番 |
| `book_key` | ○ | `book_items.csv`に存在するキー |
| `読書開始日` |  | 正しい日付または空 |
| `読了日` |  | 正しい日付または空 |
| `読書メモ` |  | モデルと同じ文字数規則 |
| `登録日時` | ○ | 正しい日時 |
| `更新日時` | ○ | 正しい日時。登録日時より前は不可 |

開始日、読了日、メモの少なくとも1つを必須とする。開始日と読了日が両方ある場合、開始日は読了日以前でなければならない。

## 12. パッケージ内キー

### 12.1 生成方法

- 書籍: 元の`book_items.id`昇順に `B000001`、`B000002`…
- タグ: 元の`tags.id`昇順に `T000001`、`T000002`…
- 読書履歴: 元の`reading_histories.id`昇順に `H000001`、`H000002`…

元IDは順序決定にだけ使い、キー文字列へ元IDそのものを埋め込まない。キーはZIP内部だけで有効な不透明識別子とする。

### 12.2 インポート時の対応表

登録時に次のメモリ上の対応表を作る。

```text
book_key -> new_book_item_id
tag_key  -> new_tag_id
```

読書履歴とタグ関連はこの対応表を使い、新しく採番されたIDへ接続する。

## 13. エクスポート処理

### 13.1 処理順

1. 保存先を選択する。
2. 読み取り専用の一貫したDBスナップショットを開始する。
3. 4テーブルを取得する。
4. パッケージ内キーと対応表を生成する。
5. 一時ディレクトリへ4データCSVを出力する。
6. 実件数から`manifest.csv`を出力する。
7. 一時ZIPを作成する。
8. ZIPを再度開き、構成とCSV読込を自己検査する。
9. 一時ZIPを最終パスへ原子的に置換する。
10. 一時ファイルを削除し、結果を表示する。

### 13.2 失敗時

- 最終ファイルは作成・上書きしない。
- 作業用ディレクトリと一時ZIPを削除する。
- DBは読み取りだけなので変更しない。
- 利用者には処理段階と原因を表示する。

## 14. ZIP安全性

インポート前に、次を検査する。

- ZIP形式として開けること。
- 必須5ファイルがそれぞれ1つだけ存在すること。
- ZIP直下以外のパスを含まないこと。
- `..`、絶対パス、ドライブ文字を含むエントリがないこと。
- 暗号化エントリ、シンボリックリンク、特殊ファイルがないこと。
- 許可されない追加エントリがないこと。
- エントリ数、各展開サイズ、合計展開サイズが上限内であること。
- 異常な圧縮率を持つZIP bomb相当の内容でないこと。

初期上限値は、通常の個人利用を十分に上回る保守的な値として定数化し、テスト可能にする。

## 15. インポート事前検査

### 15.1 DBを変更しない段階

事前検査ではDBへ一切書き込まない。次の順に検査する。

1. ZIPの安全性と構成
2. `manifest.csv`の形式Versionと必須値
3. 各CSVの文字コード、ヘッダー、列数
4. 各セルの型、必須値、文字数、列挙値、日時
5. 各ファイル内のパッケージキー、タグ名、同一書籍タグ関連の重複
6. ファイル間の参照整合性
7. manifest件数と実件数の一致
8. 移行先DBが空であること

### 15.2 空DBの定義

次の全件数が0であることを必要条件とする。

- `book_items`
- `tags`
- `book_item_tags`
- `reading_histories`

書籍が0件でもタグだけが存在する場合は空DBとみなさない。

### 15.3 検査結果

検査結果は少なくとも次を持つ。

- パッケージ情報
- 各データ種別の件数
- 警告一覧
- エラー一覧
- 実行可能かどうか
- エラーのファイル名、行番号、列名、内容、説明

エラーが1件でもあれば実行ボタンを無効にする。警告だけの場合は内容を表示し、利用者の確認後に実行できる。

## 16. インポート実行

### 16.1 実行条件

- 同じファイルに対する最新の事前検査が成功していること。
- 検査後にファイルが変更されていないことをサイズ、更新日時、SHA-256で確認すること。
- DBが引き続き空であること。

### 16.2 バックアップ

DBが空でも、実行直前に`BackupService.create_backup()`を呼ぶ。バックアップが作成できない場合はインポートを開始しない。

生成したバックアップは世代削除から保護した状態でインポートを実行し、成功後に通常の管理へ戻す。既存の`protected_paths`を利用する。

### 16.3 トランザクション

1つのSQLite接続を開き、明示的にトランザクションを開始する。次の全処理で同じ接続を使用する。

1. `book_items`を登録し、book_key対応表を作る。
2. `tags`を登録し、tag_key対応表を作る。
3. `book_item_tags`を登録する。
4. `reading_histories`を登録する。
5. 件数と外部キー整合性を再検証する。
6. 成功時だけコミットする。

例外、件数不一致、外部キー違反のいずれかが発生した場合はロールバックする。ロールバック後、4テーブルが実行前と同じ状態であることを前提にエラーを表示する。

既存Repositoryは操作ごとに接続を開くため、そのままループ呼出ししない。共有接続を受け取るパッケージ復元専用Repositoryを設ける。

## 17. 日時とデータの復元

- `created_at`、`updated_at`はパッケージ値をそのまま復元する。
- 通常の追加処理で現在日時へ置換しない。
- `updated_at < created_at`は事前検査エラーとする。
- `cover_image_url`は復元する。
- `cover_image_path`は常に`NULL`で登録する。
- 表紙画像は書籍選択時に既存の遅延取得処理で再生成する。
- 空文字列は、対象列の意味に応じて`None`または空文字列へ正規化する。

## 18. 既存単一CSVインポートの安全化

**実装状況：GUIからの安全な取込フローを実装し、Windowsソース版の画面確認と全1713件の自動テストを完了した。配布版2.6.0での検証も完了。**

既存形式と行単位の問題報告は維持しつつ、DB変更方法を改善する。

GUIは`CsvImportService.preview_file`で検査し、確認後に`execute_preview`を呼ぶ。`BookService.prepare_book`はDBを変更せずに入力を正規化・検証する。`BookRepository.add_many`は書籍・タグ・関連付けを1トランザクションで登録する。登録予定が0件の場合は検査結果だけを表示し、バックアップと登録を実行しない。

CSVのSHA-256と登録予定・スキップ・エラーを実行前とバックアップ後に再検査する。検査時に生成する登録日時は比較対象から除外する。旧`import_file`は互換用として残っており、安全なGUI取込はこの旧処理を使用しない。

### 18.1 処理の分離

1. CSV全体を読込み、全行を検査する。
2. 登録可能行、スキップ行、エラー行をプレビュー表示する。
3. 利用者が確定した後、バックアップを作成する。
4. 登録可能行を1トランザクションで登録する。
5. 予期しないDBエラー時は登録可能行をすべてロールバックする。

入力値不正の行を除外して正常行を登録する既存仕様は維持できる。ただし、実行段階の障害による「途中まで登録」は認めない。

### 18.2 互換性

- 現行ヘッダーを維持する。
- タグ列がない旧ヘッダーを引き続き受け付ける。
- タグの`|`区切りを維持する。
- 既存の成功・スキップ・失敗件数と行別説明を維持する。
- 読書履歴と日時の完全移行には単一CSVを使用しない。

## 19. GUI設計

### 19.1 メニュー

CSV関連操作を次のように明確に分ける。

- 書籍一覧をCSVへエクスポート
- 書籍一覧CSVをインポート
- 完全データをZIPへエクスポート
- 完全データZIPをインポート

「完全データ」は書籍、タグ、タグ関連、読書履歴を含むことを説明文に表示する。

### 19.2 完全データのエクスポート

- 保存先選択
- 実行中表示
- 完了時にファイルパスと4種の件数を表示
- 失敗時に最終ファイルが残っていないことを説明

### 19.3 完全データのインポート

1. ZIP選択
2. 事前検査ダイアログ
3. 件数、生成元Version、出力日時、警告・エラー表示
4. 「空のデータベースだけに復元できる」旨を表示
5. 実行確認
6. バックアップ作成とインポート
7. 完了後に一覧、タグ候補、統計表示を再読込

バックアップ作成後に失敗した場合は、DBがロールバック済みであることと、作成したバックアップの場所を表示する。

## 21. エラー分類

| 分類 | 例 | DB変更 |
| --- | --- | ---: |
| パッケージエラー | 必須ファイル欠落、危険なZIPパス | なし |
| 形式エラー | ヘッダー不一致、列数不一致 | なし |
| 値エラー | 不正日付、範囲外評価 | なし |
| 関係エラー | 存在しないbook_key参照 | なし |
| 実行条件エラー | DBが空でない、検査後にZIP変更 | なし |
| バックアップエラー | DBバックアップ失敗 | なし |
| DB実行エラー | 制約違反、I/Oエラー | 全ロールバック |

利用者向け文言とログ向け詳細を分ける。ログには例外情報を残すが、GUIには次に取るべき行動が分かる説明を表示する。

## 22. テスト方針

### 22.1 Model

- manifestと各行Modelの正常・境界・不正値
- キー形式
- 日付・日時
- 空値変換
- Issueのファイル名、行番号、列名

### 22.2 Service

- 0件を含む正常エクスポート
- 全項目、Unicode、カンマ、改行、引用符
- ZIP構成、安全性、サイズ上限、圧縮率
- 必須ファイル欠落、追加、重複
- manifest件数不一致
- 各キー重複、参照先欠落
- タグ名の重複拒否、ISBN・雑誌コードが同じ別書籍の保持
- 読書履歴の日付規則
- 検査後のファイル改変検知
- 一時ファイルの後始末

### 22.3 Repository・統合

- 新しい主キーで全関係が復元されること
- 書籍、タグ、関連、履歴の件数一致
- 日時保持
- 表紙URL保持と表紙パス非保持

- 外部キー検査成功
- 空DB判定

### 22.4 バックアップ

- インポート開始前に作成されること
- 作成失敗時にDBを書き換えないこと
- インポート失敗後もバックアップが残ること

### 22.5 GUI

- メニューと説明
- 事前検査中は実行不可
- エラーありでは実行不可
- 警告だけなら確認後に実行可能
- 成功後の一覧・タグ・統計再読込
- キャンセル時に変更なし

### 22.6 単一CSV回帰

- 現行ヘッダー
- 旧ヘッダー
- タグの復元
- 正常行と不正行の混在
- 実行時障害で全登録対象がロールバックされること

## 23. 実画面検証

1. 通常利用DBから完全パッケージを出力する。
2. ZIP内に5ファイルだけ存在することを確認する。
3. 各CSVの件数と元DB件数を比較する。
4. 検証専用の空DBへインポートする。
5. 書籍、タグ、絞込、読書履歴、統計を画面で確認する。
6. 表紙画像が未キャッシュ状態から選択時に再取得されることを確認する。
7. インポート前バックアップが存在することを確認する。
8. 不正参照を含むZIPで、DBが変更されないことを確認する。
9. 実行途中の疑似失敗で、全変更がロールバックされることを確認する。
10. 既存データがあるDBでは実行できないことを確認する。
11. 既存単一CSVの現行形式と旧形式を確認する。

検証には必ず`BOOK_MANAGER_HOME`で分離した一時保存先を使い、普段の利用者データを直接対象にしない。新規保存先は旧DBの自動移行対象になる場合があるため、空DB検証ではinitialize_databaseで正式な空DBを先に作成し、4テーブルが0件であることを確認してから起動する。
