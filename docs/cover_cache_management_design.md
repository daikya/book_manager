# 表紙画像キャッシュ管理・設定画面配置 設計書

## 1. 目的

Version 2.5では、利用者が表紙画像キャッシュの状態を設定画面から確認し、必要なときだけ安全に削除できるようにする。

あわせて、設定画面を親画面中央より少し上へ配置し、Windowsのタスクバーを除いた作業領域内へ補正することで、画面下部の「閉じる」ボタンを操作しやすくする。

本機能では、データベースと各種設定ファイルを変更せず、表紙画像キャッシュだけを明示的な操作で整理できることを最優先とする。

---

## 2. 現状

### 2.1 表紙画像キャッシュ

現在の`CoverImageService`は、表紙画像URLのSHA-256からファイル名を生成し、利用者データ領域の次の場所へ画像を保存している。

```text
%LOCALAPPDATA%\book_manager\cache\covers
```

同じURLのキャッシュファイルが存在する場合は、HTTP通信を行わず既存ファイルを返す。DBには表紙画像URLと、利用者データルートを基準としたキャッシュパスが保存される。

一方、現在は次の機能を持たない。

* キャッシュファイルの件数と合計サイズの取得
* キャッシュファイルの一括削除
* 削除失敗を継続可能な結果として返す処理
* DBに保存されたパスのファイルがない場合の表紙画像再取得

一覧表示はキャッシュファイルが存在する場合だけサムネイルを生成する。書籍選択時も保存済みファイルが存在しなければ「画像なし」となり、自動再取得は行わない。

### 2.2 設定画面

設定画面を含む既存のサブウィンドウは、`_wait_for_dialog()`から`center_window_on_parent()`を呼び出し、親画面中央へ配置している。

現在の配置処理はTkinterが返す画面全体の幅と高さを基準に補正するため、Windowsのタスクバーを除いた作業領域と一致しない場合がある。また、設定画面だけを上方へ移動する指定はない。

---

## 3. 対象範囲

### 3.1 対象

* 表紙画像キャッシュのファイル件数と合計サイズの取得
* 設定画面へのキャッシュ状態表示
* 設定画面からのキャッシュフォルダー表示
* 確認ダイアログを経た手動削除
* 一部削除失敗時の継続と結果通知
* 削除後の画面表示とキャッシュ状態の更新
* キャッシュがない書籍を選択した場合の表紙画像再取得
* 設定画面の上方配置と作業領域内補正

### 3.2 対象外

* 起動時または一定期間ごとの自動削除
* キャッシュ容量の上限設定
* 最終参照日時による削除
* 書籍ごとの個別キャッシュ削除
* 外部書誌情報の一括再取得
* 一覧表示時の表紙画像一括再取得
* DBに保存された表紙画像URL・キャッシュパスの一括更新
* すべてのサブウィンドウに対する上方オフセット

---

## 4. 基本方針

1. キャッシュ管理は`CoverImageService`へ追加し、GUIからファイル操作を分離する。
2. 設定画面から使用する処理は`ApplicationSettingsService`を経由する。
3. 削除対象は`cover_cache_directory`直下のファイルだけとし、サブディレクトリは走査・削除しない。
4. キャッシュディレクトリ自体は削除しない。
5. DB、バックアップ、ログおよび各種JSON設定ファイルは変更しない。
6. 削除後に一覧を再表示して、メモリ上に残っている表紙サムネイルも消去する。
7. 表紙の再取得は書籍選択時の1件だけとし、一括通信を行わない。
8. 設定画面だけに上方オフセットを指定し、ほかのサブウィンドウは親画面中央配置を維持する。

---

## 5. キャッシュ状態Model

`cover_image_service.py`に、変更不能な結果Modelを追加する。

### 5.1 `CoverCacheStatus`

```python
@dataclass(frozen=True, slots=True)
class CoverCacheStatus:
    file_count: int
    total_size_bytes: int
```

* `file_count`: 管理対象ファイルの件数
* `total_size_bytes`: 管理対象ファイルの合計バイト数

### 5.2 `CoverCacheClearResult`

```python
@dataclass(frozen=True, slots=True)
class CoverCacheClearResult:
    deleted_count: int
    deleted_size_bytes: int
    failed_count: int
    remaining_status: CoverCacheStatus
```

* `deleted_count`: 正常に削除した件数
* `deleted_size_bytes`: 削除直前に取得した対象ファイルサイズの合計
* `failed_count`: 削除できなかった件数
* `remaining_status`: 処理後に再取得したキャッシュ状態

`deleted_size_bytes`は対象ファイルの論理サイズであり、ファイルシステム上で実際に解放された容量を保証する値とはしない。

### 5.3 例外

キャッシュディレクトリを列挙できないなど、処理全体を開始・継続できない場合は`CoverCacheError`を送出する。

個別ファイルの削除失敗は処理全体の例外にせず、ログへ記録して`failed_count`へ加算する。

## 6. `CoverImageService`の責務

### 6.1 状態取得

次の公開メソッドを追加する。

```python
def get_cache_status(self) -> CoverCacheStatus:
    ...
```

処理規則は次のとおりとする。

* キャッシュディレクトリが存在しない場合は0件・0バイトを返す。
* キャッシュディレクトリ直下だけを列挙する。
* 通常ファイルを集計対象とする。
* サブディレクトリとその内容は対象外とする。
* ファイルサイズを取得できない場合は`CoverCacheError`とする。

### 6.2 キャッシュ削除

次の公開メソッドを追加する。

```python
def clear_cache(self) -> CoverCacheClearResult:
    ...
```

処理規則は次のとおりとする。

1. キャッシュディレクトリが存在しなければ、削除0件の結果を返す。
2. 削除開始時点の直下ファイルを確定する。
3. 各ファイルのサイズを取得してから`unlink()`する。
4. 個別ファイルの`OSError`はログへ記録し、次のファイルを処理する。
5. サブディレクトリは削除しない。
6. キャッシュディレクトリ自体は削除しない。
7. 処理後の状態を再取得して結果へ含める。

キャッシュディレクトリはコンストラクターで正規化済みであり、削除処理では外部から任意のパスを受け取らない。これにより、利用者データ領域外を誤って削除する経路を作らない。

---

## 7. `ApplicationSettingsService`の責務

`ApplicationSettingsService`へ、起動時に生成済みの同じ`CoverImageService`を注入する。

```python
cover_image_service: CoverImageService | None = None
```

次の公開メソッドを追加する。

```python
def get_cover_cache_status(self) -> CoverCacheStatus:
    ...

def clear_cover_cache(self) -> CoverCacheClearResult:
    ...
```

`CoverImageService`が未設定の場合、または状態取得・削除に失敗した場合は、設定画面用の`CoverCacheSettingsError`へ変換する。

既存の`get_snapshot()`にはキャッシュ件数とサイズを含めない。APIキーなどの基本設定取得とキャッシュ走査を分離し、キャッシュ状態を取得できない場合でも設定画面自体を開けるようにする。

---

## 8. 依存性注入

`main.py`では、現在の`CoverImageService`インスタンスを次の2か所へ共有して注入する。

* `BookService`
* `ApplicationSettingsService`

新しいHTTPセッションや別の`CoverImageService`は生成しない。書籍表示と設定画面のキャッシュ管理が、同じ保存先を参照することを保証する。

## 9. 設定画面

### 9.1 表示構成

設定画面へ「表紙画像キャッシュ」領域を追加し、次を表示する。

* キャッシュ件数
* 合計サイズ
* 「フォルダーを開く」ボタン
* 「キャッシュを削除」ボタン

既存の利用者データ欄にある表紙画像パス表示は維持する。フォルダー表示処理は既存の`open_directory()`を再利用する。

### 9.2 サイズ表示

合計サイズは1024単位で読みやすく表示する。

```text
0 B
850 B
1.5 KiB
12.3 MiB
1.1 GiB
```

画面上の状態は、次の形式を基本とする。

```text
12件・8.4 MiB
```

状態取得に失敗した場合は設定画面を閉じず、次のように表示する。

```text
取得できません
```

### 9.3 削除確認

削除ボタン押下時は、次の内容を確認ダイアログに表示する。

* 削除対象の件数と合計サイズ
* DBに保存された書籍情報は削除しないこと
* 必要な表紙は書籍選択時に再取得されること
* 操作を取り消せないこと

0件の場合は確認ダイアログを表示せず、「削除する表紙画像キャッシュはありません。」と通知する。

### 9.4 削除中と削除後

* 二重実行を防ぐため、処理中は削除ボタンを無効化する。
* `finally`でボタンを有効状態へ戻す。
* 削除後はServiceから最新状態を取得して表示を更新する。
* 全件成功時は削除件数とサイズを通知する。
* 一部失敗時は削除件数、失敗件数および残存件数を警告表示する。
* 処理全体の失敗時はエラーを表示し、設定画面を継続利用できるようにする。

### 9.5 メイン画面の更新

キャッシュ削除後は次を行う。

1. 現在選択中の書籍と入力フォームをクリアする。
2. 詳細表示の表紙画像参照を解除する。
3. 一覧のサムネイル参照を破棄する。
4. 現在の検索条件と並べ替え条件を維持して一覧を再読み込みする。

選択中の書籍をクリアしてから再読み込みし、削除直後に同じ表紙が自動再取得されないようにする。

## 10. 表紙画像の必要時再取得

### 10.1 実行条件

書籍を選択して詳細を表示するとき、次の条件をすべて満たす場合だけ再取得する。

* DBに表紙画像URLが保存されている。
* DBに保存されたキャッシュパスが未設定、解決不能、またはファイルが存在しない。
* 現在の処理が一覧サムネイル生成ではなく、利用者による1冊の選択である。

### 10.2 処理

1. 既存の`BookService.fetch_cover_image()`で画像を取得する。
2. 取得した画像を詳細表示へ反映する。
3. `create_stored_cover_image_path()`で現在の内部状態を更新する。
4. DBの書籍レコードは自動更新しない。

通常の相対キャッシュパスはURLから同じ保存先が生成されるため、DBを書き換えなくても次回から既存キャッシュを利用できる。

旧Version由来の絶対パスなど、再取得先とDB上のパスが一致しないデータは、そのセッションでは表示できるがDBを暗黙に更新しない。DB更新を伴う移行は別の機能として扱う。

### 10.3 失敗時

ネットワーク障害や画像取得失敗時は「画像なし」表示へ戻し、ログへ記録する。書籍選択のたびに警告ダイアログを表示して操作を妨げない。

一覧サムネイルでは再取得を行わない。これにより、キャッシュ削除後の一覧再表示で多数のHTTP通信が発生することを防ぐ。

## 11. 設定画面の配置

### 11.1 現行処理の課題

現行の`calculate_centered_position()`は、左上が`0, 0`の画面全体を前提にしている。Windowsのタスクバーを除いた作業領域や、負の座標を持つ複数モニターを直接扱わない。

### 11.2 配置計算

既存の`ScreenWorkArea`、`get_screen_work_areas()`および`select_work_area()`をサブウィンドウ配置にも利用する。

配置計算は次の順序で行う。

1. 親画面の矩形を取得する。
2. 親画面との交差面積が最大の作業領域を選ぶ。
3. 親画面中央を基準に子画面の座標を計算する。
4. 設定画面の場合だけY座標へ`-40`ピクセルのオフセットを加える。
5. 最後に作業領域の上下左右へ収まるよう補正する。

上方オフセットは画面内補正より先に適用する。親画面が画面上端付近にある場合は作業領域上端で止め、負の座標へ無理に移動しない。

### 11.3 公開関数

`center_window_on_parent()`へ、既定値0のキーワード専用引数を追加する。

```python
def center_window_on_parent(
    child: tk.Toplevel,
    parent: tk.Misc,
    *,
    margin: int = 0,
    vertical_offset: int = 0,
) -> None:
    ...
```

既定値を0とするため、既存サブウィンドウの呼び出し側は変更しない。設定画面だけを次のように呼び出す。

```python
self._wait_for_dialog(
    dialog,
    vertical_offset=-40,
)
```

`_wait_for_dialog()`にも同じキーワード専用引数を追加し、既存呼び出しの互換性を維持する。

### 11.4 子画面が作業領域より大きい場合

サブウィンドウのサイズ自体は変更しない。子画面が作業領域より大きい場合は作業領域の左上へ配置し、利用可能な範囲を最大化する。

Version 2.5では設定画面のスクロール対応やレイアウトの全面変更は行わない。実機確認で操作領域を表示できない画面サイズが判明した場合は、別途レイアウト変更を検討する。

## 12. エラー処理

| 状況 | 処理 |
| --- | --- |
| キャッシュディレクトリがない | 0件・0バイトとして扱う |
| キャッシュ状態を取得できない | 「取得できません」と表示し、設定画面は開く |
| 削除対象が0件 | 情報通知のみで終了する |
| 個別ファイルを削除できない | 続行し、失敗件数へ加算する |
| ディレクトリを列挙できない | 専用エラーを表示する |
| 表紙画像を再取得できない | 「画像なし」とし、書籍操作を継続する |
| 設定画面の配置計算に失敗 | Tkinterの既定位置で表示する |

例外メッセージやログへGoogle Books APIキーなどの秘密情報を含めない。

## 13. テスト方針

### 13.1 `CoverImageService`

* 未作成ディレクトリを0件として扱う。
* 空ディレクトリを0件として扱う。
* 複数ファイルの件数と合計サイズを返す。
* サブディレクトリを集計・削除しない。
* 全ファイルを削除し、ディレクトリ自体を残す。
* 一部ファイルの削除失敗後も残りを処理する。
* 列挙失敗を`CoverCacheError`へ変換する。
* 既存の取得、キャッシュ再利用、相対パス変換テストを維持する。

### 13.2 `ApplicationSettingsService`

* キャッシュ状態取得を同じ`CoverImageService`へ委譲する。
* キャッシュ削除を委譲する。
* Service未設定時に専用エラーを返す。
* 下位処理の失敗を設定画面用エラーへ変換する。
* 既存のAPIキー、バックアップ設定、フォルダー表示テストを維持する。

### 13.3 GUI

* キャッシュ件数と読みやすいサイズを表示する。
* 状態取得失敗時も設定画面を生成する。
* 0件では削除処理を呼び出さない。
* 確認を取り消した場合は削除しない。
* 削除中はボタンを無効化し、成功・失敗にかかわらず戻す。
* 全件成功後に状態と一覧を更新する。
* 一部失敗時に警告を表示する。
* 削除後も検索条件と並べ替え条件を維持する。
* 一覧サムネイルでは表紙を再取得しない。
* 選択した書籍のキャッシュがない場合だけ1件を再取得する。
* 再取得失敗時に書籍選択を継続できる。

### 13.4 ウィンドウ配置

* `vertical_offset=0`で親画面中央になる。
* `vertical_offset=-40`で設定画面が40ピクセル上へ移動する。
* 上端を超える場合に作業領域上端へ補正する。
* 下端を超える場合に作業領域内へ補正する。
* 負の座標を持つモニターでも正しい作業領域へ配置する。
* 子画面が作業領域より大きい場合に左上へ配置する。
* 既存サブウィンドウがオフセットなしで共通処理を使用する。
* 配置失敗時も例外をGUIへ伝播しない。

### 13.5 結合・回帰確認

* `main.py`が同じ`CoverImageService`を2つのServiceへ注入する。
* キャッシュ削除でDBファイルのハッシュが変化しない。
* バックアップ設定、ウィンドウ状態、一覧表示状態が変化しない。
* 全pytestが成功する。
