## 6. 指摘事項への対応結果

### 6.1 `title` の空文字防止

#### 指摘内容

`title TEXT NOT NULL` だけでは、空文字の保存を防止できません。

#### 対応内容

Serviceで次の検証を行う方針が、`database_design.md` Version 0.2へ反映されました。

```text id="e6y07r"
titleをstripする
↓
空文字か確認する
↓
空文字の場合は検証エラーにする
↓
GUIへエラー内容を返す
```

#### 判定

```text id="lic2ga"
対応完了
```

---

### 6.2 ISBNの正規化

#### 指摘内容

ISBN-10末尾の小文字 `x` を含む、正規化ルールの明確化が必要でした。

#### 対応内容

保存前に次の処理を行う方針が確定しました。

* 前後の空白を除去する。
* 半角空白を除去する。
* 全角空白を除去する。
* ハイフンを除去する。
* ISBN-10末尾の小文字 `x` を大文字 `X` に変換する。

#### 判定

```text id="zpz87q"
対応完了
```

---

### 6.3 ISBN不正時の登録可否

#### 指摘内容

ISBNの検証に失敗した場合、登録を禁止するか警告だけにするかが未確定でした。

#### 対応内容

次の方針が確定しました。

```text id="hsz31i"
ISBNを正規化する
↓
ISBN-10またはISBN-13として検証する
↓
不正な場合は警告結果を返す
↓
GUIが利用者へ警告を表示する
↓
利用者がキャンセルした場合は保存しない
↓
利用者が続行した場合は保存する
```

Serviceは確認ダイアログを直接表示せず、検証結果をGUIへ返します。

#### 判定

```text id="1xkrxg"
対応完了
```

---

### 6.4 雑誌コードの正規化

#### 指摘内容

雑誌コードの保存形式と正規化範囲が未確定でした。

#### 対応内容

Version 0.1では、前後の空白のみを除去します。

次の処理は行いません。

* ハイフンの自動追加。
* ハイフンの自動除去。
* 桁数に基づく自動整形。
* コード構成要素への分割。

重複検索は、保存値との完全一致で行います。

#### 判定

```text id="obd0v8"
対応完了
```


初期化処理では、テーブルとインデックス作成後に次のSQLを実行します。

```sql id="t6unk3"

```

#### 判定

```text id="s8oh9p"
対応完了
```

### 6.7 バックアップ機能

#### 指摘内容

Version 0.1の初期実装に、バックアップ機能を含めるかが未確定でした。

#### 対応内容

バックアップ機能は、初期CRUDの必須範囲から除外します。

次の機能が完成した後に、実装時期を判断します。

* データベース初期化。
* 登録。
* 取得。
* 更新。
* 削除。
* 検索。
* 基本GUI。

バックアップを実装する場合は、SQLiteのバックアップAPIを使用します。

#### 判定

```text id="op2emv"
対応完了
```

---

### 6.8 書影機能

#### 指摘内容

書影機能をVersion 0.1の初期CRUDへ含めるかが未確定でした。

#### 対応内容

書影取得と書影表示は、初期CRUDの必須範囲から除外します。

Version 0.2のスキーマには、次のカラムを含めません。

* 書影URL。
* 書影ファイルパス。
* 書影バイナリデータ。

将来書影を扱う場合も、画像をSQLiteへ直接保存せず、キャッシュディレクトリを使用する方針です。

#### 判定

```text id="bpq894"
対応完了
```

### 6.9 データベースファイルの保存場所

#### 指摘内容

開発中と配布後の保存場所が混在する可能性がありました。

#### 対応内容

開発中は、次の場所を使用します。

```text id="8vd6cq"
data/book_manager.db
```

配布版の保存場所は、この段階では確定しません。

配布方法を設計する際に、OSごとの適切なユーザーデータ保存先を検討します。

#### 判定

```text id="536crv"
対応完了
```

---

### 6.10 部分一致検索とインデックス

#### 指摘内容

`LIKE '%検索語%'` では、通常のインデックスが十分に使用されない場合があります。

#### 対応内容

Version 0.1で想定するデータ件数は、数百件から数千件程度です。

この規模では、通常の部分一致検索で実用上の問題は小さいと判断します。

`idx_book_items_title` は、並び替えや将来の前方一致検索にも利用できるため維持します。

Version 0.1では全文検索やFTSを導入しません。

#### 判定

```text id="ghlw05"
対応完了
```

## 8. 正式なテーブル構造

Design Freeze版のテーブル定義は、次のとおりです。

```sql id="xkxsph"
CREATE TABLE IF NOT EXISTS book_items (
    id INTEGER PRIMARY KEY,
    isbn TEXT,
    magazine_code TEXT,
    title TEXT NOT NULL,
    author TEXT,
    publisher TEXT,
    publication_format TEXT,
    description TEXT,
    completion_month TEXT,
    notes TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

## 9. 正式なインデックス構成

```sql id="00zdrl"
CREATE INDEX IF NOT EXISTS idx_book_items_title
ON book_items(title);

CREATE INDEX IF NOT EXISTS idx_book_items_isbn
ON book_items(isbn);

CREATE INDEX IF NOT EXISTS idx_book_items_magazine_code
ON book_items(magazine_code);
```

## 11. 承認済み設計事項

Version 0.2では、次の設計事項を正式に承認します。

* SQLiteを使用する。
* 開発中のデータベース保存先を `data/book_manager.db` とする。
* スキーマVersionを `PRAGMA user_version = 1` とする。
* `book_items` 単一テーブルとする。
* 主キーを `id INTEGER PRIMARY KEY` とする。
* `AUTOINCREMENT` を使用しない。
* `title` を必須項目とする。
* `title` の空文字をServiceで禁止する。
* ISBNと雑誌コードを任意項目とする。
* ISBNと雑誌コードをTEXTとして保存する。
* ISBNのハイフンと空白を除去する。
* ISBN-10末尾の小文字 `x` を大文字 `X` に変換する。
* ISBNの形式とチェックデジットを検証する。
* 不正なISBNは警告後に登録可能とする。
* 雑誌コードは前後の空白だけを除去する。
* ISBNと雑誌コードの重複を許可する。
* 重複時は警告後に登録可能とする。
* 任意項目の空文字をNULLへ変換する。
* 読了年月を `YYYY-MM` 形式で保存する。
* 登録日時と更新日時をJSTで生成する。
* SQLiteの `CURRENT_TIMESTAMP` を使用しない。
* `title`、`isbn`、`magazine_code` にインデックスを作成する。
* 書籍名の部分一致検索に対応する。
* SQLではプレースホルダーを使用する。
* 削除を物理削除とする。
* 初期CRUDではバックアップ機能を必須としない。
* 初期CRUDでは書影機能を必須としない。
* 書影画像をSQLiteへ直接保存しない。
* Version 0.1では正規化しない。
* Version 0.1では外部キーを使用しない。
* Version 0.1では論理削除を使用しない。

## 12. 実装時の必須事項

SQLite初期化処理とRepository実装では、次の事項を必須とします。

* データベースパスを1か所で管理する。
* `data` ディレクトリがなければ作成する。
* `book_items` テーブルを `IF NOT EXISTS` で作成する。
* 3つのインデックスを `IF NOT EXISTS` で作成する。
* `PRAGMA user_version` を設定する。
* 初期化処理を複数回実行できるようにする。
* SQLではプレースホルダーを使用する。
* データベース接続を確実に閉じる。
* 例外発生時にロールバックする。
* SQLite例外を無条件に握りつぶさない。
* `title` の空文字をServiceで拒否する。
* 任意項目の空文字をNULLへ変換する。
* ISBNを保存前に正規化する。
* ISBNの検証結果をGUIへ返せるようにする。
* 日時をPython側でJSTとして生成する。
* `created_at` を更新時に変更しない。
* `updated_at` を更新時に再生成する。
* 更新件数と削除件数を確認する。

## 13. 実装前テスト項目

データベース初期化処理では、少なくとも次の内容を確認します。

* `data` ディレクトリがない状態から作成できる。
* `book_manager.db` がない状態から作成できる。
* `book_items` テーブルが作成される。
* 3つのインデックスが作成される。
* `PRAGMA user_version` が `1` になる。
* 初期化処理を複数回実行してもエラーにならない。
* 既存データがある状態で初期化してもデータが消えない。
* `title` がNULLの場合は登録できない。
* 任意項目へNULLを保存できる。
* 同じISBNを複数登録できる。
* 同じ雑誌コードを複数登録できる。

* 日本語を正しく保存および取得できる。
* データベースを作成できない場合に例外が通知される。
