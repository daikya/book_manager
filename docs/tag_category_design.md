# タグ・カテゴリ機能 設計書

## 1. 目的

本設計書は、book_manager Version 1.7で追加するタグ・カテゴリ機能の設計を定義する。

書籍ごとに複数のタグを設定し、「小説」「技術書」「仕事」「未整理」など、利用者自身の目的に合わせて蔵書を分類・整理できるようにする。

Version 1.7では、階層を持つ独立したカテゴリ機能は実装しない。複数設定できるタグをカテゴリ用途にも利用し、分類方法と操作を一つにまとめる。

---

## 2. 背景

Version 1.3では、読書状態・お気に入り・評価による蔵書管理を追加した。

Version 1.5では、これらの読書情報による絞り込みを追加した。

Version 1.6では、読書情報による並べ替えを追加した。

これらは全書籍に共通する固定的な管理項目である。一方、利用者が蔵書を整理する観点は、ジャンル、用途、保管場所、購入予定、貸出先などによって異なる。

Version 1.7では、名称を自由に決められるタグを導入し、固定項目だけでは表現できない分類を可能にする。

---

## 3. 対象範囲

Version 1.7では、次の機能を実装対象とする。

* タグの登録
* タグ名の変更
* タグの削除
* 一つの書籍への複数タグ設定
* 複数書籍での同一タグ共有
* 書籍登録・更新時のタグ保存
* 書籍取得時のタグ復元
* 書籍一覧へのタグ表示
* 一つのタグによる書籍の絞り込み
* 既存検索条件とタグ条件のAND検索
* CSVエクスポートへのタグ追加
* CSVインポートへのタグ追加
* タグ列を持たない旧形式CSVとの互換性
* 既存データを保持したデータベース移行

---

## 4. 対象外

Version 1.7では、次の機能を実装しない。

* 階層構造を持つカテゴリ
* タグとカテゴリを別々に管理する仕組み
* タグの色、アイコン、説明文
* タグの任意並べ替え
* 複数タグを指定する高度なAND・OR検索
* タグによる書籍一覧の並べ替え
* 外部書誌情報からのタグ自動設定
* AIによる自動分類
* タグ別の冊数集計およびグラフ表示
* タグの一括付与および一括解除
* 削除したタグの復元

---

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| タグ | 利用者が書籍を分類するために付ける任意の名称 |
| タグマスタ | 登録済みタグを一意に管理する`tags`テーブル |
| タグ関連 | 書籍とタグの組み合わせを管理する`book_item_tags`テーブル |
| タグ未設定 | 書籍にタグ関連が一件も存在しない状態 |
| 使用中タグ | 一件以上の書籍に設定されているタグ |
| 未使用タグ | どの書籍にも設定されていないタグ |

---

## 6. 基本方針

タグ・カテゴリ機能は、次の方針で実装する。

* 一つの書籍へ複数のタグを設定できる。
* 同じタグは複数の書籍で共有する。
* 書籍とタグは多対多関係として正規化する。
* `book_items`へタグ名を連結して保存しない。
* タグ未設定の書籍を許可する。
* 既存の書籍データへ自動的にタグを付与しない。
* タグ名の正規化と検証はService層で行う。
* SQL、トランザクションおよび行変換はRepository層で扱う。
* GUIはRepositoryおよびSQLiteを直接操作しない。
* CSV固有の文字列表現はCSV Serviceで変換する。
* 書籍とタグ関連の保存は同一トランザクションで行う。
* 既存機能の操作方法と責務分離を維持する。

## 7. タグ名仕様

### 7.1 入力値

タグ名はPythonの`str`として扱う。

利用者が入力した一つのタグ名に対して、前後の空白を`strip()`で除去する。

```python
normalized_tag_name = tag_name.strip()
```

内部にある空白は保持する。

例：

| 入力値 | 正規化後 |
| --- | --- |
| `" 小説 "` | `"小説"` |
| `"Python 入門"` | `"Python 入門"` |
| `"　技術書　"` | `"技術書"` |

### 7.2 文字数

正規化後のタグ名は、1文字以上30文字以下とする。

30文字を超える場合は`ValueError`とする。

利用者向けメッセージは次のとおりとする。

```text
タグ名は30文字以内で入力してください。
```

### 7.3 禁止文字

次の文字をタグ名に使用できない。

* 区切り文字として使用する半角縦線`|`
* 改行文字`\r`
* 改行文字`\n`

禁止文字を含む場合は`ValueError`とする。

利用者向けメッセージは次のとおりとする。

```text
タグ名に「|」または改行は使用できません。
```

### 7.4 空文字

正規化後に空文字となるタグは登録しない。

単一タグの登録・名称変更では、空文字を`ValueError`とする。

```text
タグ名を入力してください。
```

書籍フォームまたはCSVのタグ欄全体が空の場合は、タグ未設定として扱い、エラーにしない。

### 7.5 大文字・小文字

Version 1.7では、タグ名の大文字・小文字を区別する。

したがって、次のタグは別のタグとして扱う。

```text
Python
python
```

Unicodeの複雑な正規化や言語依存の同一視は行わない。

### 7.6 重複

前後空白を除去した後、完全一致するタグ名は同一タグとして扱う。

一つの書籍へ同じタグ名が複数回入力された場合は、最初の一件だけを採用する。

入力順に重複を除去した後、保存および表示用としてタグ名の昇順へ並べる。

---

## 8. 区切り形式

### 8.1 区切り文字

複数タグを一つの文字列で表現する場合は、半角縦線`|`を区切り文字として使用する。

```text
小説|歴史|再読予定
```

この形式は、次の場所で共通利用する。

* 書籍登録・編集フォームのタグ入力欄
* 書籍一覧のタグ列
* CSVファイルのタグ列

### 8.2 分割処理

入力文字列は`|`で分割し、各要素の前後空白を除去する。

空要素は無視する。

例：

| 入力値 | 結果 |
| --- | --- |
| `"小説|歴史"` | `("小説", "歴史")` |
| `" 小説 | 歴史 "` | `("小説", "歴史")` |
| `"小説||歴史"` | `("小説", "歴史")` |
| `""` | `()` |

タグ名そのものでは`|`を禁止するため、エスケープ規則は設けない。

### 8.3 出力処理

複数タグを表示またはCSV出力する場合は、正規化済みタグ名を昇順に並べ、`|`で連結する。

## 9. データモデル

### 9.1 Tagモデル

タグマスタの一件を表すため、次のモデルを追加する。

```python
from dataclasses import dataclass


@dataclass(slots=True)
class Tag:
    name: str
    id: int | None = None
    created_at: str | None = None
    updated_at: str | None = None
```

配置先は次のとおりとする。

```text
src/book_manager/models/tag.py
```

`Tag`はデータ保持だけを担当し、正規化、検証、SQLおよびGUI処理を持たない。

### 9.2 BookItemの拡張

`BookItem`へ次の属性を追加する。

```python
tags: tuple[str, ...] = ()
```

属性は既定値を持つ末尾項目として追加する。

可変な`list`ではなく`tuple`を使用し、複数インスタンス間で既定値が共有される問題と、意図しない変更を防ぐ。

タグ未設定は空タプル`()`で表す。`None`は使用しない。

### 9.3 BookItemへタグ名を保持する理由

GUI、検索結果、CSVエクスポートでは、書籍とタグを同時に扱う。

`BookItem.tags`へタグ名を保持することで、GUIが追加のRepository呼び出しを行うことを避ける。

タグIDはデータベース内部の関連管理に使用し、通常の書籍表示では公開しない。

タグマスタの名称変更・削除では`Tag`モデルを使用する。

## 10. データベーススキーマ

### 10.1 スキーマVersion

現在のスキーマVersionは5である。

Version 1.7では、スキーマVersionを6へ更新する。

```python
SCHEMA_VERSION = 6
```

### 10.2 tagsテーブル

```sql
CREATE TABLE IF NOT EXISTS tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    CHECK (length(name) BETWEEN 1 AND 30),
    CHECK (instr(name, '|') = 0),
    CHECK (instr(name, char(10)) = 0),
    CHECK (instr(name, char(13)) = 0)
)
```

| カラム | 型 | NULL | 説明 |
| --- | --- | --- | --- |
| `id` | INTEGER | 不可 | タグID。自動採番 |
| `name` | TEXT | 不可 | 正規化済みタグ名。一意 |
| `created_at` | TEXT | 不可 | 登録日時 |
| `updated_at` | TEXT | 不可 | 更新日時 |

`UNIQUE`制約により、同じタグ名の重複登録をデータベースでも防止する。

### 10.3 book_item_tagsテーブル

```sql
CREATE TABLE IF NOT EXISTS book_item_tags (
    book_item_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    PRIMARY KEY (book_item_id, tag_id),
    FOREIGN KEY (book_item_id)
        REFERENCES book_items (id)
        ON DELETE CASCADE,
    FOREIGN KEY (tag_id)
        REFERENCES tags (id)
        ON DELETE CASCADE
)
```

| カラム | 型 | NULL | 説明 |
| --- | --- | --- | --- |
| `book_item_id` | INTEGER | 不可 | `book_items.id` |
| `tag_id` | INTEGER | 不可 | `tags.id` |

複合主キーにより、同じ書籍とタグの関連を重複登録できないようにする。

### 10.4 インデックス

次のインデックスを追加する。

```sql
CREATE INDEX IF NOT EXISTS idx_book_item_tags_tag_id
ON book_item_tags (tag_id)
```

`book_item_id`から始まる検索は複合主キーのインデックスを利用する。

タグによる書籍検索では`tag_id`から関連を取得するため、専用インデックスを追加する。

### 10.5 外部キー

接続作成時に次の設定を有効にする。

```sql
PRAGMA foreign_keys = ON;
```

既存の`create_connection()`がこの設定を行っていることを実装前に確認する。

有効になっていない場合は、すべての接続で有効になるよう`connection.py`を修正し、自動テストを追加する。

### 10.6 削除時の動作

書籍削除時は、`ON DELETE CASCADE`により`book_item_tags`の関連だけを削除する。

タグマスタは削除しない。書籍削除によって未使用となったタグも残し、利用者がタグ管理画面から明示的に削除できるようにする。

タグ削除時は、`ON DELETE CASCADE`により全書籍との関連を削除した後、タグマスタを削除する。

GUIでは使用中タグの削除前に確認を表示する。

## 11. マイグレーション

### 11.1 Version 5から6への移行

`MIGRATE_VERSION_5_TO_6`として、次の処理を定義する。

1. `tags`テーブルを作成する。
2. `book_item_tags`テーブルを作成する。
3. `idx_book_item_tags_tag_id`を作成する。
4. `PRAGMA user_version`を6へ更新する。

新しいテーブルを追加するだけであり、既存の`book_items`を変更または再作成しない。

既存書籍はすべてタグ未設定として扱う。

### 11.2 新規データベース

`SCHEMA_STATEMENTS`へ新しいテーブルとインデックスの作成SQLを追加する。

新規データベースでは、`book_items`、既存インデックス、`tags`、`book_item_tags`および新インデックスを作成した後、`user_version`を6に設定する。

### 11.3 旧Versionからの連続移行

Version 1から5までのデータベースは、既存の移行処理を順番に実行した後、Version 5から6への移行を実行する。

移行処理は一つのトランザクション内で行う。

途中で失敗した場合は`user_version`だけを進めず、移行全体をロールバックする。

### 11.4 マイグレーションテスト

少なくとも次を確認する。

* 新規データベースがVersion 6で初期化される。
* `tags`テーブルが作成される。
* `book_item_tags`テーブルが作成される。
* タグ検索用インデックスが作成される。
* Version 5から6へ移行できる。
* Version 1から6へ連続移行できる。
* 移行前の書籍データがすべて保持される。
* 移行前の読書状態・お気に入り・評価が保持される。
* 既存書籍のタグが空タプルとして取得される。
* 対応Versionより新しいデータベースを拒否する。
* 外部キー制約が有効である。
* 書籍削除時にタグ関連が削除される。
* タグ削除時にタグ関連が削除される。

## 12. Repository設計

### 12.1 責務

`BookRepository`は、`book_items`に加え、書籍に関連するタグの永続化を担当する。

Version 1.7では小規模なデスクトップアプリケーションとしてトランザクション境界を単純に保つため、独立した`TagRepository`は追加しない。

タグマスタの操作も`BookRepository`へ集約し、書籍本体とタグ関連を一つのSQLite接続で更新する。

将来タグ機能が大きくなった場合は、Repository分割とトランザクション管理方法を改めて検討する。

### 12.2 書籍登録

```python
def add(self, book_item: BookItem) -> BookItem:
    ...
```

既存シグネチャを維持し、`book_item.tags`を同時に保存する。

一つのトランザクションで次を行う。

1. `book_items`へ書籍を登録する。
2. 各タグ名についてタグマスタを取得または登録する。
3. `book_item_tags`へ関連を登録する。
4. 採番された書籍IDと正規化済みタグを持つ新しい`BookItem`を返す。

タグ取得または登録では、`INSERT OR IGNORE`と再検索を利用できる。

`UNIQUE`制約違反を通常の制御フローとして外部へ漏らさない。

### 12.3 書籍更新

```python
def update(self, book_item: BookItem) -> bool:
    ...
```

一つのトランザクションで次を行う。

1. `book_items`を更新する。
2. 更新対象書籍の既存タグ関連を削除する。
3. 新しいタグをタグマスタから取得または登録する。
4. 新しいタグ関連を登録する。

存在しない書籍IDの場合は`False`を返し、タグマスタと関連を変更しない。

### 12.4 書籍取得

次の既存メソッドが返すすべての`BookItem`へタグを設定する。

* `get_by_id()`
* `get_all()`
* `get_all_sorted()`
* 個別検索メソッド
* `search_by_conditions()`

書籍一覧を取得した後、対象書籍IDを使ってタグを一括取得し、`dataclasses.replace()`で各`BookItem.tags`を設定する。

書籍ごとにSQLを実行するN+1構成は採用しない。

概念的な一括取得SQLは次のとおりとする。

```sql
SELECT
    bit.book_item_id,
    t.name
FROM book_item_tags AS bit
INNER JOIN tags AS t
    ON t.id = bit.tag_id
WHERE bit.book_item_id IN (?, ?, ...)
ORDER BY t.name ASC
```

対象書籍が0件の場合は、タグ取得SQLを実行しない。

### 12.5 タグによる検索

`search_by_conditions()`へ次の引数を追加する。

```python
tag_name: str | None = None
untagged_only: bool = False
```

タグ条件が指定された場合は、`EXISTS`を使用する。

```sql
EXISTS (
    SELECT 1
    FROM book_item_tags AS bit
    INNER JOIN tags AS t
        ON t.id = bit.tag_id
    WHERE bit.book_item_id = book_items.id
      AND t.name = ?
)
```

既存の書籍名、著者名、出版社、ISBN、雑誌コード、読書状態、お気に入り、評価条件とはANDで組み合わせる。

`untagged_only=True`の場合は、`book_item_tags`に対象書籍の関連が存在しないことを`NOT EXISTS`で判定する。

`tag_name`と`untagged_only=True`を同時に指定した場合は`ValueError`とする。

いずれのタグ条件も指定しない場合は、既存検索結果を変更しない。

### 12.6 タグマスタ操作

`BookRepository`へ次のメソッドを追加する。

```python
def get_all_tags(self) -> list[Tag]:
    ...

def get_tag_by_id(self, tag_id: int) -> Tag | None:
    ...

def get_tag_by_name(self, name: str) -> Tag | None:
    ...

def rename_tag(
    self,
    *,
    tag_id: int,
    name: str,
    updated_at: str,
) -> bool:
    ...

def delete_tag(self, tag_id: int) -> bool:
    ...

def count_books_by_tag(self, tag_id: int) -> int:
    ...
```

`get_all_tags()`はタグ名の昇順で返す。

`get_tag_by_name()`は名称変更時の重複確認と、書籍保存時のタグ再利用に使用する。

`rename_tag()`は対象が存在する場合だけ更新し、存在しない場合は`False`を返す。

別タグと同じ名称への変更は許可せず、Serviceから利用者向け`ValueError`として通知する。

`count_books_by_tag()`は削除確認メッセージに使用する。

### 12.7 書籍削除

既存の`delete()`を使用する。

外部キーと`ON DELETE CASCADE`によりタグ関連を削除する。

未使用となったタグマスタは自動削除しない。

### 12.8 Repositoryテスト

少なくとも次を確認する。

* タグ未設定の書籍を登録できる。
* 一つのタグを持つ書籍を登録できる。
* 複数タグを持つ書籍を登録できる。
* 同一タグを複数書籍で共有できる。
* 同じ書籍とタグの関連が重複しない。
* 書籍取得時にタグが昇順で復元される。
* 複数書籍のタグを一括取得できる。
* 書籍更新でタグを追加・解除できる。
* 書籍更新失敗時にタグ関連を変更しない。
* 書籍削除で関連だけが削除される。
* 書籍削除後もタグマスタが残る。
* タグ一覧を名称順で取得できる。
* タグ名を変更できる。
* タグを削除できる。
* タグ削除で全書籍との関連が解除される。
* タグごとの使用書籍数を取得できる。
* タグによる検索ができる。
* 既存条件とタグ条件をAND検索できる。
* タグ条件なしの既存検索結果が変わらない。
* SQLへタグ名を安全にバインドする。

## 13. Service設計

### 13.1 責務

`BookService`は、次を担当する。

* タグ名の分割
* タグ名の正規化
* タグ名の検証
* タグ名の重複排除
* 書籍登録・更新時のタグ連携
* タグ検索条件の検証
* タグ名称変更の業務ルール
* Repository結果のGUI向け整理

### 13.2 タグ正規化

次の非公開メソッドを追加する。

```python
@classmethod
def _normalize_tags(
    cls,
    tags: tuple[str, ...] | list[str],
) -> tuple[str, ...]:
    ...
```

処理順序は次のとおりとする。

1. 各要素を`strip()`する。
2. 空文字を除外する。
3. 文字数と禁止文字を検証する。
4. 完全一致する重複を入力順に除去する。
5. タグ名の昇順へ並べる。
6. `tuple`として返す。

文字列一つを直接渡した場合は、文字単位の反復を防ぐため`ValueError`とする。

### 13.3 書籍登録

`add_book()`へ次の引数を追加する。

```python
tags: tuple[str, ...] | list[str] = (),
```

タグを正規化した後、`BookItem.tags`へ設定してRepositoryへ渡す。

既存呼び出し側は引数を省略できるため、タグ未設定として従来どおり動作する。

### 13.4 書籍更新

`update_book()`では、`book_item.tags`を正規化し、新しく生成する`normalized_book_item`へ設定する。

引数として受け取った`BookItem`は直接変更しない。

### 13.5 書籍検索

`search_books()`へ次の引数を追加する。

```python
tag_name: str | None = None
untagged_only: bool = False
```

タグ名は任意文字列と同様に前後空白を除去する。

空文字は条件なしとして`None`へ変換する。

タグ名が指定された場合は、タグ名仕様に従って検証し、Repositoryへ渡す。

`tag_name`と`untagged_only=True`を同時に指定した場合は`ValueError`とする。

検索条件が一つもないかを判定する既存の`all()`対象へ、正規化済みタグ名と`untagged_only`を追加する。

### 13.7 タグ名称変更

名称変更では次を行う。

1. タグIDに対応するタグが存在することを確認する。
2. 新しい名称を正規化・検証する。
3. 現在と同じ名称の場合は変更成功として扱う。
4. 別の既存タグと同名になる場合は拒否する。
5. 現在日時を`updated_at`としてRepositoryへ渡す。

## 16. CSVインポート設計

### 16.1 対応ヘッダー

Version 1.7では、次の二形式を受け付ける。

* 新形式：タグ列を含む15列
* 旧形式：Version 1.6までの14列

新形式を`HEADERS`、旧形式を`LEGACY_HEADERS`として定義する。

いずれにも一致しないヘッダーは、従来どおりファイル全体のエラーとする。

これにより、Version 1.6以前にエクスポートしたCSVを引き続き取り込める。

### 16.2 タグ列の変換

新形式のタグ列を`|`で分割し、各要素の前後空白を除去する。

変換結果は`tuple[str, ...]`とし、`BookService.add_book(tags=...)`へ渡す。

最終的な正規化と検証は`BookService`で行う。

CSV Serviceは区切り形式からPython値への変換だけを担当し、文字数などの業務Validationを重複実装しない。

### 16.3 旧形式

旧形式CSVではタグ列が存在しないため、空タプル`()`を`BookService.add_book()`へ渡す。

その他の列位置は旧形式の定義を使用して取得する。

列追加による固定インデックスのずれを避けるため、ヘッダー形式ごとに列位置を明示するか、ヘッダー名からインデックスを解決する。

### 16.4 タグの登録

CSVに未登録のタグが含まれる場合は、書籍登録と同じトランザクションでタグマスタへ登録する。

既存タグと同名の場合は再利用する。

CSV行が書籍重複によりスキップされた場合、その行にしか存在しないタグは登録しない。

CSV行がValidationエラーとなった場合は、書籍、タグおよび関連を一切登録しない。

### 16.5 エラー処理

一つのタグが不正な場合は、そのCSV行全体をエラーとして扱う。

他の正常行の処理は継続する。

エラー詳細にはServiceから返されたタグValidationメッセージを使用する。

既存の`CsvImportIssue`および`CsvImportResult`の構造は変更しない。

### 16.6 インポートテスト

少なくとも次を確認する。

* 新しい15列ヘッダーを受け付ける。
* 旧14列ヘッダーを受け付ける。
* それ以外のヘッダーを拒否する。
* 一つのタグを取り込める。
* 複数タグを取り込める。
* タグ未設定を取り込める。
* タグ名の前後空白を除去できる。
* 重複タグを一件として取り込める。
* 未登録タグを登録できる。
* 既存タグを再利用できる。
* 不正タグを含む行をエラーにできる。
* エラー行でタグだけが登録されない。
* 重複書籍の行でタグだけが登録されない。
* 正常行とエラー行が混在しても処理を継続できる。
* エクスポートしたCSVを再インポートしてタグを復元できる。
* 既存の読書状態・お気に入り・評価の変換が維持される。

## 19. 性能方針

Version 1.7では個人利用規模を前提とする。

ただし、書籍一覧取得時に書籍件数分のタグ取得SQLを発行しない。

次の方針を採用する。

* 書籍一覧は既存SQLで取得する。
* 対象書籍のタグは一つの追加SQLで一括取得する。
* タグ検索は`EXISTS`とインデックスを利用する。
* タグ一覧は必要な画面更新時に取得する。
* 過剰なキャッシュは導入しない。

ページング、全文検索およびタグ件数の事前集計はVersion 1.7の対象外とする。

## 20. セキュリティ方針

タグ名を含むすべての値は、SQLへ文字列連結せずプレースホルダーで渡す。

テーブル名およびカラム名へ利用者入力を使用しない。

CSVの解析はPython標準`csv`モジュールを利用する。

CSVをExcelなどで開いた場合の数式実行対策は既存CSV仕様の範囲を維持し、Version 1.7だけで新しい独自変換を追加しない。必要な場合はCSV機能全体の課題として別途設計する。

## 21. 既存機能との互換性

### 21.1 BookItem

`tags`へ既定値`()`を設定するため、既存の`BookItem`生成コードは変更しなくても動作する。

### 21.2 BookService

`add_book()`の`tags`は既定値を持つキーワード専用引数とし、既存呼び出しを維持する。

`search_books()`のタグ条件も既定値を持ち、既存検索を変更しない。

### 21.3 BookRepository

既存公開メソッドの戻り値と基本的な意味を維持する。

返却される`BookItem`に`tags`が追加されるが、既存コードは属性を参照しなければ影響を受けない。

### 21.4 GUI

登録、更新、削除、検索、並べ替え、CSV、バックアップおよび復元の既存操作を維持する。

タグ列追加後も横スクロールを利用できるようにし、既存列を削除しない。

### 21.5 CSV

エクスポートは新15列形式へ更新する。

インポートは新15列形式と旧14列形式の両方に対応する。

任意形式のCSVやVersion 1.2以前の異なるヘッダー形式まで自動判定する機能は追加しない。

### 21.6 バックアップ・復元

SQLite Backup APIはデータベース全体を扱うため、新テーブルもバックアップ対象となる。

復元後の初期化処理でスキーマVersionを確認し、Version 6のタグテーブルを利用できるようにする。

Version 6より新しいバックアップを拒否する既存方針を維持する。

## 27. 設計上の決定事項

Version 1.7では、次を正式な設計判断とする。

* タグをカテゴリ用途にも使用し、独立したカテゴリ機能は設けない。
* 書籍とタグは多対多関係とする。
* `tags`と`book_item_tags`を追加する。
* スキーマVersionを5から6へ更新する。
* `BookItem.tags`は`tuple[str, ...]`とする。
* タグ名は1文字以上30文字以下とする。
* タグ名は前後空白を除去し、大文字・小文字を区別する。
* 複数タグの区切り文字は`|`とする。
* タグ名では`|`と改行を禁止する。
* タグは名称昇順で保存・表示する。
* 書籍取得時のタグは一括取得し、N+1 SQLを避ける。
* Version 1.7の検索は一つのタグまたはタグ未設定による絞り込みとする。
* タグ列による並べ替えは実装しない。
* 未使用タグは自動削除しない。
* 同名タグへの名称変更で自動統合しない。
* CSVは新15列と旧14列の両方をインポートできるようにする。
* 書籍とタグ関連の更新は一つのトランザクションで行う。

---

**Version 1.7 タグ・カテゴリ機能方針：複数タグによる自由な蔵書分類を、既存データと操作性を維持しながら安全に追加する。**
