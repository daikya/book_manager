Last Updated : 2026-07-22
Status : Approved / Design Freeze

## 1. 目的

この文書は、`book_manager` プロジェクトにおけるGUI層の設計を定義するものです。

GUIは、利用者による書籍情報の入力、一覧表示、検索、登録、更新、削除および重複候補確認を担当します。

GUIはアプリケーションロジックやデータベース処理を直接実装せず、Design Freeze済みの `BookService` を通じて処理を行います。

```text

```

---

## 5. GUIの基本方針

GUI設計では、次の方針を採用します。

```text
単一ウィンドウ構成
一覧と入力フォームを同一画面に配置
主要操作をボタンで実行
一覧選択と入力フォームを連動
BookServiceを通じて処理
GUIからRepositoryを直接呼ばない
GUIからSQLiteを直接操作しない
GUIからValidatorを直接呼ばない
入力エラーはダイアログで表示
重大でない処理失敗は利用者へ明示
処理成功後は一覧を更新
```

## 12. 起動処理

`main.py` は、次の順序でアプリケーションを起動します。

```text
データベースパスを決定する
↓
データベースを初期化する
↓
BookRepositoryを生成する
↓
BookServiceを生成する
↓
Tkルートウィンドウを生成する
↓
BookManagerApplicationを生成する
↓
mainloopを開始する
```

概念コード：

```python
def main() -> None:
    database_path = ...
    initialize_database(database_path)

    repository = BookRepository(database_path)
    service = BookService(repository)

    root = tk.Tk()

    BookManagerApplication(
        root,
        service,
    )

    root.mainloop()
```

## 15. レイアウト方式

GUIレイアウトには、原則として `grid()` を使用します。

理由：

* 行と列を明示しやすい。
* 入力フォームへ適している。
* ウィンドウサイズ変更に対応しやすい。
* `pack()` との混在による混乱を避けられる。

同一親ウィジェット内では、`grid()` と `pack()` を混在させません。

ウィンドウサイズ変更へ対応するため、必要な行と列へ `weight` を設定します。

```text

ハイフン除去

```

---

## 21. 雑誌コード検索

検索種類が「雑誌コード」の場合、次を呼び出します。


## 22. 検索結果

検索結果は、書籍一覧TreeViewへ表示します。

検索結果が0件の場合は、一覧を空にして状態表示を更新します。

例：

```text

```

0件であることをエラーダイアログにはしません。

タイトル：

```text

```

```text

```

例：

## 31. 一覧行の識別

TreeViewの各行には、`BookItem.id` を文字列化して `iid` に設定します。

```python
tree.insert(
    "",
    "end",
    iid=str(book.id),
    values=(...),
)
```

`BookItem.id` が `None` のデータは、TreeViewへ追加しません。

保存済みデータにIDがない場合はデータ不整合として扱い、開発時に検出できるようにします。

---

## 32. 一覧選択時の処理

利用者が一覧行を選択した場合、次の処理を行います。

```text
選択されたiidからIDを取得
↓
service.get_book()を呼び出す
↓
取得したBookItemを入力フォームへ表示
↓
編集対象IDとして内部保持
```

TreeViewに表示されていない項目も、`get_book()` で再取得してフォームへ表示します。

---

## 33. ダブルクリック

## 34. 選択解除

```python

)
```

内部で保持している編集対象IDも `None` に戻します。

## 45. 入力変数

単一行入力には、`tk.StringVar` を使用します。

```python
self._title_var = tk.StringVar()
self._isbn_var = tk.StringVar()
self._magazine_code_var = tk.StringVar()
self._author_var = tk.StringVar()
self._publisher_var = tk.StringVar()
self._publication_format_var = tk.StringVar()
self._completion_month_var = tk.StringVar()
```

内容紹介と備考は、`Text.get()` で取得します。

末尾にTkinterが自動付加する改行を含めないため、次の形式を使用します。

```python
text_widget.get(
    "1.0",
    "end-1c",
)
```

これは業務上の正規化ではなく、Tkinter固有の値取得処理です。

## 47. 操作ボタン

## 48. 新規登録ボタン

「新規登録」ボタンは、入力フォームの内容を新しい書籍として登録します。

一覧で既存書籍が選択されている場合でも、新規登録として動作します。

ただし、誤操作防止のため確認ダイアログを表示します。

```text
現在、既存の書籍が選択されています。
入力内容を新しい書籍として登録しますか？
```

利用者が登録を承認した場合、選択中の既存データは変更せず、新しい書籍として登録します。

登録成功後は、新しく登録された書籍へ一覧選択を移します。

---

## 49. 更新ボタン

「更新」ボタンは、現在選択されている書籍を更新します。

編集対象IDが `None` の場合は、処理を行わず警告を表示します。

タイトル：

```text
更新対象なし
```

本文：

```text
更新する書籍を一覧から選択してください。
```

## 50. 削除ボタン

「削除」ボタンは、現在選択されている書籍を削除します。

削除前には確認ダイアログを表示します。

```text
「吾輩は猫である」を削除しますか？
この操作は元に戻せません。
```

## 51. 入力クリアボタン

「入力クリア」ボタンでは、次の処理を行います。


# 新規登録フロー

## 54. 新規登録の基本フロー

新規登録処理は、次の順序で行います。

```text
入力フォームから値を取得
↓
既存書籍の選択状態を確認
↓
選択中の場合は新規登録確認
↓
重複候補を検索
↓
候補がある場合は重複確認
↓
利用者が登録を継続
↓
service.add_book()を呼び出す
↓
成功メッセージ
↓
一覧再読み込み
↓
登録した書籍を選択
↓
入力フォームへ登録結果を表示
```

---

## 55. 入力値取得

GUIは、各入力欄から値を文字列として取得します。

```python
title = self._title_var.get()
isbn = self._isbn_var.get()
description = self._description_text.get(
    "1.0",
    "end-1c",
)
```

GUIでは、`strip()` や空文字列から `None` への変換を行いません。

Serviceへそのまま渡します。

---

## 56. 重複候補確認

登録前に、次を呼び出します。

```python
candidates = service.find_duplicate_candidates(
    isbn=isbn,
    magazine_code=magazine_code,
)
```

ISBNと雑誌コードの両方が空の場合は、空リストが返ります。

---

## 57. 重複候補がない場合

重複候補が0件の場合は、そのまま登録処理へ進みます。

```python
service.add_book(...)
```

---

## 58. 重複候補がある場合

重複候補が1件以上ある場合は、確認ダイアログを表示します。

タイトル：

```text
重複候補があります
```

本文例：

```text
同じISBNまたは雑誌コードを持つ書籍が登録されています。

・ID 15：吾輩は猫である
・ID 8：吾輩は猫である 新装版

このまま新しい書籍として登録しますか？
```

利用者が「はい」を選択した場合だけ登録します。

「いいえ」の場合は登録を中止し、入力内容を保持します。

---

## 59. 重複候補の表示件数

初期Versionでは、確認ダイアログに最大5件まで表示します。

6件以上ある場合は、次の文言を追加します。

```text
ほかにも候補があります。
```

---

## 60. 重複候補はエラーではない

重複候補が存在しても、登録禁止にはしません。

最終判断は利用者が行います。

`add_book()` は重複を理由に失敗しません。

---

## 61. 登録成功

登録成功後は、情報ダイアログを表示します。

タイトル：

```text
登録完了
```

本文：

```text
書籍情報を登録しました。
```

その後、一覧を再読み込みします。

---

## 62. 登録エラー

`BookService.add_book()` が `ValueError` を送出した場合は、次のダイアログを表示します。

タイトル：

```text
入力エラー
```

本文：

```text
ValueErrorのメッセージ
```

エラー発生時は、入力内容を保持します。

# 更新フロー

## 63. 更新の基本フロー

更新処理は、次の順序で行います。

```text
編集対象IDを確認
↓
入力フォームから値を取得
↓
重複候補を検索
↓
自分自身のIDを候補から除外
↓
候補が残る場合は重複確認
↓
更新確認ダイアログ
↓
更新用BookItemを生成
↓
service.update_book()を呼び出す
↓
成功時に一覧再読み込み
↓
更新した書籍を再選択
↓
入力フォームを更新
```

重複確認は、通常の更新確認より先に行います。

これにより、重複候補を確認した後で最終的な更新意思を確認できます。

---

## 64. 更新用BookItem

GUIは、選択中のIDと入力値を使って更新用 `BookItem` を生成します。

```python
book_item = BookItem(
    id=self._selected_book_id,
    title=self._title_var.get(),
    isbn=self._isbn_var.get(),
    magazine_code=self._magazine_code_var.get(),
    author=self._author_var.get(),
    publisher=self._publisher_var.get(),
    publication_format=(
        self._publication_format_var.get()
    ),
    description=self._get_description(),
    completion_month=(
        self._completion_month_var.get()
    ),
    notes=self._get_notes(),
)
```

`created_at` と `updated_at` は、GUIでは設定しません。

Serviceが既存値と現在日時を使用します。

---

## 65. 更新時の重複確認

更新時にも、ISBNまたは雑誌コードの重複候補を確認します。

```python
candidates = service.find_duplicate_candidates(
    isbn=isbn,
    magazine_code=magazine_code,
)
```

取得後、自分自身のIDを候補から除外します。

```python
candidates = [
    candidate
    for candidate in candidates
    if candidate.id != self._selected_book_id
]
```

候補が残る場合は、重複確認ダイアログを表示します。

利用者が「いいえ」を選択した場合は、更新処理を中止し、入力内容を保持します。

---

## 66. 更新確認

重複候補確認が完了した後、更新確認ダイアログを表示します。

タイトル：

```text
更新確認
```

本文：

```text
選択中の書籍情報を更新しますか？
```

利用者が「いいえ」を選択した場合は、入力内容を保持して処理を終了します。

---

## 67. 更新成功

`service.update_book()` が `True` を返した場合、情報ダイアログを表示します。

タイトル：

```text
更新完了
```

本文：

```text
書籍情報を更新しました。
```

その後、一覧を再読み込みし、同じIDの書籍を再選択します。

---

## 68. 更新対象なし

`service.update_book()` が `False` を返した場合、対象データが存在しません。

警告ダイアログ：

タイトル：

```text
更新できません
```

本文：

```text
更新対象の書籍が見つかりませんでした。
一覧を再読み込みしてください。
```

その後、一覧を再読み込みし、フォームをクリアします。

---

## 69. 更新エラー

`ValueError` が送出された場合は、入力エラーダイアログを表示します。

入力内容と一覧選択は保持します。

# Version 1.3 読書ステータス対応

Version 1.3の読書ステータス管理機能追加に伴い、GUIへ読書状態の入力・表示機能を追加する。

本対応では、既存の画面構成と操作性を維持しながら、読書状態を日常的に確認・変更できるようにする。

読書状態追加のために画面を縦方向へ拡大せず、既存の入力フォーム内へ横並びで配置する。

---

## 138. 基本方針

Version 1.3のGUI対応では、次の方針を採用する。

* 読書状態を入力フォームから選択できるようにする。
* 読書状態は「未設定」「未読」「読書中」「読了」の4種類とする。
* 読書状態には`ttk.Combobox`を使用する。
* Comboboxは`readonly`とし、任意の文字列を入力できないようにする。
* GUIでは利用者が理解しやすい日本語表示を使用する。
* BookServiceへ渡す値は内部値へ変換する。
* 読書状態と読了年月は独立して扱う。
* 読書状態の変更によって読了年月を自動変更・自動削除しない。
* 書籍一覧へ読書状態を表示する。
* 読書状態はVersion 1.3では検索対象にしない。
* 読書状態はVersion 1.3ではソート対象にしない。
* 初期ウィンドウの高さは800pxを超えない。
* 新しい入力行を追加しない。
* 既存の一覧表示件数および書籍情報表示領域を可能な限り維持する。

---

## 139. GUI表示値と内部値

GUI上の読書状態と、BookItemおよびデータベースで使用する内部値は次のように対応する。

| GUI表示 | 内部値 |
| --- | --- |
| 未設定 | `None` |
| 未読 | `unread` |
| 読書中 | `reading` |
| 読了 | `completed` |

GUIでは内部値をそのまま表示しない。

既存書籍の`reading_status`が`None`の場合は「未設定」と表示する。

---

## 140. 読書状態入力

読書状態には`ttk.Combobox`を使用する。

候補は次の4種類とする。

```text
未設定
未読
読書中
読了
```

Comboboxは次の状態とする。

```python
state="readonly"
```

これにより、利用者が定義されていない文字列を直接入力できないようにする。

---

## 141. 入力変数

読書状態用の`StringVar`を追加する。

概念上は次の形式とする。

```python
self._reading_status_var = tk.StringVar(
    master=self._root,
    value="未設定",
)
```

初期値は「未設定」とする。

---

## 142. GUI配置

Version 1.3では、読書状態追加のために新しい入力行を追加しない。

既存の読了年月と同じ行へ、読書状態を横並びで配置する。

基本配置は次のとおりとする。

```text
読了年月 [2026-07]    読書状態 [未設定 ▼]
```

現在、読了年月入力欄付近に表示している、

```text
例：2026-07
```

の補助表示は、横方向のスペースを確保するため削除する。

読了年月の入力形式自体は従来どおり、

```text
YYYY-MM
```

とする。

---

## 143. ウィンドウサイズ

Version 1.3では、既存画面の縦方向をこれ以上拡大しない。

初期ウィンドウサイズの高さは、

```text

```

を上限とする。

読書状態追加後も、現在の初期ウィンドウサイズを維持する。

新機能追加のために`WINDOW_SIZE`の高さを増加させない。

---

## 144. 入力フォームの表示領域

読書状態は既存行へ横並びで配置し、次の領域を可能な限り維持する。

* 書籍一覧の表示件数
* 内容紹介の表示領域
* 備考の表示領域
* 操作ボタン領域
* 状態表示領域

入力フォーム全体を縦スクロール前提の構成には変更しない。

必要な調整は横方向の配置およびウィジェット幅を優先する。

## 145. 書籍選択時

```python
self._service.add_book(

)
```

読書状態が「未設定」の場合は`None`を渡す。

正常登録後は、既存の自動クリア処理により読書状態も「未設定」へ戻す。

```python
self._rating_var.set("未評価")
```

次の場合も同様に初期化する。

* 入力クリアボタン押下時
* 新規登録成功後
* 更新成功後
* 削除後のフォーム初期化
* 更新対象が存在しない場合のフォーム初期化

お気に入りはOFF、読書状態は未設定、評価は未評価という、それぞれ独立した初期状態へ戻す。

## 193. 読書状態・読了年月・お気に入りとの関係

評価は、読書状態・読了年月・お気に入りとは独立して扱う。

例えば、次の状態も正常なデータとして扱う。

```text
読了年月　：未入力
読書状態　：未読
評価　　　：★★★★★
お気に入り：OFF
```

また、次の状態も正常とする。

```text
読了年月　：2026-08
読書状態　：読了
評価　　　：未評価
お気に入り：ON
```

評価を変更しても、読書状態・読了年月・お気に入りを自動変更しない。

同様に、読書状態・読了年月・お気に入りを変更しても、評価を自動変更しない。

評価5を設定しても自動的にお気に入りONとはしない。

お気に入りONでも評価5を自動設定しない。
