# 複合条件検索機能 設計書

## 1. 目的

本設計書は、book_manager Version 1.2で追加する複合条件検索機能の設計を定義する。

現在のbook_managerでは、検索種類を1つ選択し、1つの検索文字列を指定して検索する単一条件検索を採用している。

Version 1.2では、書籍名・著者名・出版社・ISBN・雑誌コードを複数同時に指定できるようにし、登録書籍が増えた場合でも目的の書籍を絞り込みやすくする。

高機能な検索式を導入するのではなく、個人利用で分かりやすく扱えるシンプルなAND検索を基本とする。

---

## 2. 基本方針

複合条件検索は、次の方針で実装する。

- 書籍名・著者名・出版社・ISBN・雑誌コードの5項目を検索対象とする。
- 入力された項目だけを検索条件として使用する。
- 複数の検索条件はAND条件として扱う。
- 空欄は検索条件として使用しない。
- 全項目が空欄の場合は全件表示する。
- 書籍名・著者名・出版社は部分一致検索とする。
- ISBN・雑誌コードは既存検索仕様を維持する。
- ISBNは既存の正規化・検証処理を利用する。
- 雑誌コードは既存の正規化・検証処理を利用する。
- 既存の並べ替え機能をそのまま利用する。
- ヘッダークリックソートとの連携を維持する。
- 検索処理のために既存の単一条件検索メソッドを削除しない。
- OR検索・NOT検索などの複雑な検索はVersion 1.2では実装しない。

---

## 3. 検索対象項目

Version 1.2では、次の5項目を検索対象とする。

| 項目 | 一致方法 |
| --- | --- |
| 書籍名 | 部分一致 |
| 著者名 | 部分一致 |
| 出版社 | 部分一致 |
| ISBN | 完全一致 |
| 雑誌コード | 完全一致 |

書籍名・著者名・出版社は、現在の単一条件検索と同じ部分一致検索とする。

ISBN・雑誌コードも、現在の単一条件検索と同じ完全一致検索とする。

---

## 4. 複数条件の扱い

複数の検索条件が入力された場合は、すべての条件を満たす書籍だけを検索結果として返す。

例：

```text
著者名：東野圭吾
出版社：講談社
```

の場合、

```text
著者名に「東野圭吾」を含む
AND
出版社に「講談社」を含む
```

書籍を検索する。

Version 1.2では、条件同士の結合方法はANDのみとする。

---

## 5. 空欄の扱い

検索項目が空欄の場合、その項目は検索条件として使用しない。

例：

```text
書籍名：
著者名：村上春樹
出版社：
ISBN：
雑誌コード：
```

の場合、著者名だけを条件として検索する。

空白文字だけが入力されている場合も、前後空白を除去した結果が空文字になるため、検索条件なしとして扱う。

---

## 6. 全項目が空欄の場合

5つの検索項目がすべて空欄の場合は、エラーや警告を表示せず、登録済み書籍を全件表示する。

概念上は次の動作とする。

```text
すべて空欄
    ↓
検索
    ↓
全件表示
```

利用者に検索条件入力を強制しない。

---

## 7. 入力値の正規化

### 7.1 書籍名

前後の空白を除去する。

空文字になった場合は検索条件として使用しない。

### 7.2 著者名

前後の空白を除去する。

空文字になった場合は検索条件として使用しない。

### 7.3 出版社

前後の空白を除去する。

空文字になった場合は検索条件として使用しない。

### 7.4 ISBN

既存の`BookService`が持つISBN正規化方針を維持する。

正規化時には、

- 前後空白を除去する。
- ハイフンを除去する。
- 空白を除去する。

正規化後に値が存在する場合は、既存のISBN Validatorで検証する。

不正なISBNが入力された場合は、既存検索と同様に検索エラーとして利用者へ通知する。

### 7.5 雑誌コード

前後空白を除去する。

正規化後に値が存在する場合は、既存の雑誌コードValidatorで検証する。

不正な雑誌コードが入力された場合は、既存検索と同様に検索エラーとして利用者へ通知する。

## 9. 検索用GUI状態

`BookManagerApplication`には、登録・編集フォームとは独立した検索専用の`StringVar`を持たせる。

概念上は次の変数を使用する。

```python
self._search_title_var
self._search_author_var
self._search_publisher_var
self._search_isbn_var
self._search_magazine_code_var
```

登録フォームで使用している、

```python
self._title_var
self._author_var
self._publisher_var
self._isbn_var
self._magazine_code_var
```

とは共有しない。

検索条件と登録・編集内容を独立した状態として管理する。

## 10. Enterキー検索

5つの検索入力欄のいずれでも、Enterキーを押した場合に検索を実行できるようにする。

すべての検索Entryから既存の検索イベントハンドラへ接続する。

---

## 11. 検索ボタン

「検索」ボタンを押した場合は、現在入力されている5つの検索条件を取得し、複合条件検索を実行する。

検索後は、既存の並べ替え条件を適用して一覧へ表示する。

概念上の処理は次のとおりとする。

```text
5つの検索条件を取得
        ↓
BookService.search_books()
        ↓
検索結果
        ↓
既存のソート条件を取得
        ↓
BookService.sort_books()
        ↓
一覧表示
```

---

## 12. 検索条件クリア

Version 1.2では、「全件表示」ボタンと「検索条件クリア」ボタンの役割を統合する。

「検索条件クリア」を実行した場合は、

1. 5つの検索条件をすべて空欄にする。
2. 登録済み書籍を全件表示する。
3. 現在の並べ替え条件を維持する。
4. 最初の検索入力欄へフォーカスを移す。

という動作とする。

現在の「全件表示」ボタンはVersion 1.2では廃止する。

---

## 13. 検索中判定

複合条件検索では、単一の検索キーワードだけでは検索中かどうかを判定できない。

そのため、`BookManagerApplication`に検索条件の有無を判定する補助処理を追加する。

概念上は次の処理とする。

```python
def _has_search_conditions(self) -> bool:
    return any(
        value.strip()
        for value in (
            self._search_title_var.get(),
            self._search_author_var.get(),
            self._search_publisher_var.get(),
            self._search_isbn_var.get(),
            self._search_magazine_code_var.get(),
        )
    )
```

検索条件が1つ以上存在する場合は、件数表示の先頭を、

```text
検索結果
```

とする。

検索条件がすべて空欄の場合は、

```text
全
```

とする。

## 14. BookManagerApplication

### 14.1 削除する状態

既存の次の状態は、複合条件検索への移行に伴い不要となる。

```python
SEARCH_TYPES
_search_type_var
_search_keyword_var
```

### 14.2 削除するGUI部品

次のGUI部品は不要となる。

```python
_search_type_combobox
_search_entry
_show_all_button
```

### 14.3 追加するGUI部品

次の検索用Entryを追加する。

- 書籍名
- 著者名
- 出版社
- ISBN
- 雑誌コード

### 14.4 `_get_filtered_books()`

現在の検索種類ごとの分岐は廃止する。

複合条件検索では、`BookService.search_books()`へ5つの検索条件を渡す。

概念上は次の構成とする。

```python
def _get_filtered_books(self) -> list[BookItem]:
    return self._service.search_books(
        title=self._search_title_var.get(),
        author=self._search_author_var.get(),
        publisher=self._search_publisher_var.get(),
        isbn=self._search_isbn_var.get(),
        magazine_code=self._search_magazine_code_var.get(),
    )
```

### 14.5 `_on_search()`

現在の、

```text
検索
↓
ソート
↓
一覧表示
```

という処理構造を維持する。

検索成功後は、既存どおり登録・編集フォームの選択状態を解除する。

### 14.6 `_on_sort_changed()`

現在の検索条件を維持したまま、再度`_get_filtered_books()`を実行し、その結果を既存の`sort_books()`で並べ替える。

検索条件の有無は`_has_search_conditions()`で判定する。

### 14.7 `_on_reload()`

現在入力されている複合検索条件を維持したまま検索し直し、その結果を現在のソート条件で再表示する。

## 15. BookService

複合条件検索の公開窓口として、新しいメソッドを追加する。

第一候補は次の形とする。

```python
def search_books(
    self,
    *,
    title: str | None = None,
    author: str | None = None,
    publisher: str | None = None,
    isbn: str | None = None,
    magazine_code: str | None = None,
) -> list[BookItem]:
    ...
```

### 15.1 責務

`BookService.search_books()`は次を担当する。

1. 書籍名の前後空白を除去する。
2. 著者名の前後空白を除去する。
3. 出版社の前後空白を除去する。
4. ISBNを既存方針で正規化する。
5. 雑誌コードの前後空白を除去する。
6. ISBNが存在する場合は検証する。
7. 雑誌コードが存在する場合は検証する。
8. 全条件が空の場合は全件取得する。
9. 1つ以上条件がある場合はRepositoryの複合条件検索を呼び出す。

入力値の正規化・検証はRepositoryへ持ち込まない。

---

## 16. BookRepository

複合条件検索用のメソッドを追加する。

第一候補は次の形とする。

```python
def search_by_conditions(
    self,
    *,
    title: str | None = None,
    author: str | None = None,
    publisher: str | None = None,
    isbn: str | None = None,
    magazine_code: str | None = None,
) -> list[BookItem]:
    ...
```

### 16.1 責務

`BookRepository.search_by_conditions()`は、Serviceから渡された正規化済み検索条件をSQLへ変換する。

入力値検証は行わない。

---

## 17. SQL生成方針

検索条件が存在する項目だけWHERE句へ追加する。

例：

```text
title = "海辺"
author = "村上"
publisher = None
isbn = None
magazine_code = None
```

の場合、概念上のSQLは次のようになる。

```sql
SELECT
    ...
FROM book_items
WHERE title LIKE ?
  AND author LIKE ?
ORDER BY id DESC
```

パラメータは、

```text
%海辺%
%村上%
```

となる。

ISBNが指定された場合は、

```sql
isbn = ?
```

を使用する。

雑誌コードが指定された場合は、

```sql
magazine_code = ?
```

を使用する。

SQL文字列へ検索値を直接埋め込まず、必ずSQLiteのパラメータを利用する。

---

## 18. SQL条件の組み立て

概念上は、条件リストとパラメータリストを使用する。

```python
conditions = []
parameters = []
```

入力値が存在する項目についてだけ条件を追加する。

例：

```python
if title is not None:
    conditions.append("title LIKE ?")
    parameters.append(f"%{title}%")
```

最終的に、

```text
WHERE 条件1 AND 条件2 AND 条件3
```

となるように組み立てる。

---

## 19. 並び順

Repositoryによる複合条件検索結果の基本順序は、既存検索と同じID降順とする。

```sql
ORDER BY id DESC
```

GUIでは検索後に既存の`BookService.sort_books()`を適用するため、最終表示順は現在選択されている並べ替え条件に従う。

---

## 20. 既存単一条件検索との関係

現在存在する、

```python
search_books_by_title()
search_books_by_author()
search_books_by_publisher()
find_books_by_isbn()
find_books_by_magazine_code()
```

およびRepositoryの対応メソッドは、Version 1.2では削除しない。

複合条件検索の実装を理由に既存APIを整理・統合するリファクタリングは行わない。

既存テストおよび他の処理への影響を最小限にする。

---

## 21. ソート機能との連携

複合条件検索では新しいソートロジックを実装しない。

現在の、

```python
BookService.sort_books()
```

をそのまま利用する。

次の既存操作との整合性を維持する。

- 並べ替えコンボボックス
- 昇順・降順ラジオボタン
- Treeviewヘッダークリック

複合検索条件を設定した状態でこれらの操作を行っても、検索条件を解除しない。

---

## 22. エラー処理

### 22.1 ISBN

不正なISBNが指定された場合は、既存Validatorの`ValueError`をGUI側で捕捉し、検索エラーとして利用者へ通知する。

入力内容は保持する。

### 22.2 雑誌コード

不正な雑誌コードが指定された場合も同様に、検索エラーとして通知する。

入力内容は保持する。

### 22.3 データベースエラー

RepositoryまたはServiceで予期しない例外が発生した場合は、既存の検索エラー処理を利用する。

利用者へ、

```text
書籍情報を検索できませんでした。
```

と通知する。

---

## 23. Repositoryテスト

`BookRepository.search_by_conditions()`の自動テストを追加する。

主な確認項目は次のとおりとする。

- 書籍名だけで部分一致検索できる。
- 著者名だけで部分一致検索できる。
- 出版社だけで部分一致検索できる。
- ISBNだけで完全一致検索できる。
- 雑誌コードだけで完全一致検索できる。
- 書籍名＋著者名でAND検索できる。
- 著者名＋出版社でAND検索できる。
- ISBN＋書籍名でAND検索できる。
- 複数条件すべてを満たす書籍だけを取得できる。
- 条件に一致しない場合は空リストを返す。
- SQLパラメータに特殊文字が含まれていても安全に検索できる。
- ID降順で結果を返す。

## 24. BookServiceテスト

`BookService.search_books()`の自動テストを追加する。

主な確認項目は次のとおりとする。

- 各検索項目の前後空白を除去する。
- 空文字を`None`相当として扱う。
- 全条件空欄の場合は全件取得する。
- 1条件をRepositoryへ正しく渡す。
- 複数条件をRepositoryへ正しく渡す。
- ISBNのハイフンを除去する。
- ISBN内の空白を除去する。
- ISBNを検証する。
- 雑誌コードを検証する。
- 不正なISBNでは`ValueError`となる。
- 不正な雑誌コードでは`ValueError`となる。

## 25. GUIテスト・実機確認

GUIでは主に実機確認を行い、必要に応じて単体テストを追加する。

### 25.1 単一条件

- 書籍名だけで検索できる。
- 著者名だけで検索できる。
- 出版社だけで検索できる。
- ISBNだけで検索できる。
- 雑誌コードだけで検索できる。

### 25.2 複数条件

- 2条件のAND検索ができる。
- 3条件以上のAND検索ができる。
- 条件に一致しない場合は0件になる。

### 25.3 空欄

- 一部空欄でも検索できる。
- 全項目空欄で検索すると全件表示になる。
- 空白だけの項目を条件として扱わない。

### 25.4 検索条件クリア

- 5項目がすべて空欄になる。
- 全件表示へ戻る。
- ソート条件は維持される。
- 最初の検索欄へフォーカスが移る。

### 25.5 ソート

- 検索結果を維持したままコンボボックスでソートできる。
- 検索結果を維持したまま昇順・降順を切り替えられる。
- 検索結果を維持したままヘッダークリックソートできる。

### 25.6 再読み込み

- 検索条件を維持したまま再読み込みできる。
- 現在のソート条件を維持できる。

### 25.7 エラー

- 不正ISBNで適切な検索エラーが表示される。
- 不正雑誌コードで適切な検索エラーが表示される。
- エラー発生後も検索入力内容が保持される。

## 26. Version 1.2で実装しない範囲

次の機能はVersion 1.2の複合条件検索には含めない。

- OR検索
- NOT検索
- AND / ORの利用者選択
- 複雑な検索式
- 括弧付き検索条件
- 条件追加・削除方式のGUI
- 別ウィンドウによる詳細検索
- 検索条件の保存
- 検索履歴
- 最近使った検索条件
- 正規表現検索
- 内容紹介検索
- 備考検索
- 出版形態検索
- 読了年月検索

これらは実利用結果を踏まえて将来Versionで検討する。
