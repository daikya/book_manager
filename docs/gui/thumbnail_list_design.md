# 表紙サムネイル付き一覧機能 設計書

## 1. 目的

本設計書は、book_manager Version 1.2で追加する表紙サムネイル付き一覧機能の設計を定義する。

現在のbook_managerでは、書籍一覧を`ttk.Treeview`で表示し、書籍名・著者名・出版社・ISBN・雑誌コード・読了年月などを文字情報として確認できる。

Version 1.2では、既存の表紙画像キャッシュを活用し、書籍一覧の各行に小さな表紙サムネイルを表示する。

これにより、書籍名だけでなく表紙画像からも書籍を識別できるようにし、日常的な一覧操作をより分かりやすくする。

---

## 2. 基本方針

表紙サムネイル付き一覧は、次の方針で実装する。

- 既存の`ttk.Treeview`による一覧表示を維持する。
- `Treeview`の`#0`列を表紙サムネイル専用列として利用する。
- `show="headings"`から`show="tree headings"`へ変更する。
- 既存の文字情報列は維持する。
- 表紙サムネイル列はソート対象外とする。
- 既存の表紙画像キャッシュ`cache/covers`を再利用する。
- 新たな表紙画像取得処理は追加しない。
- サムネイルは一覧上の視覚的な目印として小さく表示する。
- 元画像の縦横比を維持する。
- 表紙画像が存在しない場合も一覧表示を継続する。
- 表紙画像ファイルが破損している場合も一覧表示を継続する。
- 検索・ソート・選択・編集など既存の一覧操作を維持する。
- 大量の書籍を表示する場合の性能を考慮する。
- RepositoryおよびBookServiceは原則変更せず、GUI側を中心に実装する。

---

## 3. Treeview構成

### 3.1 現在の構成

現在のTreeviewは、概念上次の構成となっている。

```python
ttk.Treeview(
    ...,
    columns=self.TREE_COLUMNS,
    show="headings",
)
```

`show="headings"`を使用しているため、Treeview固有の`#0`列は表示されていない。

### 3.2 Version 1.2での構成

Version 1.2では、

```python
show="tree headings"
```

へ変更する。

これにより、`#0`列を表示し、表紙サムネイル専用列として利用する。

概念上の一覧は次のようになる。

```text
┌──────┬────┬──────────────┬────────────┬──────────┬─────
│ 表紙 │ ID │ 書籍名       │ 著者名     │ 出版社   │ ...
├──────┼────┼──────────────┼────────────┼──────────┼─────
│      │ 12 │ 海辺のカフカ │ 村上春樹   │ 新潮社   │
│      │ 11 │ ...          │ ...        │ ...      │
└──────┴────┴──────────────┴────────────┴──────────┴─────
```

---

## 4. 表紙列

Treeviewの`#0`列を表紙専用列として使用する。

見出しは、

```text
表紙
```

とする。

表紙列にはソート処理を割り当てない。

既存の、

- 登録順
- 書籍名
- 著者名
- 出版社
- 読了年月

などのソート機能には影響を与えない。

---

## 5. サムネイルサイズ

サムネイル画像は、一覧性を維持するため小さく表示する。

第一候補の最大サイズは次のとおりとする。

```text
幅：40px
高さ：55px
```

元画像の縦横比は維持する。

Pillowの、

```python
Image.thumbnail()
```

を利用して縮小する。

拡大は行わない。

---

## 6. 行の高さ

表紙サムネイルを表示するため、Treeviewの行高を調整する。

第一候補は、

```text
60px前後
```

とする。

実際の値はGUI実機確認時に、

- サムネイルが切れない。
- 文字が読みづらくならない。
- 一画面に表示できる冊数が少なくなりすぎない。

ことを確認して調整する。

---

## 7. 表紙画像の取得元

新たに画像をダウンロードしない。

既存の`BookItem.cover_image_path`に保存されている表紙画像キャッシュパスを利用する。

対象ファイルは既存の、

```text
cache/covers
```

配下の画像とする。

---

## 8. 表紙画像が存在しない場合

次の場合は、サムネイルを表示しない。

- `cover_image_path`が`None`
- `cover_image_path`が空欄
- 指定されたファイルが存在しない

一覧自体は正常に表示する。

表紙なしの書籍も、既存の文字情報列によって通常どおり操作できるようにする。

Version 1.2では、一覧用の代替画像ファイルは新規作成しない。

---

## 9. 表紙画像が破損している場合

画像ファイルが存在していても、Pillowで読み込めない場合がある。

この場合、

- 例外内容は必要に応じてターミナルへ出力する。
- アプリケーションは停止しない。
- 当該書籍のサムネイルは表示しない。
- 他の書籍は通常どおり一覧表示する。

一覧表示全体を失敗させないことを優先する。

---

## 10. PhotoImageの保持

Tkinterの`PhotoImage`は、Python側で参照が保持されていない場合に表示されなくなる可能性がある。

そのため、一覧表示中のサムネイルは`BookManagerApplication`内部で保持する。

第一候補として、次のような辞書を使用する。

```python
self._thumbnail_photos: dict[
    int,
    ImageTk.PhotoImage,
]
```

キーは書籍IDとする。

値は一覧用の`ImageTk.PhotoImage`とする。

---

## 11. サムネイルキャッシュの扱い

### 11.1 一覧再表示時

現在の`_display_books()`は、Treeviewの既存行をすべて削除してから一覧を再構築している。

Version 1.2でも基本構造を維持する。

一覧再構築時には、

```python
self._thumbnail_photos.clear()
```

によって一覧用の`PhotoImage`参照をいったん解放する。

その後、今回表示する書籍について必要なサムネイルだけを再生成する。

### 11.2 ディスク上の画像キャッシュ

`cache/covers`に保存されている元画像ファイルは削除しない。

一覧再表示時に破棄するのは、GUI表示用の`PhotoImage`参照のみとする。

---

## 12. サムネイル生成処理

一覧表示専用の補助メソッドを追加する。

第一候補は次のような責務とする。

```python
def _create_thumbnail_photo(
    self,
    cover_image_path: str | None,
) -> ImageTk.PhotoImage | None:
    ...
```

責務は次のとおりとする。

1. パスが存在するか確認する。
2. ファイルが存在するか確認する。
3. Pillowで画像を開く。
4. コピーを作成する。
5. 最大40×55px程度へ縮小する。
6. `ImageTk.PhotoImage`へ変換する。
7. 生成できない場合は`None`を返す。

---

## 13. Treeviewへのサムネイル設定

書籍一覧へ行を追加する際、`#0`列の画像としてサムネイルを指定する。

概念上は次のようにする。

```python
self._book_tree.insert(
    "",
    "end",
    iid=str(book.id),
    image=thumbnail_photo,
    values=(
        ...
    ),
)
```

`thumbnail_photo`が`None`の場合は画像を指定しない。

---

## 14. 書籍IDとの関連付け

サムネイルを保持する場合は、書籍IDをキーとする。

概念上は次のようにする。

```python
if thumbnail_photo is not None:
    self._thumbnail_photos[book.id] = (
        thumbnail_photo
    )
```

Treeviewの`iid`も現在どおり、

```python
str(book.id)
```

を使用する。

これにより、既存の一覧選択・編集処理との整合性を維持する。

---

## 15. 既存の表紙表示との関係

現在、書籍情報入力フォーム右側には選択中書籍の表紙画像を表示する機能が存在する。

Version 1.2のサムネイル一覧は、この既存表紙表示を置き換えない。

役割を次のように分ける。

### 一覧サムネイル

```text
目的：
一覧から書籍を視覚的に識別する。

サイズ：
小さい。

表示対象：
現在一覧に表示されている複数書籍。
```

### 入力フォーム側表紙画像

```text
目的：
選択中書籍の表紙を確認する。

サイズ：
大きい。

表示対象：
現在選択されている1冊。
```

両機能を併存させる。

---

## 16. 検索との連携

複合条件検索によって一覧が絞り込まれた場合、検索結果に含まれる書籍だけについてサムネイルを表示する。

新しい検索処理は追加しない。

既存の、

```text
複合条件検索
↓
BookItem一覧
↓
_display_books()
```

という処理をそのまま利用する。

---

## 17. ソートとの連携

ソート処理そのものは変更しない。

既存の、

```python
BookService.sort_books()
```

を利用する。

ソート後に`_display_books()`で一覧を再構築する際、並べ替え後の各書籍についてサムネイルを再表示する。

表紙列自体はソート対象外とする。

---

## 18. ヘッダークリックソートとの連携

Treeviewの既存列見出しクリックによるソート機能を維持する。

`#0`列の「表紙」見出しには、

```python
command
```

を設定しない。

そのため「表紙」列をクリックしてもソート処理は実行しない。

---

## 19. 一覧選択との連携

サムネイル付き一覧でも、行選択は現在と同じくTreeviewの選択イベントを利用する。

```text
<<TreeviewSelect>>
```

によって選択された書籍IDを取得し、入力フォームへ表示する。

サムネイル列追加によって、

- 一覧選択
- 編集対象ID
- 入力フォーム表示
- 表紙詳細表示

の既存動作を変更しない。

---

## 20. Repository・BookService

Version 1.2の表紙サムネイル付き一覧では、原則としてRepositoryおよびBookServiceへ新しい処理を追加しない。

既存の`BookItem.cover_image_path`を利用する。

一覧表示のためだけに新しいデータ取得APIは追加しない。

実装時に必要性が判明した場合は、設計書を更新したうえで変更する。

---

## 21. 性能方針

一覧表示ごとに画像ファイルの読み込みとサムネイル生成が発生する。

Version 1.2では、まず既存のローカル画像キャッシュを直接利用するシンプルな方式を採用する。

ただし、次の点を実機確認する。

- 全件表示時の待ち時間
- 複合条件検索後の表示速度
- ソート時の表示速度
- 再読み込み時の表示速度
- 多数の表紙画像がある場合のメモリ使用感

日常利用で明確な遅延が確認された場合は、将来Versionで一覧用サムネイルキャッシュを検討する。

Version 1.2では、必要性が確認される前に専用サムネイルファイルを生成・保存する仕組みは追加しない。

---

## 22. エラー処理

### 22.1 表紙パスなし

エラーとしない。

サムネイルなしで一覧表示する。

### 22.2 表紙ファイルなし

エラーとしない。

サムネイルなしで一覧表示する。

### 22.3 表紙画像読み込み失敗

例外をアプリケーション全体へ伝播させない。

必要に応じて、

```python
traceback.print_exc()
```

で内容をターミナルへ出力する。

当該書籍のみサムネイルなしで表示する。

### 22.4 一覧表示自体の失敗

表紙以外の既存一覧処理で予期しない例外が発生した場合は、既存のエラー処理方針を維持する。

---

## 23. GUIスタイル

Treeviewの行高を変更する場合は、`ttk.Style`を利用する。

既存GUI全体のテーマを変更しない。

表紙サムネイル付き一覧のために必要な最小限のスタイル設定だけを追加する。

他のTreeviewが将来追加される可能性も考慮し、必要であれば一覧専用Style名を使用する。

例：

```python
"Book.Treeview"
```

実際のStyle名は実装時に決定する。

---

## 24. 自動テスト

表紙サムネイル付き一覧では、画像表示そのものをTkinter実画面で自動テストすることは避け、ロジック部分を中心に確認する。

主な確認項目は次のとおりとする。

- 表紙パスが`None`の場合に`None`を返す。
- 表紙ファイルが存在しない場合に`None`を返す。
- 正常な画像からサムネイルを生成できる。
- サムネイルサイズが最大サイズを超えない。
- 元画像の縦横比を大きく崩さない。
- 破損画像の場合に一覧処理を停止しない。
- 一覧再表示時にサムネイル保持用辞書をクリアする。
- サムネイルが生成された書籍を辞書へ保持する。
- 表紙なし書籍もTreeviewへ追加できる。

---

## 25. 実機確認

### 25.1 表紙あり

- 表紙画像がある書籍にサムネイルが表示される。
- サムネイルが行内に収まる。
- 元画像の縦横比が維持される。
- 文字列表示が崩れない。

### 25.2 表紙なし

- 表紙画像がない書籍も一覧に表示される。
- 行選択できる。
- 編集できる。

### 25.3 破損・欠損画像

- キャッシュファイルがない場合も一覧表示できる。
- 破損画像が存在していても一覧表示を継続できる。
- 他の書籍のサムネイル表示に影響しない。

### 25.4 検索

- 複合条件検索結果にもサムネイルが表示される。
- 検索条件クリア後の全件表示にもサムネイルが表示される。

### 25.5 ソート

- コンボボックスによるソート後もサムネイルが正しい書籍に表示される。
- 昇順・降順切り替え後も正常表示される。
- ヘッダークリックソート後も正常表示される。
- 表紙列クリックではソートされない。

### 25.6 一覧選択

- サムネイル列を含む行を選択できる。
- 選択した書籍が入力フォームへ正しく表示される。
- 既存の大きな表紙表示も正常に更新される。

### 25.7 性能

- 全件表示で実用上問題のない速度で表示される。
- 検索・ソート・再読み込み時に著しい遅延がない。
- 通常操作中にGUIが不安定にならない。

---

## 26. Version 1.2で実装しない範囲

次の機能はVersion 1.2の表紙サムネイル付き一覧には含めない。

- カード形式の書籍一覧
- サムネイルサイズの利用者設定
- サムネイル表示ON/OFF設定
- 一覧用サムネイル画像ファイルの永続キャッシュ
- 表紙画像の一覧上での拡大表示
- マウスオーバーによる表紙拡大
- 表紙列によるソート
- 表紙画像の一括再取得
- 表紙なし用の新規代替画像ファイル
- 遅延読み込み
- 非同期画像読み込み
- ページング
- 仮想スクロール

これらは、Version 1.2の実利用結果を踏まえて将来Versionで検討する。
