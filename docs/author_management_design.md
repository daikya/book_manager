# 著者管理の設計（Version 2.8候補）

2026年10月22日。Version 2.7.0公開後の次工程として、著者をIDで管理する。

## 基本方針

- 同姓同名の著者を別IDで登録できる。表示名・別名・検索用キーに全著者共通の一意制約を付けない。
- 表記の正規化は検索候補の抽出にだけ使う。文字列一致や候補順位だけで関連付け・統合しない。
- 既存のbook_items.authorは入力・取得元の表記として保持し、DB移行で分割・置換・著者作成しない。
- 書籍と著者は複数対複数。別名は1人の著者に複数登録できる。
- 不明な人物は未関連のままにできる。別名・分野・所属・生年等は任意で、外部照会を要求しない。

## 人物と表記の例

| ID | 表示名 | 別名 | 識別メモ |
|---|---|---|---|
| 101 | 小路幸也 | 利用者が必要に応じて登録 | 小説家 |
| 102 | 山田太郎 | 山田 太郎 | 経済学・○○大学 |
| 103 | 山田太郎 | 山田 太郎 | 小説家 |

空白の違いは別名を登録しなくても検索で吸収する。別名には旧字体、筆名、読み、取得元の表記などを利用者の判断で登録できる。筆名の一致も同一人物の自動判定には使わない。

## 入力と検索

- 表示名・別名は1項目200文字以内、空欄・制御文字を拒否する。識別メモは任意で2000文字以内、改行可。
- 保存する表記と検索キーを分ける。検索キーはNFKC、大文字小文字の統一、Unicode空白の除去で生成する。
- カンマ・中点・ハイフン・数字・生年・「著」等を除去しない。姓名の順序を入れ替えない。旧字体や似た漢字を自動変換しない。
- 「小路,幸也,1961-」と「小路幸也」は正規化だけでは完全一致しない。必要なら別名として明示登録する。
- 表示名・別名の文字列完全一致、正規化後の一致、部分一致、識別メモの一致の順。同順位は元の順序を維持する。
- 1人の著者に複数表記が一致しても候補は1件。同名の別IDは全件表示する。
- 空検索では候補検索関数は空リストを返す。著者管理画面の全件一覧は別操作で提供する。
- 一致の目安は人物確認の材料であり、同一人物を保証しない。自動選択しない。

## DB構成案

| テーブル | 主な項目・制約 |
|---|---|
| authors | id、name、name_key、disambiguation_note、created_at、updated_at。name_keyは検索用の非一意インデックス |
| author_aliases | id、author_id、name、name_key。FKはauthors、同じ著者内の同一表記だけ重複を防ぐ。別人間の同じ別名を許可 |
| book_item_authors | book_item_id、author_id、position。書籍・著者の組み合わせを主キーとし、表示順を保持 |

著者削除は関連書籍がある場合に拒否する。書籍削除は関連のみ連動削除し、著者は残す。関連付けの解除も著者や書籍を削除しない。

Schema 8→9を実装した。既存テーブルの内容を保持し、3テーブルを追加する。著者・別名・関連は空のまま開始する。移行前バックアップ、整合性・外部キー検査、失敗時のロールバックを既存方式で行う。

## 画面・操作

1. タグ管理に近い著者管理画面を追加。一覧に表示名・識別メモ・関連書籍数を表示する。著者IDでも区別できるようにする。
2. 新規登録で似た名前を候補表示しても、「別人として登録」を選べる。名前だけで登録を拒否しない。
3. 表示名・別名・識別メモの編集、未使用著者の削除、関連書籍の表示を提供する。
4. 書籍フォームでは既存の著者名欄を保持し、タグ選択に近い「管理著者」の選択操作を追加する。
5. 書籍の登録・更新時に著者の関連付けを同一トランザクションで保存する。未登録フォームで選択しても、登録までは書籍・関連を作らない。
6. 既存著者への関連付け、別人の新規登録、未整理のまま、を利用者が選べる。自動分割や自動関連付けはしない。
7. 著者名編集や外部書誌情報の反映で、確定済みの管理著者を勝手に変更しない。原表記と関連付けは利用者がそれぞれ確認する。
8. 著者管理・選択・編集画面も初回は親中央、以降は前回位置・サイズを復元する。

管理著者による書籍一覧の絞り込みは著者IDで行う。現在の著者名文字列を対象にした検索も残す。著者の表示名を改名しても、既存書籍の原表記は変更しない。

## データ保護・入出力

- SQLiteバックアップ・復元は新テーブルを含めて保持する。
- 完全データZIPに著者・別名・関連CSVを追加し、形式Version 3を実装した。旧形式1・2は著者情報なしで読み込めるようにする。
- 完全データZIPの非空DBへの復元拒否条件は、著者・別名・関連も対象にする。
- 単一CSV・Excelは従来どおり原表記を保持して取り込む。取込時の人物の自動生成・関連付けはしない。
- 単一CSVでは管理著者・別名・関連を完全に保存できないことを案内し、完全移行には完全データZIPを使う。
- 完全データZIPの往復・DB移行・バックアップ復元を検証してから、GUIの登録・更新を接続する。
- 2.7.0へ戻す場合、Schema 9のDBをそのまま使わず、移行前バックアップを使用する。

## 実装順序と確認範囲

1. **完了（c80d351）**: Author／AuthorCandidateモデル、表記違いの候補検索、同姓同名・別名・識別メモのテスト。
2. **完了（36ff253）**: Schema 9移行、AuthorRepository、AuthorService、完全データZIP形式3の往復・復元。著者・別名・関連件数を完全データ入出力の確認画面にも表示する。GUIの著者登録・編集操作はまだ接続しない。
3. **今回実装**: 著者管理・編集・選択をGUIへ接続。書籍の登録・更新と管理著者の関連を同一トランザクションで保存。著者IDによるメイン一覧の絞り込みは次工程とする。Windows実機確認は未完了。
4. 既存書籍の整理を支援する。統合前の対象書籍確認、統合元別名の引継ぎ、同名別人の維持と、関連付けの修正を検証する。

人物の自動統合、外部の人物DB連携、読みの自動生成、巻・出版社からの人物推定は初期実装に含めない。

- Linux環境でWindows専用モジュールの読み込みだけを補助し、全2199件＋13 subtests成功。第1段階2145件に対して54件を追加。その後、Windowsでも追加54件・全2199件＋13 subtests成功を利用者が確認。
- Schema 8→9で既存書籍・原著者名・タグ・履歴・ID連番を保持し、著者3テーブルを空で作成。バックアップ失敗・DDL失敗時は元DBを維持。
- 同名別人・共有別名・未関連の著者、識別メモ、複数著者の表示順を保存してZIP往復できる。
- 著者だけ登録済みのDBにも完全データの復元を許可しない。復元途中の失敗は7テーブル全体をロールバックし、事前バックアップを保持。

- 表示名・別名の索引キー生成はvalidators/author_name_normalizer.pyで共用し、author_matching.pyの公開関数は維持。
- 現段階はソース版の基盤実装。公開済み2.7.0のEXEを置き換えず、pytestが用意する一時DBで確認する。GUI接続時に通常DBとは別のBOOK_MANAGER_HOMEで実機検証する。
- 開発ソースを起動するとDBはSchema 9へ移行する。通常利用DBでpython main.pyを起動する操作は、隔離した実機検証が済むまで行わない。

## 第3段階：著者管理GUIと書籍フォーム

- 起動時にAuthorRepository／AuthorServiceを同じDB保存先で生成し、アプリへ注入する。
- 著者名欄の横に「著者選択(n)」を置き、フォームの行数を増やさない。nは選択中の管理著者数。
- 選択画面は候補と選択済み著者を分け、ID・表示名・識別メモ・一致の根拠を表示する。別名でも検索でき、同名別人は別行に表示する。
- 追加・解除・上へ／下へで関連付けと順序を編集できる。「選択を反映」はフォームへの仮反映のみ。キャンセル時は以前の仮選択を保持する。
- 「著者管理」で登録・編集・削除・関連書籍表示を行う。別名は1行1つで入力し、カンマでは分割しない。
- 新規著者の同名・類似候補があれば確認し、別人として登録できる。識別メモだけの一致は同名確認の対象にしない。
- 著者マスターの保存・削除はその操作で確定する。書籍の関連を未保存でも新規著者は未関連の著者として残ることを画面で案内する。
- 書籍の「登録」「更新」で書籍・タグ・管理著者を同じSQLiteトランザクションで確定する。途中の失敗ではすべて戻す。通常の書誌情報取得や著者マスターの改名でbook_items.authorを置き換えない。
- サービスAPIでauthor_ids=Noneは既存の関連を維持し、空タプル／リストは解除を意味する。旧呼出元の動作は維持する。
- 著者関連の読込失敗時は関連を上書きせず保持する。選択後に著者が削除された場合、確定時に再確認して保存を拒否する。
- 管理・選択・編集・関連書籍の各画面で初回親中央表示と前回配置の保存・復元を共通処理で行う。
- LinuxでWindows専用モジュールの読み込みを補助した全体テストは2234件＋13 subtests成功（35件追加）。GUI表示・操作はWindowsで別途確認する。

Windows実機では、空の検証用保存先をBOOK_MANAGER_HOMEへ指定し、DBを先に初期化してからmain.pyを起動する。これにより旧データの自動移行先や通常利用DBと混同しない。今回のGUI確認では配布済み2.7.0のEXEを使用しない。

残作業は既存書籍の整理支援、統合・付替え操作と確認、配布版の検証。著者の自動統合は引き続き行わない。

## 第4段階：管理著者による一覧検索

- 検索領域の並べ替えと同じ行に「管理著者」の読取専用選択欄を配置する。表示名・ID・識別メモで同姓同名を区別する。
- 選択時に検索する。書籍名、原著者名、タグ等の既存条件とはAND検索する。「すべて」または「検索条件クリア」で解除する。
- 対象はbook_item_authorsで関連付けた書籍だけ。原著者名が同じ未関連の書籍は含めない。共著はどちらの著者でも検索でき、重複表示しない。
- 著者の改名・別名・スペースの違いで関連は変わらない。選択欄を開くと最新の名前を取得し、IDを維持する。削除済みの選択は無断で全件表示へ変更しない。
- 検索条件は既存条件と同様に再起動時は保持しない。一覧の列幅・並べ替え設定の保存仕様は維持する。
- 第3段階はWindowsで2234件＋13 subtestsと実機確認6項目が成功。第4段階のWindows実機確認はこれから行う。

## 第5段階：未関連の既存書籍を確認して整理

- 検索欄の「未関連書籍の整理」から、管理著者が1人も関連付いていない書籍を表示する。原著者名が空欄の書籍も対象にする。
- 選択した1冊の原著者名を既存の著者選択画面へ引き継ぎ、一致の目安・ID・識別メモを確認する。必要なら条件修正・全件表示・著者管理を利用する。名前の自動分割・自動登録・自動確定は行わない。
- 複数の管理著者と順序を選び、書籍ID・書籍名・原著者名・選択著者を最後に確認して関連だけ保存する。選択取消・確認取消では関連を保存しない。著者マスターの編集は従来どおりその操作で確定する。
- 保存時に同じトランザクションで未関連であることと書籍名・原著者名が表示時から変わっていないことを確認する。変更・削除・別の関連付けがあれば拒否する。途中で失敗しても一部の関連を残さない。
- 書籍情報・タグ・読書履歴は変更しない。成功した書籍は未関連一覧から消える。初回親中央・次回位置復元に対応する。
- メインフォームに入力がある場合は、クリアの確認後に整理画面を開く。第4段階はWindowsで2246件＋13 subtests、実機5項目が成功。第5段階のWindows実機確認はこれから行う。
