# 読書ステータス管理 設計書

## 1. 目的

本設計書は、book_manager Version 1.3で追加する「読書ステータス管理」機能の設計を定義する。

Version 1.2までのbook_managerでは、読了年月を記録できるが、「未読」「読書中」「読了」といった現在の読書状態を管理する機能は存在しない。

Version 1.3では、登録済み書籍について現在の読書状態を簡単に管理できるようにし、日常利用で書籍の状態を把握しやすくする。

---

## 2. 基本方針

次の方針で実装する。

- 読書ステータスを管理できるようにする。
- ステータスは「未設定」「未読」「読書中」「読了」の4状態とする。
- 「未設定」は既存データとの互換性を維持するために用意する。
- データベースには日本語表示名ではなく安定した内部値を保存する。
- 読書ステータスと読了年月は独立した項目として扱う。
- 読書ステータス変更時に読了年月を自動変更・自動削除しない。
- 同一書籍を複数回読む利用を考慮する。
- 複数回の読書履歴そのものはVersion 1.3では管理しない。
- 既存データを安全に維持したままDBスキーマを更新する。
- 既存の検索・ソート機能は今回変更しない。
- GUIの縦サイズは800pxを超えない。
- 新しい入力項目は既存行へ横並びで配置する。
- 必要な自動テストとGUI実機確認を行う。

---

## 3. 読書ステータスの定義

GUIでは次の4状態を表示する。

| GUI表示 | 内部値 | 意味 |
|---|---|---|
| 未設定 | `NULL` | 読書状態を設定していない |
| 未読 | `unread` | 現在は未読として管理している |
| 読書中 | `reading` | 現在読んでいる |
| 読了 | `completed` | 現在は読了状態として管理している |

---

## 4. 「未設定」の扱い

既存データには読書ステータス情報が存在しない。

そのため、Version 2からVersion 3へのマイグレーションでは、既存書籍へ状態を推測して設定しない。

既存書籍の`reading_status`は`NULL`のままとし、GUIでは「未設定」と表示する。

次のような推測は行わない。

```text
読了年月あり
↓
自動的に「読了」
```

既存データの意味をアプリケーション側で推測しないことで、誤った状態設定を防ぐ。

---

## 5. 読了年月との関係

現在の`completion_month`は読了年月を保持している。

Version 1.3では、

```text
reading_status
→ 現在の読書状態

completion_month
→ 過去に記録した読了年月
```

として、別の情報として扱う。

両項目間に自動的な整合性制約は設けない。

---

## 6. 再読への対応

同じ書籍を複数回読む場合を考慮する。

例えば次の状態を正常なデータとして扱う。

```text
読書ステータス：読書中
読了年月：2025-05
```

これは、

```text
2025年5月に一度読了し、
現在は再読中
```

と解釈できる。

したがって、読書ステータスを「読書中」または「未読」へ変更しても、既存の読了年月を自動削除しない。

---

## 7. 複数回の読書履歴

Version 1.3では、読書回数や複数回の読了履歴は管理しない。

将来的に必要になった場合は、`book_items`へ複数の読了年月カラムを追加するのではなく、別テーブルによる履歴管理を検討する。

将来案：

```text
reading_history

id
book_item_id
started_on
completed_on
```

これにより、同一書籍について複数回の読書履歴を保持できる。

読書履歴管理はVersion 1.4以降の候補とする。

## 8. データベース

### 8.1 スキーマVersion

現在のSQLiteスキーマVersionは次のとおりである。

```python
SCHEMA_VERSION = 2
```

読書ステータス追加後は、

```python
SCHEMA_VERSION = 3
```

とする。

---

## 9. `book_items`テーブル

`book_items`へ次のカラムを追加する。

```text
reading_status TEXT NULL
```

新規作成時のテーブル定義にも`reading_status`を含める。

概念上は次の位置とする。

```text
completion_month TEXT,
reading_status TEXT,
notes TEXT,
```

`reading_status`はNULLを許可する。

---

## 10. Version 2からVersion 3へのマイグレーション

Version 2の既存データベースに対して、次のマイグレーションを実行する。

```sql
ALTER TABLE book_items
ADD COLUMN reading_status TEXT
```

既存レコードでは自動的に`NULL`となる。

既存の書籍データは変更しない。

---

## 11. マイグレーション実行順序

`initialize_database()`では、既存のVersion 1からVersion 2へのマイグレーションを維持する。

Version 2からVersion 3へのマイグレーションを追加する。

概念上は次の流れとする。

```text
user_version = 0
↓
新規DB作成
↓
SCHEMA_VERSION = 3

user_version = 1
↓
Version 1 → 2
↓
Version 2 → 3
↓
SCHEMA_VERSION = 3

user_version = 2
↓
Version 2 → 3
↓
SCHEMA_VERSION = 3
```

Version 1のDBから直接Version 3へ更新する場合も、安全に順番どおりマイグレーションできるようにする。

## 12. Model

`BookItem`へ次の項目を追加する。

```python
reading_status: str | None = None
```

概念上は、

```python
completion_month: str | None = None
reading_status: str | None = None
notes: str | None = None
```

の順とする。

既存コードとの互換性を維持するため、デフォルト値は`None`とする。


### 13.2 新規登録

`INSERT INTO book_items`へ`reading_status`を追加する。

パラメータには、

```python
book_item.reading_status
```

を追加する。

---

### 13.3 更新

`UPDATE book_items`へ`reading_status`を追加する。

既存の更新処理と同様に、`BookItem.reading_status`をDBへ保存する。

---

### 13.4 `_row_to_book_item()`

SQLiteの行から`BookItem`を生成する際に`reading_status`を設定する。

---

## 14. Service

`BookService`では読書ステータスを登録・更新できるようにする。

### 14.1 `add_book()`

次の引数を追加する。

```python
reading_status: str | None = None
```

値を正規化・検証したうえで`BookItem`へ設定する。

---

### 14.2 `update_book()`

`BookItem.reading_status`を正規化・検証し、更新用`BookItem`へ設定する。

---

## 15. 読書ステータスの正規化

GUIから渡された読書ステータス内部値について、前後空白を除去する。

空文字列は`None`として扱う。

例：

```text
""            → None
" unread "    → "unread"
"reading"     → "reading"
"completed"   → "completed"
```

---

## 16. Validator

読書ステータス専用Validatorを追加する。

ファイル名候補：

```text
src/book_manager/validators/reading_status_validator.py
```

許可する値は次のみとする。

```text
None
unread
reading
completed
```

それ以外の値は`ValueError`とする。

例：

```text
finished
done
読了
unknown
```

などは内部値として受け付けない。

---

## 17. GUI表示値と内部値の変換

GUIでは日本語表示を使用する。

```text
未設定
未読
読書中
読了
```

内部では次のように変換する。

```text
未設定 → None
未読   → unread
読書中 → reading
読了   → completed
```

DB内部値をGUIへ表示する場合は逆変換する。

---

## 18. GUI入力部品

読書ステータスは自由入力ではなく、`ttk.Combobox`を使用する。

候補は次の4つとする。

```text
未設定
未読
読書中
読了
```

利用者が任意文字列を入力できないよう、`state="readonly"`を基本とする。

---

## 19. GUI配置

Version 1.3では画面の縦方向を増やさない。

現在の初期ウィンドウサイズ、

```text
1350 × 800
```

を維持する。

読書ステータスは新しい行を追加せず、既存の読了年月と同じ行へ横並びで配置する。

第一候補は次の構成とする。

```text
読了年月 [2026-07]    読書状態 [未設定 ▼]
```

必要に応じて現在表示している、

```text
例：2026-07
```

の補助表示を整理し、横方向のスペースを確保する。

## 23. フォーム値取得

## 24. 新規登録

新規登録時に読書ステータスを`BookService.add_book()`へ渡す。

正常登録後は既存仕様どおり入力フォームを自動クリアし、読書ステータスも「未設定」へ戻す。

---

## 25. 更新

更新時は選択中の書籍の読書ステータスを`BookItem`へ設定し、既存の更新処理へ渡す。

正常更新後は入力フォームを自動クリアし、読書ステータスも「未設定」へ戻す。

---

## 26. 書籍一覧

Version 1.3では、書籍一覧へ「読書状態」列を追加する方向とする。

表示値は日本語とする。

```text
未設定
未読
読書中
読了
```

DB内部値をそのまま表示しない。

---

## 27. Treeview列

`TREE_COLUMNS`へ`reading_status`を追加する。

第一候補は、

```text
読了年月
読書状態
```

の順で並べる。

列幅は小さめとし、既存画面の横方向を極端に広げない。

横スクロールは既存のものを利用する。

## 28. 検索

Version 1.3の読書ステータス管理では、読書ステータスを複合条件検索の対象へ追加しない。

既存の検索条件は維持する。

```text
書籍名
著者名
出版社
ISBN
雑誌コード
```

読書ステータス検索が日常利用で必要と判断した場合は、将来Versionで検討する。

---

## 29. ソート

Version 1.3の読書ステータス管理では、読書ステータスをソート対象へ追加しない。

既存の、

```text
登録順
書籍名
著者名
出版社
読了年月
```

を維持する。

読書ステータス順のソートは将来必要性を確認してから検討する。

---

## 30. ヘッダークリックソート

読書状態列はVersion 1.3ではヘッダークリックソート対象外とする。

列見出しは表示するが、クリックしてもソートしない。

---

## 31. CSVエクスポート

Version 1.3の読書ステータス管理では、CSVエクスポートへの`reading_status`追加を検討対象とする。

CSVはbook_managerに保存されているデータを外部へ出力する機能であるため、原則として読書ステータスも出力する方向とする。

CSV上の値を、

```text
未設定
未読
読書中
読了
```

とするか、

```text
空欄
unread
reading
completed
```

とするかは実装前に既存CSV設計との整合性を確認して決定する。

---

## 32. 外部書誌情報取得

Google Books APIやopenBDから取得する書誌情報には、book_manager利用者個人の読書ステータスを含めない。

外部書誌情報取得時に`reading_status`を変更しない。

既存の入力値上書き確認とも独立して扱う。

---

## 33. 表紙画像

読書ステータス機能は表紙画像取得・キャッシュ・表示処理へ影響を与えない。

一覧の表紙サムネイル表示も維持する。

---

## 34. 重複候補

読書ステータスは重複候補判定には使用しない。

既存の、

```text
書籍名
ISBN
雑誌コード
```

による判定を維持する。

- 読了を表示できる。
- 一覧へ日本語状態を表示できる。
- 入力クリアで未設定へ戻る。

- 読書中ページ数

これらは実利用結果を踏まえて将来Versionで検討する。
