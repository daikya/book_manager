# バックアップ復元機能 設計書

## 1. 目的

Book Managerで自動作成されたSQLiteデータベースのバックアップから、書籍データを安全に復元できる機能を追加する。

復元操作によって現在のデータが失われる危険を抑えるため、復元元データベースの事前検証と、復元直前の現行データベースのバックアップを行う。

本機能はVersion 1.4のデータ移行・復旧機能の一部として実装する。

---

## 2. 対象範囲

### 2.1 対象

復元対象はBook Managerが使用するSQLiteデータベースとする。

```text
data/books.db
```

復元元として、SQLiteデータベースファイルを選択する。

主な対象は自動バックアップによって作成された以下のファイルとする。

```text
backups/books_YYYYMMDD_HHMMSS.db
```

### 2.2 対象外

以下は復元対象外とする。

* 表紙画像キャッシュ
* アプリケーション設定
* CSVファイル
* ログファイル
* その他SQLiteデータベース以外のファイル

表紙画像キャッシュは現在のバックアップ機能でも対象外であるため、復元機能でも扱わない。

---

## 3. 基本方針

バックアップ復元は以下の方針で実装する。

1. GUIから復元元データベースを選択する。
2. 復元元データベースを検証する。
3. 復元直前の現在のデータベースをバックアップする。
4. SQLite Backup APIを使用して復元する。
5. 復元後のデータベースを確認する。
6. GUIの書籍一覧を再読み込みする。
7. 利用者へ結果を通知する。

復元元データベースの検証に失敗した場合は、現在のデータベースを変更しない。

---

## 4. 復元処理フロー

復元処理の基本フローを以下とする。

```text
復元ボタン押下
    ↓
復元元DBを選択
    ↓
キャンセルされたか
    ├─ Yes → 終了
    ↓ No
復元元DBを検証
    ↓
検証成功か
    ├─ No → エラー表示 → 終了
    ↓ Yes
復元確認ダイアログ
    ↓
キャンセルされたか
    ├─ Yes → 終了
    ↓ No
現在のDBを復元前バックアップ
    ↓
バックアップ成功か
    ├─ No → エラー表示 → 終了
    ↓ Yes
復元実行
    ↓
復元後DBを確認
    ↓
GUI一覧再読み込み
    ↓
成功メッセージ表示
```

---

## 5. 復元元データベースの検証

復元元として選択されたファイルを、現在のデータベースへ書き込む前に検証する。

### 5.1 ファイル存在確認

指定されたパスが通常ファイルとして存在することを確認する。

存在しない場合は復元を実行しない。

### 5.2 SQLiteデータベース確認

復元元ファイルをSQLiteで読み取り専用の検証対象として開く。

SQLiteデータベースとして正常に開けない場合は復元を拒否する。

### 5.3 整合性確認

以下を実行する。

```sql
PRAGMA integrity_check;
```

結果が以下であることを確認する。

```text
ok
```

`ok` 以外の場合は破損したデータベースと判断し、復元を拒否する。

### 5.4 Book Managerデータベース確認

以下のテーブルが存在することを確認する。

```text
book_items
```

存在しない場合はBook Manager用データベースではないと判断し、復元を拒否する。

### 5.5 スキーマVersion確認

以下からスキーマVersionを取得する。

```sql
PRAGMA user_version;
```

復元元データベースのVersionが現在のアプリケーションの対応Versionより新しい場合は復元を拒否する。

```text
backup_version > application_version
```

の場合、

```text
このバックアップは現在のアプリケーションでは復元できません。
```

相当のエラーとする。

現在より古いVersionのデータベースについては復元を許可する。

復元後、既存のデータベース初期化・マイグレーション処理によって現行Versionへ移行できる構成とする。

---

## 6. 復元直前バックアップ

復元処理を開始する前に、現在使用中のデータベースをバックアップする。

目的は、誤ったバックアップを復元した場合でも、復元操作直前の状態へ戻せるようにすることである。

### 6.1 保存形式

既存の自動バックアップと同じファイル名規則を使用する。

```text
books_YYYYMMDD_HHMMSS.db
```

復元専用のファイル名規則は追加しない。

これにより、既存のバックアップ一覧取得および世代管理処理をそのまま利用できる。

### 6.2 24時間制限との関係

自動バックアップで使用する「最新バックアップから24時間以上経過している場合のみ作成する」という条件は、復元直前バックアップには適用しない。

復元操作は現在のデータを上書きする重大な操作であるため、最新バックアップの作成日時に関係なく必ず復元直前バックアップを作成する。

したがって、通常の自動バックアップとは別に、強制的にバックアップを作成できる内部処理を利用する。

### 6.3 バックアップ失敗時

復元直前バックアップの作成に失敗した場合は復元を実行しない。

現在のデータベースを安全に退避できない状態では、復元による上書きを禁止する。

---

## 7. BackupServiceの責務

既存の `BackupService` に復元機能を追加する。

公開インターフェースとして以下を想定する。

```python
def restore_backup(
    self,
    backup_path: Path,
) -> None:
    """指定されたバックアップからデータベースを復元する。"""
```

`restore_backup()` は以下を担当する。

* 復元元ファイルの検証
* 復元前バックアップの作成
* SQLite Backup APIによる復元
* 復元後データベースの確認
* エラー発生時の例外送出

GUI固有の処理は担当しない。

以下はGUI側の責務とする。

* ファイル選択
* 確認ダイアログ
* 成功メッセージ
* エラーメッセージ
* 書籍一覧の再読み込み

---

## 8. SQLite Backup APIによる復元

単純なファイルコピーではなく、SQLite Backup APIを使用する。

通常バックアップでは以下の方向でコピーしている。

```text
現在DB → バックアップDB
```

復元では逆方向とする。

```text
バックアップDB → 現在DB
```

概念的には以下となる。

```python
source_connection.backup(
    destination_connection,
)
```

ここで、

```text
source_connection
    = 復元元バックアップDB

destination_connection
    = data/books.db
```

とする。

SQLiteデータベースの取り扱いを既存バックアップ処理と統一し、SQLite管理外の単純なファイルコピーによる復元は行わない。

---

## 9. 復元後の処理

復元完了後は、既存のデータベース初期化処理を実行する。

これにより、古いスキーマVersionのバックアップを復元した場合は、現在のVersionへ必要なマイグレーションを適用する。

その後、GUIでは書籍一覧を再読み込みする。

```python
self._load_all_books()
```

必要に応じて入力フォームも初期状態へ戻す。

復元前に選択されていた書籍IDは、復元後に存在する保証がないため、その選択状態は維持しない。

## 10. GUI設計

### 10.1 ボタン

メイン画面へ以下のボタンを追加する。

```text
バックアップ復元
```

CSV関連ボタン付近に配置する。

例：

```text
CSVエクスポート  CSVインポート  バックアップ復元          終了
```

### 10.2 ファイル選択

ボタン押下時にファイル選択ダイアログを表示する。

対象拡張子は原則として以下とする。

```text
*.db
```

ファイル選択をキャンセルした場合は何も行わない。

### 10.3 復元確認

復元元ファイルの検証後、実際の復元を開始する前に確認ダイアログを表示する。

表示例：

```text
バックアップからデータを復元します。

現在のデータは復元前にバックアップされます。
復元すると、現在のデータは選択したバックアップ時点の状態に置き換わります。

続行しますか？
```

利用者がキャンセルした場合は復元しない。

### 10.4 成功通知

復元成功時は以下に相当するメッセージを表示する。

```text
バックアップからデータを復元しました。
```

### 10.5 エラー通知

復元に失敗した場合は、GUIでエラーダイアログを表示する。

利用者向けには簡潔なメッセージを表示し、詳細な例外情報は既存方針と同様に標準エラー出力へ出力する。

---

## 11. エラー時の安全性

復元処理では現在のデータを保護することを最優先とする。

### 11.1 検証失敗

復元元DBの検証に失敗した場合：

```text
現在DB
    → 変更しない
```

### 11.2 復元前バックアップ失敗

現在DBの退避バックアップに失敗した場合：

```text
現在DB
    → 変更しない
復元
    → 実行しない
```

### 11.3 復元処理失敗

復元開始後にエラーが発生した場合は、復元直前に作成したバックアップが残っているため、復旧可能な状態を維持する。

復元処理中の失敗から自動的に再復元する処理はVersion 1.4では実装しない。

自動ロールバック機能は処理を複雑化させるため、必要性が確認された場合に将来検討する。

---

## 12. テスト方針

### 12.1 BackupServiceテスト

最低限、以下を自動テストする。

* 正常なバックアップから復元できる
* 復元によって現在DBの内容がバックアップDBの内容へ置き換わる
* 復元直前バックアップが作成される
* 24時間以内に既存バックアップが存在しても復元直前バックアップを作成する
* 復元元ファイルが存在しない場合は失敗する
* SQLiteではないファイルを拒否する
* 破損したSQLite DBを拒否する
* `book_items` テーブルが存在しないDBを拒否する
* 現在より新しいスキーマVersionのDBを拒否する
* 古いスキーマVersionのDBを復元できる
* 検証失敗時に現在DBを変更しない
* 復元前バックアップ失敗時に現在DBを変更しない

### 12.2 GUIテスト

最低限、以下を確認する。

* 復元ボタンからファイル選択処理が呼ばれる
* ファイル選択キャンセル時は復元処理を呼ばない
* 確認キャンセル時は復元処理を呼ばない
* 復元成功時に一覧を再読み込みする
* 復元成功メッセージを表示する
* 復元失敗時にエラーメッセージを表示する
* 復元失敗時に一覧再読み込みを行わない

### 12.3 手動確認

自動テスト完了後、実際のアプリケーションを起動する。

```powershell
python .\main.py
```

実際のバックアップファイルを使用し、以下を確認する。

1. バックアップファイルを選択できる。
2. 確認ダイアログが表示される。
3. 復元前バックアップが作成される。
4. 過去のデータへ正常に復元される。
5. 書籍一覧が復元後の内容へ更新される。
6. アプリケーションを再起動しても復元後のデータが維持される。

GUI機能については、自動テスト成功だけでは完了とせず、実際のGUI操作による結合確認を必須とする。

7. GUI復元処理追加

9. focused pytest

12. ドキュメント更新
13. コミット
