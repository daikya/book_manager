# ウィンドウ状態保存・復元 設計書

## 1. 目的

Book Manager Version 2.3では、メインウィンドウの位置、サイズ、最大化状態を終了時に保存し、次回起動時に安全に復元する。

前回の作業環境を引き継げるようにしつつ、モニター構成や解像度が変わった場合でも、画面外にウィンドウが表示されないことを重視する。

## 2. 対象範囲

### 2.1 対象

- メインウィンドウの通常時の位置
- メインウィンドウの通常時の幅と高さ
- 終了時の最大化状態
- 複数モニター環境における負の座標
- モニター構成変更後の安全な表示位置補正
- 設定画面からの保存状態リセット

### 2.2 対象外

- サブウィンドウの位置とサイズ
- 一覧列の幅や並び順
- テーマ、フォント、表示倍率
- 最小化状態の復元
- ウィンドウ状態の複数プロファイル管理

## 3. 現在の実装との関係

保存状態がない場合、メインウィンドウは起動時に次の値を基本として中央配置される。

- 標準サイズ: `1350 x 800`
- 最小サイズ: `1150 x 650`

`BookManagerApplication._on_exit()`では、通常矩形と最大化状態を保存してからルートウィンドウを破棄する。移動・サイズ変更中はメモリ上の通常矩形だけを更新する。

既存の `window_positioning.py` はサブウィンドウの親画面中央配置に使用されている。メインウィンドウの復元では負の座標と複数モニターの作業領域を扱う必要があるため、用途を分けた処理を追加する。

## 4. 保存先

ウィンドウ状態は、バックアップ設定とは独立したJSONファイルへ保存する。

```text
%LOCALAPPDATA%\book_manager\window_state.json
```

`BOOK_MANAGER_HOME` が指定されている場合は、既存の利用者データと同様に次の場所を使用する。

```text
%BOOK_MANAGER_HOME%\window_state.json
```

`ApplicationPaths` に `window_state_path` を追加し、保存先の組み立てを一か所へ集約する。

独立ファイルとする理由は次のとおり。

- バックアップ設定と画面表示状態の責務を分離できる
- 破損時に影響範囲をウィンドウ配置だけに限定できる
- 設定画面からウィンドウ状態だけをリセットできる
- 将来のスキーマ変更を個別に管理できる

## 5. 保存形式

```json
{
  "schema_version": 1,
  "x": 120,
  "y": 80,
  "width": 1350,
  "height": 800,
  "maximized": false
}
```

| 項目 | 型 | 内容 |
|---|---|---|
| `schema_version` | integer | 保存形式のVersion。初期値は`1` |
| `x` | integer | 通常表示時の左上X座標 |
| `y` | integer | 通常表示時の左上Y座標 |
| `width` | integer | 通常表示時の幅 |
| `height` | integer | 通常表示時の高さ |
| `maximized` | boolean | 終了時に最大化されていたか |

### 5.1 検証条件

- `schema_version` は対応する値であること
- `x` と `y` は `-100000` 以上 `100000` 以下の整数であること
- `width` と `height` は `1` 以上 `32767` 以下の整数であること
- `maximized` は真偽値であること
- Pythonでは `bool` が `int` の派生型であるため、整数項目に真偽値を受け入れないこと
- 必須項目の欠落、不明な形式、JSON解析失敗は無効な設定として扱うこと

## 6. Model

不変の値オブジェクト `WindowState` を追加する。

```python
@dataclass(frozen=True)
class WindowState:
    x: int
    y: int
    width: int
    height: int
    maximized: bool
    schema_version: int = 1
```

Modelは値の保持と妥当性検証を担当し、ファイル入出力やTkinter操作を持たない。

## 7. 保存処理

`WindowStateStore` を追加し、次の操作を提供する。

- `load() -> WindowState | None`
- `save(state: WindowState) -> None`
- `delete() -> None`

### 7.1 読み込み

- ファイルが存在しない場合は `None` を返す
- 正常なJSONは `WindowState` に変換する
- 破損、不正な型、未対応スキーマは例外をアプリケーションまで伝播させず、ログへ記録して `None` を返す
- ウィンドウ状態の異常によってデータベース起動を妨げない

### 7.2 書き込み

- UTF-8のJSONとして保存する
- 保存先ディレクトリがなければ作成する
- 一時ファイルへ書き込み後、置換する原子的な更新を行う
- インデントと末尾改行を付け、人が確認しやすい形式にする
- 書き込み失敗はログへ記録し、終了処理を継続する

### 7.3 削除

- ファイルが存在すれば削除する
- 存在しない場合も正常終了する
- 削除失敗は設定画面へ分かる形で通知する

## 8. ウィンドウ状態の取得

### 8.1 通常表示時

`<Configure>` イベントで位置とサイズを取得し、メモリ上の最新状態だけを更新する。

イベントのたびにファイル保存は行わない。移動・サイズ変更中の頻繁なディスク書き込みを避け、終了時に一度だけ保存する。

### 8.2 最大化時

最大化中にTkinterから取得できる座標とサイズは、通常表示へ戻したときの形状ではない。このため、最大化前に最後に確認できた通常表示時の位置とサイズを保持する。

終了時に最大化されている場合は、次の組み合わせを保存する。

- 位置とサイズ: 最後の通常表示時の値
- `maximized`: `true`

### 8.3 最小化時

最小化状態そのものは保存・復元しない。終了時に最小化されていても、最後の通常表示時の位置とサイズを保存し、`maximized` は `false` とする。

## 9. 複数モニター対応

### 9.1 座標

Windowsの仮想デスクトップでは、主モニターの左側や上側に配置されたモニターが負の座標を持つ。したがって、`x` と `y` を単純に0以上へ補正してはならない。

### 9.2 作業領域

タスクバーを除いた各モニターの作業領域を取得する。Windowsではモニター列挙APIを使用し、各領域を次の形で扱う。

```python
ScreenWorkArea(left, top, right, bottom, primary)
```

Windows APIを利用できない環境やテストでは、Tkinterから取得した画面サイズを `(0, 0, width, height)` の単一作業領域として使用する。

### 9.3 復元先モニターの選択

保存されたウィンドウ矩形と各作業領域の交差面積を計算する。

1. 交差面積が最大のモニターを選ぶ
2. 同値の場合は主モニターを優先する
3. どのモニターとも交差しない場合は主モニターを選ぶ

これにより、以前使用していたモニターが残っている場合は元のモニターを優先できる。

### 9.4 位置とサイズの補正

選択した作業領域に対して次の順序で補正する。

1. 幅と高さを作業領域以内へ縮小する
2. 左端と上端が作業領域より外側なら内側へ移動する
3. 右端と下端が作業領域より外側なら内側へ移動する
4. タイトルバーを含むウィンドウ全体が操作可能な位置に収まることを保証する

保存状態が完全に画面外の場合は、標準サイズを作業領域に収まる大きさへ調整し、主モニター中央へ配置する。

## 10. 小さい作業領域への対応

既定の最小サイズ `1150 x 650` より作業領域が小さい場合、固定した最小サイズを先に設定するとウィンドウが画面からはみ出す可能性がある。

起動時は次のように扱う。

- 作業領域が十分な場合は `1150 x 650` を最小サイズにする
- 作業領域が小さい場合は、その作業領域に収まる値まで実効最小サイズを下げる
- 復元サイズも実効最小サイズ以上、作業領域以下へ補正する

## 11. 起動時の復元順序

1. `ApplicationPaths.window_state_path` を決定する
2. `WindowStateStore.load()` で保存状態を読み込む
3. 利用可能なモニター作業領域を取得する
4. 保存状態が有効なら安全な位置とサイズへ補正する
5. 保存状態がない、または無効なら現在の既定処理で主モニター中央へ配置する
6. 通常表示時のジオメトリを `geometry()` へ設定する
7. 必要なレイアウト更新を行う
8. 保存状態の `maximized` が真なら `state("zoomed")` を適用する
9. `<Configure>` の監視を開始する

最大化を先に適用せず、通常表示時のジオメトリを設定してから最大化する。これにより「元に戻す」操作でも保存していた通常サイズへ戻せる。

## 12. 終了時の保存順序

1. 現在のウィンドウ状態を確認する
2. 通常表示中なら最新の位置とサイズをメモリへ反映する
3. 最大化状態を判定する
4. `WindowState` を組み立てる
5. `WindowStateStore.save()` で一度だけ保存する
6. 保存に失敗した場合はログへ記録する
7. アプリケーションを終了する

保存失敗を理由に終了を中止しない。

## 13. 設定画面からのリセット

設定画面の「アプリケーション情報」付近に、次回起動時のウィンドウ配置を初期状態へ戻す操作を追加する。

表示例:

```text
ウィンドウ配置  [初期状態に戻す]
```

操作時の動作:

1. 確認ダイアログを表示する
2. `window_state.json` を削除する
3. 「次回起動時から適用されます」と通知する
4. 現在のウィンドウ位置とサイズは変更しない

### 13.1 終了時の再作成防止

リセット後に通常の終了保存を行うと、削除した状態ファイルが同じセッションの現在位置で再作成されてしまう。

このため、リセット成功時にアプリケーション内の `window_state_save_suppressed` を真にする。以後、そのセッションの終了処理ではウィンドウ状態を保存しない。

次回起動時は状態ファイルが存在しないため、既定サイズ・中央配置が適用される。次回の終了時から通常どおり保存を再開する。

## 14. エラー時の動作

| 状況 | 動作 |
|---|---|
| 状態ファイルがない | 既定サイズで中央配置する |
| JSONが壊れている | ログを残し、既定配置で起動する |
| 値が不正 | ログを残し、既定配置で起動する |
| 未対応スキーマ | ログを残し、既定配置で起動する |
| モニター情報を取得できない | Tkinterの単一画面情報へフォールバックする |
| 保存に失敗 | ログを残して終了を継続する |
| リセットに失敗 | エラーダイアログを表示し、保存抑止は行わない |

状態ファイルの異常は非致命的な問題として扱い、データベース、バックアップ、書誌情報取得などの主要機能へ影響させない。

## 15. 責務分担

| 構成要素 | 責務 |
|---|---|
| `WindowState` | 保存値と妥当性の表現 |
| `WindowStateStore` | JSONの読み込み、原子的保存、削除 |
| ウィンドウ配置処理 | 作業領域取得、モニター選択、位置・サイズ補正 |
| `ApplicationPaths` | 状態ファイルのパス提供 |
| `BookManagerApplication` | Tkinter状態取得、イベント監視、復元、終了保存、リセット連携 |
| 設定画面 | リセット操作、確認、結果通知 |
| `main.py` | 依存関係の生成と受け渡し |

## 16. テスト方針

### 16.1 Model

- 正常値を保持できる
- 負の座標を受け入れる
- 座標範囲外を拒否する
- 0以下または上限超過のサイズを拒否する
- 整数項目の真偽値を拒否する
- `maximized` の整数値を拒否する

### 16.2 Store

- ファイルがない場合に `None` を返す
- 正常なJSONを読み込める
- 保存後に同じ状態を読み込める
- 保存先ディレクトリを作成できる
- 壊れたJSONを安全に扱える
- 不正値と未対応スキーマを安全に扱える
- 一時ファイルを使って置換できる
- 存在するファイルを削除できる
- 存在しないファイルの削除を正常に扱える

### 16.3 配置計算

- 主モニター内の位置を維持する
- 左側モニターの負のX座標を維持する
- 上側モニターの負のY座標を維持する
- 最大交差面積のモニターを選ぶ
- 完全に画面外なら主モニター中央へ戻す
- 右端・下端のはみ出しを補正する
- 作業領域より大きいサイズを縮小する
- 小さい画面で実効最小サイズを調整する

### 16.4 GUI

- 保存状態がない場合に既定配置となる
- 通常状態を復元できる
- 通常ジオメトリ適用後に最大化できる
- `<Configure>` ではメモリだけを更新する
- 最大化中のサイズで通常ジオメトリを上書きしない
- 終了時に一度だけ保存する
- 保存失敗時も終了できる
- リセット確認の取消時は削除しない
- リセット成功時に終了保存を抑止する
- リセット失敗時に終了保存を抑止しない

## 17. 実機確認

### 17.1 基本動作

1. ウィンドウを移動・サイズ変更して終了する
2. 再起動後に位置とサイズが復元される
3. 最大化して終了する
4. 再起動後に最大化される
5. 「元に戻す」で最大化前の通常サイズへ戻る
6. 最小化中に終了しても次回は最小化されない

### 17.2 複数モニター

1. 左側または上側のモニターへ移動して終了する
2. 負の座標を含む位置が同じモニターへ復元される
3. そのモニターを外して起動する
4. 主モニターの操作可能な範囲へ表示される
5. 解像度や表示倍率を変更しても画面外へ出ない

### 17.3 リセット

1. 状態を保存した状態で設定画面を開く
2. 「初期状態に戻す」を実行する
3. 状態ファイルが削除される
4. アプリケーションを終了しても状態ファイルが再作成されない
5. 再起動すると既定サイズで中央表示される
6. その後に終了すると状態保存が再開される

### 17.4 異常系

1. `window_state.json` を不正なJSONへ変更する
2. アプリケーションが既定配置で起動する
3. 書籍データとバックアップ設定に影響がない
4. ログに原因を確認できる
