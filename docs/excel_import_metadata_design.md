# Version 2.7 Excel移行・書誌情報補完設計

設計・更新日：2026年10月21日。Version 2.7の開発中ソース版へExcel取込・年月履歴・参照ISBN・候補検索・比較画面を実装した。正式公開版はVersion 2.6.0。今回拡張した候補検索のWindows実機確認と配布版検証は未完了。

## 1. 目的と操作の分離

既存のExcel読書記録を保持して登録し、その後、利用者が選択した1冊だけを検索・補完する。

Excel読み込み・検査・登録は外部APIを呼び出さない。起動時、取込直後、一覧表示時にも自動候補検索しない。

## 2. 実装済みの基盤

- BookItemとbook_itemsにreference_isbnを追加。ISBN-13へ正規化し、複数記録で共有できる。
- 読書履歴の日付Validator・DB制約・GUI・集計・完全データZIPをYYYY-MMとYYYY-MM-DDへ対応。
- DBスキーマVersionは8。Version 7からの更新前に検証済みバックアップを作成する。
- 完全データZIPは形式Version 2を出力し、旧形式Version 1も読み込む。
- 単一CSVに参照ISBNを追加し、旧ヘッダーを引き続き受け付ける。
- 書籍の現在状態と読書履歴は独立した仕様を維持する。

## 3. 年月精度の読書履歴

started_onとcompleted_onを、YYYY-MMまたはYYYY-MM-DDを保持するTEXTとして拡張する。文字列長から精度を判別できるため、精度カラムは追加しない。

| 値 | 意味 |
| --- | --- |
| 2006-05 | 2006年5月。日は不明 |
| 2006-05-20 | 2006年5月20日 |
| NULL | 未設定 |

年のみの値は今回受け付けない。既存の完全な日付は変更しない。保存時の正規形はASCII数字とハイフンとする。

GUIの項目名は「開始日・年月」「読了日・年月」とし、両書式の入力例を示す。月のみの値を完全な日付に見せない。

### 前後関係の判定

年月は比較時だけ、その月の初日から末日までの範囲として解釈する。日付は同じ日を下限・上限とする。比較用の日付を保存値へ書き戻さない。

開始の下限が終了の上限より後なら、矛盾が確定するため拒否する。それ以外は登録を許可する。範囲が重なり順序を確定できない場合は、検査画面で精度の説明を示す。

| 開始 | 終了 | 判定 |
| --- | --- | --- |
| 2026-05-20 | 2026-05 | 許可。終了日は不明 |
| 2026-05 | 2026-05-10 | 許可。開始日は不明 |
| 2026-06 | 2026-05-31 | 拒否 |
| 2026-05-20 | 2026-05-10 | 拒否 |
| 2026-05 | 2026-05 | 許可 |

両方の値を同じValidatorで検証する。DB制約も同じ判断に合わせて変更し、従来の単純文字列比較を残さない。

### 並び順と集計

履歴は読了値、開始値、登録日という既存の優先順を維持する。異なる月は年月順、同月では完全日付を日順、月精度の記録をその後、同値はID降順とする。同月の月精度の記録について、実際の前後関係は断定しない。

completed_onが月精度でも読了記録として数え、その年月の集計に含める。開始のみ・メモのみの履歴は読了数に含めない。

completion_monthは従来のYYYY-MMを維持する。通常の履歴編集で現在状態やcompletion_monthを自動変更しない。Excel取込時は、確認した列割当から書籍の読了年月と履歴を同時に作成できる。

## 4. 参照ISBN（実装済み）

BookItemとbook_itemsへreference_isbn（任意TEXT）を追加した。ISBN-10・ISBN-13の検証とISBN-13への正規化に対応する。

通常isbnは登録対象の版のISBN、reference_isbnは別媒体・別版から情報を取得するために利用者が選んだISBNとする。通常ISBNの重複判定に参照ISBNを含めず、複数の記録で同じ参照ISBNを共有できる。

2026年10月2日の利用者との確認により、当初の「空欄の内容紹介・書影だけ」という方針を変更し、参照ISBNも通常ISBNと同じ書誌情報取得・上書き確認を行う仕様とした。

- 通常ISBNを優先し、空欄の場合に参照ISBNを使用する。
- 取得したISBNは参照ISBN欄へ反映し、通常ISBN欄は空欄のまま維持する。
- 書籍名・著者名・出版社・出版形態・内容紹介・表紙画像も通常ISBNと同じ処理で反映する。入力済み情報は既存の確認を経て反映する。
- 参照元の出版形態や書影が元媒体と異なる場合がある。Audible等の出版形態を参照取得時に常に保持する仕様ではない。
- 読書情報、評価、お気に入り、タグ、備考は書誌情報取得で変更しない。
- 表紙画像は既存のCoverImageServiceとキャッシュ処理を使用する。

候補一覧と項目別比較画面を開発中ソース版へ実装済み。ASIN専用項目・ASIN検索は今回の対象外。ISBNなし候補の直接取得は8.1の追加設計に従う。

## 5. DB移行

スキーマVersionを7から8へ更新する。

1. 更新前DBの検証済みバックアップを作成する。失敗したら移行しない。
2. 1トランザクションでreference_isbnを追加し、履歴テーブルの制約を更新する。
3. 履歴テーブルを再構築する場合はID、書籍ID、日時、メモ、既存日付をそのままコピーする。
4. インデックス、外部キー、削除時CASCADE、自動採番状態を維持する。
5. 件数・データ・外部キーを検証してからuser_versionを8へ更新する。
6. 失敗時はロールバックする。

既存のreference_isbnはNULLとなる。通常ISBNを参照ISBNへ自動移動しない。移行バックアップはDB初期化内のschema_backupsへ作成する。通常の自動バックアップとは別に、スキーマ変更前の保存を保証する。

旧スキーマから新Versionへ移行する経路と、新規DBの作成を両方検証する。移行済みDBをVersion 2.6へ戻して利用することは想定しない。

## 6. 完全データZIPの互換性

最新出力をformat_version=2とする。5ファイル構成を維持する。

- book_items.csvでは「ISBN」の直後へ「参照ISBN」を追加する。
- reading_histories.csvの列は維持し、開始・読了の値にYYYY-MMも許可する。
- manifestのdatabase_schema_versionは出力元の実際のVersionを記録する。
- Version 2.7の読込は形式Version 1と2を明示的に対応する。
- Version 1では旧ヘッダーと完全日付だけを受け付け、参照ISBNをNULLへ補う。
- Version 2では新ヘッダーと精度を保った履歴値を検証する。
- manifestを先に検査し、その形式Versionに対応するヘッダー・Parserを選択する。
- 未知の形式Versionは拒否する。形式VersionとDBスキーマVersionを混同しない。
- 空DBへの復元、全件検査、直前バックアップ、単一トランザクションを維持する。

Version 2.6ではVersion 2のZIPを読み込めない。新しいデータを旧形式へ黙って切り捨てて出力しない。GUIと利用説明へ対応Versionを明記する。

単一CSVにも参照ISBNを保持する新ヘッダーを定義し、既存の現行・旧ヘッダーを引き続き読み込む。従来どおり複数読書履歴は単一CSVへ含めず、完全移行にはZIPを使う。参照ISBNはISBNの直後へ配置する。

## 7. Excel取込（実装・ソース版検証済み）

openpyxl>=3.1.5,<4を使用する。.xlsxのワークブック全体でシートを1枚にする。複数シートは拒否し、シート選択・統合は行わない。元ファイルは変更しない。

読み取りServiceは見出し行番号を指定できるが、現在のGUIは1行目を見出しとする。見出しと各列のデータ例を表示し、列を任意項目へ割り当てる。書籍名は必須、ISBNは任意。同じ列を複数項目へ割り当てない。未割り当て列は取り込まない。

和暦年月・西暦年月・完全日付・Excelの日付値を正規化する。全角数字と月だけの表示書式を扱い、年月精度を保持する。単なる数値を日付シリアルとして推測しない。数式は実行せず、割り当てたセルの保存済み計算値がない場合は再計算・保存を案内する。未使用列の数式は取込を妨げない。

読書状態の列を割り当てない場合、読了値ありは「読了」、開始値のみは「読書中」を提案し、確認画面で注意事項を表示する。状態列を割り当てて空欄なら未設定を保持する。読了値から書籍の読了年月を補い、別途指定した読了年月と矛盾する場合は拒否する。

開始・読了・履歴備考のいずれかがある行は1回分の履歴として取り込む。履歴情報がない行へ架空の履歴を作らない。既存DBの書籍や履歴は更新しない。

各行を別の書籍として追加し、同名・同著者・同ISBNでも自動統合・除外しない。既存書籍へ再読履歴だけを関連付ける画面は未実装であり、初期取込の対象外とする。同じExcelの再取込は追加登録になる。

空行は検査結果で明示し、管理用行は利用者が実際のExcel行番号で除外する。GUIは「2,5,8-10」の指定に対応する。タイトルによる管理用最終行の除外はOptionsで明示設定できるが、現在のGUIには入力欄を設けていない。特定タイトルを無条件に除外しない。出版形態の列を割り当てない場合だけ、利用者指定の既定値を適用する。

事前検査画面で登録予定の全項目、エラー、注意事項、除外・空行を表示する。エラーが1件でもあれば全件登録を禁止する。登録可能な場合も確認チェックを必須とする。

実行直前に元ファイルを同じ条件で読み直し、SHA-256と正規化後のPreview全体を再比較する。BookServiceが検査の都度付ける作成日時・更新日時は比較から除外し、登録時にRepositoryで生成する。値や履歴の変更は拒否する。

BEGIN IMMEDIATEで書き込みを予約した後、別の読み取り接続を使うBackupServiceで必須バックアップを作成する。バックアップ後に書籍・タグ・関連付け・履歴を同じトランザクションで登録し、件数・外部キー・DB整合性を確認してコミットする。途中例外ではロールバックし、バックアップを残す。Excel取込はAPIを一度も呼び出さない。

## 8. 候補検索と補完（開発中ソース版）

選択した1冊の書籍名・著者名・出版社から利用者の操作でGoogle Booksを検索する。いずれか1項目以上を指定する。3条件は候補取得のキーワードとし、厳密なAND絞り込みではない。

2026年10月21日の拡張設計：外部検索は通常キーワードで1回のみ（最大20件、Clientでは最大40件）。自動的な条件緩和・追加ページ取得・再試行は行わない。検索語はNFKCと空白を整え、日本語・中国語の姓名間の空白を除く。元の入力値と取得データは変更しない。

候補比較ではNFKC・casefold・空白除去を適用し、中黒とハイフン類を無視する。ただし長音「ー」、数字、巻数、上下巻は残す。出版社の先頭・末尾の株式会社／有限会社表記は比較時に除く。作品の同一性や別名は推測しない。

指定項目ごとに一致・部分一致・近似（書籍名のみ）・要確認・情報なしを表示し、一致項目が多い候補を上位に並べる。同順位ではAPIの順序を維持する。数字・上下巻の違う書名は近似判定しない。低一致候補も削除せず、APIから取得できない候補の発見は保証しない。

画面は出版社欄を追加し、検索中の条件編集を無効にする。画面の高さは620のまま維持し、候補表示部分を伸縮させる。巻・版・媒体・取得済みISBNを見て候補を選ぶ。

候補は自動確定しない。紙の版を参照する運用では文庫を優先する目安を示すが、同じ作品・巻かどうかを利用者が確認する。ISBNのない候補もGoogle IDがあれば書誌情報を取得できるが、ISBNは推測しない。

GUIを止めず、要求の重複・無制限の再試行を防ぐ。画面を閉じた後や対象書籍が変わった後の応答を別の書籍へ反映しない。

候補のGoogle IDから直接取得し、比較画面で項目を選んでフォームへ反映する。DB保存はメイン画面の登録・更新で行う。保存直前に対象の現在値を再確認し、別操作による変更があれば再比較する。

## 9. 必要な検証

- 日付、年月、うるう年、同月混在、明確な逆転、空欄、和暦・全角数字。
- 既存履歴のID・値保持、Version 7から8への更新と途中失敗。
- 月精度を含む読了集計と、開始のみ・メモのみの既存動作。
- 形式Version 1の読込、Version 2の全項目往復一致、未知Version拒否。
- 参照ISBNの共有、通常ISBNの重複判定、単一CSVとの互換性。
- Excel取込がAPIを一度も呼ばないこと、取消・例外でDBを維持すること。
- 各行を別記録として維持し、別巻・別媒体を自動統合しないこと、内容紹介と改行の保持。
- 候補検索の失敗・利用制限・遅延応答・取消、入力済み情報の保持。
- 検証用保存先での実Excel照合。通常利用DBへ直接試験取込しない。
- Windows配布版、バックアップ・復元、主要既存機能の回帰。

### 8.1 未登録フォームからの候補取得（2026年10月21日追加）

登録済み書籍の選択を必須にしない。新規フォームの候補選択後はGoogle Volume IDで詳細を直接取得し、既存の比較画面を経て選択項目だけ反映する。ISBN再検索はしない。通常ISBNを初期選択とし、参照ISBNを選ぶと内容紹介・書影のみ反映する。DB保存は利用者の「登録」「更新」まで行わない。

ISBNなし候補もIDがあれば詳細取得できる。既存ISBNを空欄で消さない。ISBNが複数ある場合は1つを明示選択する。詳細応答のIDと、選択したISBN（ある場合）の一致を検証し、不一致・通信失敗・比較取消ではフォームを変更しない。詳細取得も検索と同じワーカーで実行する。

「条件別に追加検索」は指定した各項目を単独で検索して候補を合併する（最大3回、明示操作のみ）。重複排除はGoogle ID単位。1回目の検索と追加検索の結果は原文を保持して再順位付けする。途中の通信失敗では追加結果を反映せず、既存候補を保持してエラー表示する。

「次の20件」は同じ条件でstartIndexを20ずつ進める（最大200件の範囲）。別条件で検索を始めた場合はページと結果をリセットする。一致候補のみ表示は取得済み候補に対する表示フィルターであり、APIに問い合わせない。
