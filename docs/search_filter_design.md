# 検索・絞り込み機能 設計書

## 1. 目的

Book Managerの既存の複合条件検索を拡張し、Version 1.3で追加した読書状態・お気に入り・評価を検索条件として利用できるようにする。

Version 1.5では、書誌情報による既存検索と読書情報による絞り込みを組み合わせ、登録済みの蔵書から目的の書籍をより簡単に探せるようにする。

既存の検索・並べ替え機能との整合性を維持し、個人利用で分かりやすく使えるシンプルな検索操作を優先する。

本機能はVersion 1.5の主要機能として実装する。

---

## 2. 対象範囲

### 2.1 Version 1.5で対応する範囲

* 既存の書籍名検索
* 既存の著者名検索
* 既存の出版社検索
* 既存のISBN検索
* 既存の雑誌コード検索
* 読書状態による絞り込み
* お気に入り状態による絞り込み
* 評価による絞り込み
* 複数検索条件のAND検索
* 検索結果を維持した並べ替え
* 検索条件クリア
* 検索エリアのレイアウト改善
* 起動時のメインウィンドウ表示位置改善
* 関連する自動テスト
* 実際のGUIによる動作確認

### 2.2 Version 1.5で対応しない範囲

* OR検索
* NOT検索
* 複雑な検索式
* 任意に検索条件を追加する方式
* 別ウィンドウによる詳細検索
* 検索条件の保存
* 検索履歴
* 全文検索
* あいまい検索
* 読書状態・お気に入り・評価による並べ替え
* 読了年月による範囲検索
* 登録日時・更新日時による範囲検索
* 統計・集計・グラフ表示

これらはVersion 1.5では実装せず、実利用で必要性が確認された場合に将来検討する。

---

## 3. 既存検索機能との関係

Version 1.2では、次の5項目による複合条件検索を実装した。

* 書籍名
* 著者名
* 出版社
* ISBN
* 雑誌コード

Version 1.3では、書籍に次の読書情報を追加した。

* 読書状態
* お気に入り
* 評価

Version 1.5では、これらを統合し、合計8項目を同一の検索条件として利用できるようにする。

```text
書籍名
著者名
出版社
ISBN
雑誌コード
読書状態
お気に入り
評価
```

既存5項目の検索仕様は変更せず、新しい3項目を追加する。

---

## 4. 基本方針

検索・絞り込み機能は以下の方針で実装する。

1. 入力・選択された検索条件だけを使用する。
2. 複数条件はすべてAND条件として扱う。
3. 書籍名・著者名・出版社は既存どおり部分一致検索とする。
4. ISBN・雑誌コードは既存どおり完全一致検索とする。
5. 読書状態は指定された状態との一致検索とする。
6. お気に入りはお気に入り／お気に入り以外を選択できるようにする。
7. 評価は未評価または指定評価以上で絞り込めるようにする。
8. すべての検索条件が未指定の場合は全件表示する。
9. 検索結果を維持したまま既存の並べ替え機能を利用できるようにする。
10. 検索条件クリアによって全件表示へ戻せるようにする。
11. GUIの縦方向のサイズを増やさず、既存画面内に検索条件を配置する。
12. 既存の検索・並べ替え機能に回帰を発生させない。

## 5. 読書状態による絞り込み

### 5.1 GUI表示

読書状態の検索条件は以下とする。

```text
すべて
未設定
未読
読書中
読了
```

初期値は「すべて」とする。

### 5.2 検索仕様

| GUI表示 | 検索用内部値        | 検索条件                           |
| ----- | ------------- | ------------------------------ |
| すべて   | `None`        | 条件なし                           |
| 未設定   | `"unset"`     | `reading_status IS NULL`       |
| 未読    | `"unread"`    | `reading_status = 'unread'`    |
| 読書中   | `"reading"`   | `reading_status = 'reading'`   |
| 読了    | `"completed"` | `reading_status = 'completed'` |

Book Managerでは保存データの`reading_status=None`が「未設定」を表す。

そのため、検索APIでは「条件なし」と「未設定を検索する」を区別する。

検索条件なしは`None`、未設定検索は検索専用値`"unset"`として扱う。

## 6. お気に入りによる絞り込み

### 6.1 GUI表示

お気に入りの検索条件は以下とする。

```text
すべて
お気に入りのみ
お気に入り以外
```

初期値は「すべて」とする。

### 6.2 検索仕様

| GUI表示   | 検索用内部値           | 検索条件              |
| ------- | ---------------- | ----------------- |
| すべて     | `None`           | 条件なし              |
| お気に入りのみ | `"favorite"`     | `is_favorite = 1` |
| お気に入り以外 | `"not_favorite"` | `is_favorite = 0` |

お気に入りは既存仕様どおり真偽値として管理し、未設定状態は持たない。

## 7. 評価による絞り込み

### 7.1 GUI表示

評価の検索条件は以下とする。

```text
すべて
未評価
★1以上
★2以上
★3以上
★4以上
★5
```

初期値は「すべて」とする。

### 7.2 検索仕様

| GUI表示 | 検索用内部値      | 検索条件             |
| ----- | ----------- | ---------------- |
| すべて   | `None`      | 条件なし             |
| 未評価   | `"unrated"` | `rating IS NULL` |
| ★1以上  | `1`         | `rating >= 1`    |
| ★2以上  | `2`         | `rating >= 2`    |
| ★3以上  | `3`         | `rating >= 3`    |
| ★4以上  | `4`         | `rating >= 4`    |
| ★5    | `5`         | `rating >= 5`    |

評価は完全一致ではなく、指定された評価以上を対象とする。

例えば「★4以上」を選択した場合、評価4および評価5の書籍を検索結果に含める。

Book Managerでは保存データの`rating=None`が「未評価」を表す。

そのため、検索APIでは「条件なし」と「未評価を検索する」を区別する。

検索条件なしは`None`、未評価検索は検索専用値`"unrated"`として扱う。

## 8. 複数条件の組み合わせ

既存5条件と新しい3条件は、すべてAND条件として組み合わせる。

例：

```text
著者名
東野圭吾

読書状態
読了

お気に入り
お気に入りのみ

評価
★4以上
```

この場合、すべての条件を満たす書籍だけを検索結果として表示する。

概念的なSQL条件は以下となる。

```sql
author LIKE '%東野圭吾%'
AND reading_status = 'completed'
AND is_favorite = 1
AND rating >= 4
```

指定されていない条件はSQLの検索条件へ追加しない。

## 9. BookServiceの責務

既存の`BookService.search_books()`を拡張する。

検索条件専用の新しいServiceや検索条件モデルはVersion 1.5では追加しない。

既存設計を維持し、必要な検索引数を追加する。

概念的な公開インターフェースは以下とする。

```python
def search_books(
    self,
    *,
    title: str | None = None,
    author: str | None = None,
    publisher: str | None = None,
    isbn: str | None = None,
    magazine_code: str | None = None,
    reading_status_filter: str | None = None,
    favorite_filter: str | None = None,
    rating_filter: str | int | None = None,
) -> list[BookItem]:
    """複数条件によるAND検索を行う。"""
```

`BookService.search_books()`は以下を担当する。

* 既存文字列検索条件の正規化
* ISBNのValidation
* 雑誌コードのValidation
* 読書状態検索条件のValidation
* お気に入り検索条件のValidation
* 評価検索条件のValidation
* 検索条件がすべて未指定の場合の全件取得
* `BookRepository`への検索条件の受け渡し

### 9.1 読書状態検索条件の許可値

```text
None
unset
unread
reading
completed
```

上記以外は不正な検索条件として扱う。

### 9.2 お気に入り検索条件の許可値

```text
None
favorite
not_favorite
```

上記以外は不正な検索条件として扱う。

### 9.3 評価検索条件の許可値

```text
None
unrated
1
2
3
4
5
```

0、6以上、その他の不正な値は検索条件として受け付けない。

## 10. BookRepositoryの責務

既存の`BookRepository.search_by_conditions()`を拡張する。

`BookRepository`は、`BookService`から渡された検索条件をSQLiteのWHERE条件へ変換する。

既存の5条件に加えて、以下を処理する。

### 10.1 読書状態

```text
unset
    → reading_status IS NULL

unread / reading / completed
    → reading_status = ?
```

### 10.2 お気に入り

```text
favorite
    → is_favorite = 1

not_favorite
    → is_favorite = 0
```

### 10.3 評価

```text
unrated
    → rating IS NULL

1～5
    → rating >= ?
```

検索条件は既存処理と同様に`AND`で連結する。

値をSQL文字列へ直接埋め込まず、値を必要とする条件ではプレースホルダーを使用する。

Version 1.5の検索機能追加によるデータベーススキーマ変更は行わない。

## 11. GUI設計

### 11.1 基本方針

検索条件の追加によってメインウィンドウを縦方向へ拡大しない。

現在の検索エリアと同じ3行構成を維持し、横方向の配置を調整する。

### 11.2 1行目

書誌情報による既存検索項目を5項目配置する。

```text
書籍名 / 著者名 / 出版社 / ISBN / 雑誌コード
```

既存の入力欄より横幅を狭くし、5項目が1行に収まるように調整する。

各入力欄を完全な均等幅にすることは必須とせず、書籍名・著者名・出版社とISBN・雑誌コードの用途を考慮して幅を調整する。

### 11.3 2行目

Version 1.5で追加する絞り込み条件と検索操作を配置する。

```text
読書状態 / お気に入り / 評価 / 検索 / 検索条件クリア
```

読書状態・お気に入り・評価はコンボボックスから選択する。

### 11.4 3行目

既存の並べ替え操作を配置する。

```text
並べ替え / 降順 / 昇順
```

並べ替え機能そのものの仕様はVersion 1.5では変更しない。

### 11.5 配置イメージ

```text
┌──────────────────────────────────── 検索 ────────────────────────────────────┐
│ 書籍名 [      ] 著者名 [      ] 出版社 [      ] ISBN [      ] 雑誌コード [      ] │
│ 読書状態 [すべて▼] お気に入り [すべて▼] 評価 [すべて▼] [検索] [検索条件クリア]      │
│ 並べ替え [登録順▼] ○降順 ○昇順                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

実際の幅・余白はGUI実装時に最小ウィンドウ幅も考慮して調整する。

## 13. 検索実行

Version 1.5では、既存の検索操作と同様に明示的な検索実行を基本とする。

検索ボタンまたは既存の検索実行操作によって、現在指定されている8項目の検索条件を使用して検索する。

コンボボックスの選択変更だけでは即時検索を実行しない。

これにより、既存の検索操作との一貫性を維持する。

---

## 14. 検索条件クリア

「検索条件クリア」を実行した場合、検索条件を以下へ戻す。

```text
書籍名
    → 空欄

著者名
    → 空欄

出版社
    → 空欄

ISBN
    → 空欄

雑誌コード
    → 空欄

読書状態
    → すべて

お気に入り
    → すべて

評価
    → すべて
```

検索条件クリア後は全件表示へ戻す。

既存仕様と同様に、並べ替え項目および昇順・降順の状態は検索条件クリアの対象としない。

---

## 15. 並べ替えとの連携

検索結果を表示している状態で並べ替え条件を変更した場合、現在の検索条件を維持する。

新しい3つの絞り込み条件だけが指定されている場合も、「検索条件あり」として扱う。

検索条件の有無を判定する処理では、既存5項目だけでなく以下も確認する。

```text
読書状態 != すべて
または
お気に入り != すべて
または
評価 != すべて
```

これにより、新しい絞り込み条件だけを使用した検索結果でも、並べ替え後に全件表示として扱われることを防ぐ。

ヘッダークリックによる並べ替えでも同じ検索条件を維持する。

## 16. 起動時ウィンドウ表示位置

### 16.1 目的

Book Manager起動時にメインウィンドウの下部が画面外へはみ出し、ステータスバーが見えなくなる場合があるため、起動時の表示位置を改善する。

### 16.2 基本方針

* 起動時にメインウィンドウを画面中央付近へ配置する。
* 既存のウィンドウサイズを基本として維持する。
* 可能な限りウィンドウ全体が利用可能な画面領域へ収まるようにする。
* 画面左上へ固定配置しない。
* 最小ウィンドウサイズの既存仕様を維持する。
* 検索条件追加によってウィンドウの縦サイズを増加させない。

### 16.3 実装時の確認事項

Tkinterで取得できる画面サイズおよび実際のウィンドウサイズを使用して中央位置を計算する。

Windowsのタスクバーなどによる利用可能領域への影響を考慮し、単純な中央配置だけで下端が画面外へ出ないか、実機で確認する。

自動テストだけで完了とせず、実際のWindows環境で起動位置とステータスバー表示を確認する。

## 17. エラー処理

検索条件として不正な内部値がServiceへ渡された場合は`ValueError`として扱う。

少なくとも以下を不正値として確認する。

```text
reading_status_filter
    → 許可されていない文字列

favorite_filter
    → 許可されていない文字列

rating_filter
    → 0
    → 6以上
    → 許可されていない文字列
    → その他の不正な値
```

GUIから通常操作する限り不正な内部値が生成されない構成とするが、Service単体でも不正値を拒否できるようにする。

Repositoryでは検索条件の業務Validationを重複実装しない。
