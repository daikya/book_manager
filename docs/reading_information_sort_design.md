# 読書情報並べ替え機能 設計書

## 1. 目的

本設計書は、Version 1.6で追加する読書状態・お気に入り・評価による並べ替え機能の仕様、責務分担、GUI連携およびテスト方針を定義する。

Version 1.5では、読書状態・お気に入り・評価を既存の書籍情報と組み合わせて絞り込めるようにした。

Version 1.6では、同じ3項目を既存の並べ替え操作へ追加し、登録済み書籍の状態や評価を目的に応じた順序で確認できるようにする。

---

## 2. 対象Version

本設計書の対象アプリケーションVersionは、Version 1.6とする。

---

## 3. 対象範囲

### 3.1 Version 1.6で対応する範囲

Version 1.6では、次の項目による昇順・降順の並べ替えに対応する。

* 読書状態
* お気に入り
* 評価

次の既存操作を拡張する。

* 並べ替えコンボボックス
* 昇順・降順ラジオボタン
* 書籍一覧の列見出しクリック
* 検索・絞り込み結果を維持した並べ替え
* 現在の検索条件と並べ替え条件を維持した再読み込み

### 3.2 Version 1.6で対応しない範囲

次の機能はVersion 1.6の対象外とする。

* 複数項目を優先順位付きで指定する並べ替え
* 利用者が任意の並び順を定義する機能
* ドラッグ操作による手動並べ替え
* 並べ替え条件の保存
* 読書情報の統計・集計・可視化
* 新しいデータベースカラムの追加
* SQLiteスキーマVersionの更新

---

## 4. 基本方針

* Version 1.5までの既存ソート処理を拡張する。
* GUI、BookService、BookRepositoryの責務分離を維持する。
* 読書状態は保存文字列の辞書順ではなく、定義した状態順で並べる。
* お気に入りは真偽値の順序を明示して並べる。
* 評価では未評価を含む順序を明示して並べる。
* 同じ状態または評価の書籍はID降順で表示する。
* 検索・絞り込み条件を維持したまま並べ替える。
* SQLの並べ替え式はアプリケーション内の許可済み定義から選択し、利用者入力を直接埋め込まない。
* 既存の並べ替え項目と動作を変更しない。

## 6. 読書状態の並べ替え仕様

### 6.1 状態順位

読書状態には次の順位を割り当てる。

| 読書状態 | 保存値 | 順位 |
| --- | --- | ---: |
| 未設定 | `None` / `NULL` | 0 |
| 未読 | `unread` | 1 |
| 読書中 | `reading` | 2 |
| 読了 | `completed` | 3 |

### 6.2 昇順

昇順では次の順序とする。

```text
未設定
↓
未読
↓
読書中
↓
読了
```

### 6.3 降順

降順では次の順序とする。

```text
読了
↓
読書中
↓
未読
↓
未設定
```

### 6.4 不正値

通常のアプリケーション操作では、読書状態へ許可値以外を保存しない。

既存DBに想定外の値が存在した場合も処理を停止させず、未設定と同じ順位0として扱う。

## 7. お気に入りの並べ替え仕様

### 7.1 状態順位

お気に入りには次の順位を割り当てる。

| お気に入り状態 | 保存値 | 順位 |
| --- | --- | ---: |
| お気に入り以外 | `False` / `0` | 0 |
| お気に入り | `True` / `1` | 1 |

### 7.2 昇順

昇順では「お気に入り以外」「お気に入り」の順とする。

### 7.3 降順

降順では「お気に入り」「お気に入り以外」の順とする。

---

## 8. 評価の並べ替え仕様

### 8.1 評価順位

評価には次の順位を割り当てる。

| 評価 | 保存値 | 順位 |
| --- | --- | ---: |
| 未評価 | `None` / `NULL` | 0 |
| ★1 | `1` | 1 |
| ★2 | `2` | 2 |
| ★3 | `3` | 3 |
| ★4 | `4` | 4 |
| ★5 | `5` | 5 |

### 8.2 昇順

昇順では次の順序とする。

```text
未評価 → ★1 → ★2 → ★3 → ★4 → ★5
```

### 8.3 降順

降順では次の順序とする。

```text
★5 → ★4 → ★3 → ★2 → ★1 → 未評価
```

未評価は、昇順では先頭、降順では末尾となる。

---

## 9. 同順位時の順序

読書状態、お気に入りまたは評価が同じ書籍は、ID降順で表示する。

これは既存の登録順における降順と同じであり、後から登録した書籍を先に表示する。

主項目を降順にした場合も、同順位時のIDは降順を維持する。

同じデータに対して並べ替えを繰り返した場合も、表示順が不規則に変化しない構成とする。

## 10. BookRepositoryの責務

### 10.1 対象メソッド

既存の次のメソッドを拡張する。

```python
get_all_sorted(
    *,
    sort_by: str,
    descending: bool = False,
) -> list[BookItem]
```

### 10.2 許可項目

`SORT_COLUMNS`または同等の許可済み定義へ、次の識別子を追加する。

* `reading_status`
* `is_favorite`
* `rating`

未許可の`sort_by`が指定された場合は、既存仕様どおり`ValueError`を送出する。

### 10.3 SQL方針

読書状態は、SQLiteの`CASE`式によって状態順位へ変換する。

概念上の式は次のとおりとする。

```sql
CASE reading_status
    WHEN 'unread' THEN 1
    WHEN 'reading' THEN 2
    WHEN 'completed' THEN 3
    ELSE 0
END
```

お気に入りは`is_favorite`の`0`と`1`を利用する。

評価は`rating`が`NULL`の場合を順位0、それ以外を保存されている1〜5の値として扱う。

概念上の式は次のとおりとする。

```sql
CASE
    WHEN rating IS NULL THEN 0
    ELSE rating
END
```

昇順では順位式へ`ASC`、降順では`DESC`を適用し、第2ソートキーは常に`id DESC`とする。

### 10.4 SQLインジェクション対策

並べ替え識別子をSQLへ直接使用しない。

アプリケーション内で定義した許可済み識別子とSQL式の対応表から、並べ替え式を取得する。

方向は`descending`の真偽値から`ASC`または`DESC`を選択する。

利用者が入力した任意文字列をSQLへ埋め込まない。

## 11. BookServiceの責務

### 11.1 `get_sorted_books()`

全書籍をRepositoryから並べ替えて取得する既存処理へ、次の許可項目を追加する。

* `reading_status`
* `is_favorite`
* `rating`

許可値検証後、既存と同様に`BookRepository.get_all_sorted()`へ委譲する。

### 11.2 `sort_books()`

GUIが取得済みの検索・絞り込み結果をメモリ上で並べ替える既存処理を拡張する。

各項目のキーは次の方針とする。

| 内部識別子 | キー |
| --- | --- |
| `reading_status` | 状態順位0〜3 |
| `is_favorite` | `False`を0、`True`を1 |
| `rating` | 未評価を0、評価済みを1〜5 |

同順位時は、既存処理と同様にID降順とする。

Repositoryによる全件並べ替えと、Serviceによる取得済み一覧の並べ替えは同じ結果になるようにする。

### 11.3 エラー処理

未許可の`sort_by`が指定された場合は、既存仕様どおり次のメッセージで`ValueError`を送出する。

```text
指定された並べ替え項目が正しくありません。
```

## 12. GUIの責務

### 12.1 並べ替えコンボボックス

`BookManagerApplication.SORT_TYPES`へ次の表示名を追加する。

* 読書状態
* お気に入り
* 評価

既存項目の後ろへ追加し、次の順序とする。

```text
登録順
書籍名
著者名
出版社
読了年月
読書状態
お気に入り
評価
```

### 12.2 Service用識別子への変換

`_get_sort_settings()`の表示名と内部識別子の対応へ、次を追加する。

| GUI表示名 | 内部識別子 |
| --- | --- |
| 読書状態 | `reading_status` |
| お気に入り | `is_favorite` |
| 評価 | `rating` |

### 12.3 一覧ヘッダークリック

`TREE_SORT_TYPE_MAP`へ、次の列名と表示名の対応を追加する。

| Treeview列名 | GUI表示名 |
| --- | --- |
| `reading_status` | 読書状態 |
| `is_favorite` | お気に入り |
| `rating` | 評価 |

別の列見出しをクリックした場合は、既存仕様どおり昇順から開始する。

同じ列見出しを再度クリックした場合は、昇順と降順を切り替える。

ヘッダークリック後は、並べ替えコンボボックスと昇順・降順ラジオボタンの状態を同期する。

### 12.4 検索・絞り込みとの連携

`_on_sort_changed()`は、既存の`_get_filtered_books()`で取得した結果を`BookService.sort_books()`へ渡す。

このため、書籍名・著者名・出版社・ISBN・雑誌コード・読書状態・お気に入り・評価の検索条件を維持したまま並べ替える。

検索条件クリアでは、既存仕様どおり検索条件だけを初期化し、選択中の並べ替え項目と方向は維持する。

### 12.5 再読み込みとの連携

再読み込み時も、現在の検索・絞り込み条件と並べ替え項目・方向を維持する。

### 12.6 エラー表示

並べ替え項目が不正な場合は、既存仕様どおり「並べ替えエラー」ダイアログへ`ValueError`の内容を表示する。

想定外の例外が発生した場合は、既存仕様どおり利用者向けの一般的なエラーメッセージを表示する。

## 17. 設計上の決定事項

Version 1.6では、次を設計上の決定事項とする。

1. 読書状態は未設定を順位0とし、未読、読書中、読了の順に並べる。
2. お気に入りはお気に入り以外を順位0、お気に入りを順位1とする。
3. 評価は未評価を順位0、評価済みを1〜5とする。
4. 降順では順位を反転し、未設定・未評価を末尾へ配置する。
5. 同順位時は並べ替え方向にかかわらずID降順とする。
6. RepositoryとServiceで同じ並べ替え結果を返す。
7. 既存のGUI操作を拡張し、新しい専用画面は追加しない。
8. データベーススキーマは変更しない。
