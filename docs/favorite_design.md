# お気に入り機能 設計書

## 1. 目的

本設計書は、book_manager Version 1.3で追加するお気に入り機能の設計を定義する。

お気に入り機能は、登録済み書籍のうち、利用者が「特に気に入っている」「重要」「すぐ見つけたい」と考える書籍へ任意の印を付けられるようにすることを目的とする。

Version 1.3では、複雑なお気に入り分類や複数種類のマークを導入せず、ON/OFFのみのシンプルな状態管理を優先する。

---

## 2. お気に入りの定義

お気に入りとは、利用者が任意の書籍に設定する識別情報である。

お気に入り状態は次の2種類のみとする。

```text
OFF
ON
```

「未設定」という第3の状態は持たない。

お気に入りを設定していない状態をOFFとして扱う。

---

## 3. 他の書籍情報との関係

お気に入り状態は、他の書籍情報とは独立して扱う。

特に次の項目とは自動連動しない。

```text
お気に入り ←→ 読書状態
お気に入り ←→ 読了年月
お気に入り ←→ 評価
```

例えば、次の状態も正常なデータとして扱う。

```text
お気に入り：ON
読書状態　：未読
評価　　　：未評価
```

お気に入り状態から読書状態や評価を推測しない。

また、将来追加する評価機能によってお気に入りを自動設定・自動解除しない。

---

## 4. データモデル

`BookItem`へお気に入り状態を追加する。

属性名は次とする。

```python
is_favorite: bool = False
```

Python側では`bool`として扱う。

値の意味は次のとおりとする。

| Python値 | 意味 |
| --- | --- |
| `False` | お気に入りではない |
| `True` | お気に入り |

既存データおよび新規登録時の初期値は`False`とする。

---

## 5. データベース

`book_items`テーブルへお気に入り状態を保持するカラムを追加する。

カラム名は次とする。

```text
is_favorite
```

SQLite上の定義は次を基本とする。

```sql
is_favorite INTEGER NOT NULL DEFAULT 0
```

SQLiteではBoolean専用型を使用せず、整数値として保持する。

値の意味は次のとおりとする。

| DB値 | 意味 |
| --- | --- |
| `0` | お気に入りではない |
| `1` | お気に入り |

`NULL`は許可しない。

---

## 6. スキーマVersion

お気に入り機能追加に伴い、SQLiteスキーマVersionを次のように更新する。

```text
Version 3
↓
Version 4
```

`SCHEMA_VERSION`は次とする。

```python
SCHEMA_VERSION = 4
```

---

## 7. Version 3からVersion 4へのマイグレーション

Version 3の既存データベースに対して、次のカラムを追加する。

```sql
ALTER TABLE book_items
ADD COLUMN is_favorite INTEGER NOT NULL DEFAULT 0
```

マイグレーション定義は、既存方式に合わせて次の名称を使用する。

```python
MIGRATE_VERSION_3_TO_4
```

既存書籍はすべて、

```text
is_favorite = 0
```

として移行する。

これにより、既存データの内容を変更せず、お気に入り状態のみOFFとして追加する。

---

## 8. 新規データベース

新規作成される`book_items`テーブルには、最初から`is_favorite`カラムを含める。

概念上は次の形式とする。

```sql
CREATE TABLE IF NOT EXISTS book_items (
    ...
    completion_month TEXT,
    reading_status TEXT,
    is_favorite INTEGER NOT NULL DEFAULT 0,
    notes TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
)
```

---

## 9. Database初期化処理

`initialize_database()`では、既存の段階的マイグレーション方針を維持する。

Version 1のデータベースは、

```text
1 → 2 → 3 → 4
```

の順番で移行する。

Version 2のデータベースは、

```text
2 → 3 → 4
```

の順番で移行する。

Version 3のデータベースは、

```text
3 → 4
```

へ移行する。

マイグレーション完了後は、

```sql
PRAGMA user_version = 4
```

となる。

---

## 10. Repository

`BookRepository`は`is_favorite`を他の`BookItem`属性と同様に永続化する。

次の処理へ追加する。

* 新規登録
* IDによる取得
* 全件取得
* 検索結果取得
* 更新
* DB行から`BookItem`への変換

RepositoryではDB値をPythonの`bool`へ変換する。

概念上は次のように扱う。

```python
is_favorite=bool(row["is_favorite"])
```

登録・更新時は、

```python
int(book_item.is_favorite)
```

などにより、

```text
False → 0
True  → 1
```

として保存する。

---

## 11. BookService

お気に入り状態はBoolean値として扱うため、読書ステータスのような文字列Validatorは追加しない。

`BookService.add_book()`へ次の引数を追加する。

```python
is_favorite: bool = False
```

新規登録時は`BookItem`へその値を設定する。

更新時も`BookItem.is_favorite`をそのままRepositoryへ渡す。

お気に入り状態によって、他の項目を変更しない。

---

## 12. Validation

Version 1.3では、お気に入り専用Validatorは作成しない。

お気に入り状態はGUI上でチェックボックスから取得し、Pythonの`bool`として扱うためである。

GUIから任意の文字列や整数値を直接入力する構成にはしない。

将来、外部入力やCSVインポートなどからお気に入り値を受け取る必要が生じた場合は、別途Validation方針を検討する。

---

## 13. GUI基本方針

お気に入り状態は、GUI上で簡単にON/OFFできるようにする。

Version 1.3では`ttk.Checkbutton`を使用する。

概念上の表示は次のとおりとする。

```text
☑ お気に入り
```

または、

```text
☐ お気に入り
```

チェックありをON、チェックなしをOFFとする。

---

## 14. GUI入力変数

お気に入り状態用の変数として`BooleanVar`を使用する。

概念上は次の形式とする。

```python
self._is_favorite_var = tk.BooleanVar(
    master=self._root,
    value=False,
)
```

初期値は`False`とする。

---

## 15. GUI配置

お気に入り追加のために新しい入力行を追加しない。

Version 1.3で追加済みの、

```text
読了年月
読書状態
```

と同じ行へ、可能な限り横並びで配置する。

基本配置は次を第一候補とする。

```text
読了年月 [2026-08]   読書状態 [読書中 ▼]   ☑ お気に入り
```

既存フォームの縦方向のサイズは増加させない。

---

## 16. GUIサイズ制約

お気に入り機能追加後も、Version 1.3で定めたGUI制約を維持する。

* 初期ウィンドウサイズの高さは800pxを上限とする。
* 新しい入力行を追加しない。
* 書籍一覧5行を可能な限り維持する。
* 内容紹介・備考の表示領域を可能な限り維持する。
* 入力フォームを縦スクロール前提の構成へ変更しない。
* 必要な調整は横方向を優先する。

お気に入り追加を理由として`WINDOW_SIZE`の高さを増加させない。

---

## 17. 書籍選択時

一覧から既存書籍を選択した場合、`BookItem.is_favorite`をチェックボックスへ反映する。

変換は次のとおりとする。

```text
False → チェックなし
True  → チェックあり
```

---

## 18. フォーム値取得

新規登録または更新時は、`BooleanVar`からお気に入り状態を取得する。

概念上は次の形式とする。

```python
"is_favorite": self._is_favorite_var.get(),
```

取得値は`bool`として扱う。

---

## 19. 新規登録

新規登録時は、お気に入り状態を`BookService.add_book()`へ渡す。

概念上は次の形式とする。

```python
self._service.add_book(
    ...,
    reading_status=values["reading_status"],
    is_favorite=values["is_favorite"],
    notes=values["notes"],
)
```

未チェックの場合は`False`として登録する。

---

## 20. 更新

更新用`BookItem`を生成する際に、お気に入り状態を設定する。

概念上は次の形式とする。

```python
BookItem(
    ...,
    reading_status=values["reading_status"],
    is_favorite=values["is_favorite"],
    notes=values["notes"],
)
```

ONからOFF、OFFからONの両方向へ更新できるようにする。

---

## 21. フォームクリア

既存の`_clear_form()`へお気に入り状態の初期化を追加する。

フォームクリア時は、

```text
OFF
```

へ戻す。

次の場合も同様とする。

* 入力クリアボタン押下時
* 新規登録成功後
* 更新成功後
* 削除後のフォーム初期化
* 更新対象が存在しない場合のフォーム初期化

概念上は次の形式とする。

```python
self._is_favorite_var.set(False)
```

---

## 22. 書籍一覧

Version 1.3では、書籍一覧へお気に入り状態を識別できる列を追加する。

列名は次とする。

```text
お気に入り
```

一覧表示値は次とする。

| 状態 | 一覧表示 |
| --- | --- |
| OFF | 空欄 |
| ON | `★` |

一覧では`True`、`False`、`1`、`0`などの内部値を直接表示しない。

---

## 23. お気に入り列

お気に入り列は短い表示のみを行うため、狭い固定幅を基本とする。

第一候補は次とする。

```text
50〜70px程度
```

中央揃えとする。

お気に入り列追加によって一覧全体を必要以上に広げない。

既存の横スクロールバーはそのまま利用する。

---

## 24. 一覧表示件数

お気に入り列追加後も、書籍一覧5行を可能な限り維持する。

お気に入り列は横方向に追加するため、TreeViewの高さおよび行高は変更しない。

表紙サムネイル表示も既存仕様を維持する。

---

## 25. 検索

Version 1.3では、お気に入り状態を複合条件検索の対象に追加しない。

既存の検索対象、

```text
書籍名
著者名
出版社
ISBN
雑誌コード
```

を維持する。

「お気に入りだけ表示する」機能が実利用で必要と判断された場合は、将来Versionで検討する。

---

## 26. ソート

Version 1.3では、お気に入り状態をソート対象に追加しない。

お気に入り列のヘッダークリックによるソートも実装しない。

「お気に入りを先頭に表示する」機能が実利用で必要と判断された場合は、将来Versionで検討する。

---

## 27. 読書ステータスとの関係

お気に入り状態と読書ステータスは独立して扱う。

例えば次のすべてを正常な状態として扱う。

```text
お気に入り：ON
読書状態　：未読
```

```text
お気に入り：ON
読書状態　：読書中
```

```text
お気に入り：ON
読書状態　：読了
```

```text
お気に入り：OFF
読書状態　：読了
```

読書状態の変更によってお気に入りを自動変更しない。

---

## 28. 読了年月との関係

お気に入り状態と読了年月も独立して扱う。

お気に入りのON/OFFによって読了年月を変更しない。

読了年月の有無によってお気に入り状態を変更しない。

---

## 29. 評価機能との関係

Version 1.3で今後追加予定の評価機能とは独立して扱う。

例えば、

```text
お気に入り：ON
評価　　　：3
```

という状態も正常とする。

評価が5であっても自動的にお気に入りONとはしない。

お気に入りONであっても評価を自動設定しない。

利用者がそれぞれ独立して設定する。

---

## 30. 外部書誌情報取得

Google Books APIやopenBDなどから取得する書誌情報には、お気に入り状態を含めない。

外部書誌情報取得によってお気に入り状態を変更しない。

既存の入力済み項目上書き確認にもお気に入り状態は含めない。

---

## 31. CSVエクスポート

お気に入り状態は利用者が管理する正式な蔵書情報であるため、CSVエクスポート対象へ追加する。

CSVヘッダーは次とする。

```text
お気に入り
```

人が閲覧・利用するCSVという既存方針に合わせて、内部値ではなく日本語で出力する。

変換は次のとおりとする。

| 内部値 | CSV出力 |
| --- | --- |
| `False` | いいえ |
| `True` | はい |

CSVでは`0`、`1`、`False`、`True`などの内部表現を直接出力しない。

---

## 32. CSV列位置

お気に入り列は、読書状態の直後へ追加することを第一候補とする。

概念上は次の順序とする。

```text
読了年月
読書状態
お気に入り
備考
```

読書状態と同様に、利用者が管理する書籍状態情報をまとめて配置する。

CSV出力列数は、読書状態対応後の12列から13列となる。

---

## 33. CSV出力例

概念上は次の形式となる。

```text
書籍名,読了年月,読書状態,お気に入り,...
書籍A,2026-08,読了,はい,...
書籍B,,未読,いいえ,...
```

お気に入りOFFも明示的に「いいえ」と出力する。

これは一覧表示とは異なり、CSVでは値の意味を明確にするためである。

---

## 34. CSVとGUI一覧の表示差

お気に入り状態は表示用途に応じて次のように表現する。

```text
GUI一覧
ON  → ★
OFF → 空欄

CSV
ON  → はい
OFF → いいえ
```

GUI一覧では視認性と省スペース性を優先する。

CSVでは意味の明確さを優先する。

---

## 35. 表紙画像

お気に入り追加によって、表紙画像取得・キャッシュ・フォーム表示・一覧サムネイル表示の仕様を変更しない。

お気に入り列追加後も表紙サムネイル付き一覧を維持する。

---

## 36. エラー処理

お気に入り状態はチェックボックスからBoolean値として取得するため、通常のGUI操作では不正値は発生しない。

お気に入り機能追加による独自エラーダイアログは設けない。

DB・Repository・Serviceで例外が発生した場合は、既存の登録・更新エラー処理を使用する。

---

## 37. 自動テスト

お気に入り機能には必要な自動テストを追加する。

主な対象は次のとおりとする。

### Database

* 新規DBへ`is_favorite`カラムが作成される。
* `is_favorite`が`NOT NULL`である。
* デフォルト値が`0`である。
* Version 3からVersion 4へマイグレーションできる。
* 既存データが`is_favorite = 0`として維持される。
* Version 1からVersion 4まで段階的に移行できる。

### Model

* `is_favorite`の初期値が`False`である。
* `True`を保持できる。

### Repository

* `False`を登録・取得できる。
* `True`を登録・取得できる。
* OFFからONへ更新できる。
* ONからOFFへ更新できる。
* 他項目と独立して保持できる。

### Service

* 新規登録時にお気に入り状態を保存できる。
* 初期値`False`で登録できる。
* ONからOFFへ更新できる。
* OFFからONへ更新できる。
* 読書状態・読了年月と独立して保持できる。

### GUI

* 初期状態がOFFである。
* チェック状態をBoolean値として取得できる。
* 既存書籍選択時にON/OFFをフォームへ反映できる。
* フォームクリア時にOFFへ戻る。
* 新規登録成功後にOFFへ戻る。
* 更新成功後にOFFへ戻る。
* 一覧でONを`★`として表示できる。
* 一覧でOFFを空欄として表示できる。
* 既存GUI機能に回帰がない。

### CSV

* ONを「はい」として出力できる。
* OFFを「いいえ」として出力できる。
* 読書状態とお気に入りを正しい列順で出力できる。
* 既存の特殊文字・UTF-8 BOMなどの仕様に回帰がない。
