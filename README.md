# book_manager

`book_manager` は、ISBNから書誌情報を取得し、ローカル環境で蔵書を管理するためのデスクトップアプリケーションです。

Google Books APIおよびopenBDを利用して書誌情報を取得し、SQLiteデータベースへ保存します。登録した書籍情報は編集・検索・並べ替えができ、表紙画像の取得・キャッシュ・再表示にも対応しています。

データはローカル環境へ保存するため、専用のデータベースサーバーを必要としません。

個人利用を目的とした蔵書管理アプリケーションとして、保守性・テスト容易性・品質を重視して開発しています。

## 主な機能

### 書籍管理

* 書籍情報の登録・更新・削除
* SQLiteによるローカルデータベース管理
* 読了年月・備考の記録

### 読書情報の管理

* 読書ステータスを「未読」「読書中」「読了」で管理
* お気に入りをON/OFFで管理
* 1〜5段階の評価を設定
* 読書ステータス・お気に入り・評価を書籍一覧へ表示

### 読書履歴の管理

* 一つの書籍へ複数の読書履歴を登録
* 一回ごとの読書開始日・読了日・読書メモを記録
* 登録済み履歴を新しい順に表示し、変更・削除
* 現在の読書状態・読了年月とは独立して履歴を管理

### 読書記録の集計

* 読書履歴総数、履歴のある書籍数、読了記録数、再読書籍数を表示
* 読了記録が存在する年を選択
* 選択した年の1月から12月までの読了数を表示
* 月別読了数を棒グラフで可視化
* 読了記録がない場合も0件または空状態として表示

### タグによる分類

* 一つの書籍へ複数のタグを設定
* 登録済みタグを複数の書籍で共通利用
* 書籍一覧へタグを表示
* タグ名の変更と、使用中・未使用タグの削除
* タグ未設定の書籍も従来どおり管理

### 書誌情報取得

* ISBNからGoogle Books APIおよびopenBDを利用して書誌情報を取得
* 複数の取得元から不足している情報を補完
* 取得した書誌情報を入力フォームへ反映

### 表紙画像

* 表紙画像の取得
* 表紙画像のローカルキャッシュ
* アプリケーション再起動後の表紙画像再表示
* 設定画面でのキャッシュ件数・合計サイズ確認、保存先表示および手動削除
* キャッシュ削除後、選択した書籍だけを対象とする必要時再取得

### 検索

次の項目による検索に対応しています。

* 書籍名
* 著者名
* 出版社
* ISBN
* 雑誌コード
* 読書状態
* お気に入り
* 評価
* タグ
* タグ未設定

書籍名・著者名・出版社は部分一致検索に対応しています。

読書状態は「未設定」「未読」「読書中」「読了」、お気に入りは「お気に入りのみ」「お気に入り以外」で絞り込めます。

評価は「未評価」または指定した評価以上の書籍を絞り込めます。

既存の書籍情報、読書状態・お気に入り・評価、タグは、AND条件で組み合わせて検索できます。

### 並べ替え

次の項目による昇順・降順の並べ替えに対応しています。

* 登録順
* 書籍名
* 著者名
* 出版社
* 読了年月
* 読書状態
* お気に入り
* 評価

検索結果を表示している場合も、検索条件を維持したまま並べ替えることができます。

一覧のID・書籍名・著者名・出版社・読了年月・読書状態・お気に入り・評価のヘッダーをクリックして並べ替えることもできます。

同じヘッダーを再度クリックすると、昇順・降順が切り替わります。

### 自動バックアップ

SQLiteデータベースのバックアップが必要かどうかを、アプリケーションの起動時に判定します。起動したまま間隔が経過しても、その場で自動作成する機能はありません。

バックアップにはSQLite Backup APIを利用し、バックアップファイルは`backups`ディレクトリへ保存します。

既定では24時間間隔・最大10世代です。設定画面で間隔（1～168時間）と世代数（2～100件）を保存すると、次回起動から適用されます。設定変更だけでは既存ファイルを削除せず、新しいバックアップが作成・検証された後に古い世代を整理します。

バックアップに失敗した場合もアプリケーションの起動は継続し、利用者へエラーを通知します。

ただし、バックアップ設定ファイルが壊れているなど読み込めない場合は、安全のためDB操作前に起動を停止し、ログと起動エラーを表示します。設定ファイルを勝手に削除・上書きしません。

### ウィンドウ状態の保存と復元

メインウィンドウの通常位置・サイズ・最大化状態は、正常終了時に利用者データ領域の`window_state.json`へ保存されます。次回起動時には、保存した通常矩形を設定した後で最大化状態を復元します。最小化状態は引き継ぎません。

複数モニターの負の座標を扱い、保存位置が現在のモニターと重なる場合は元の配置を維持します。モニターを外した場合、保存位置が完全に画面外の場合、解像度が小さくなった場合は、操作可能な作業領域へ位置とサイズを補正します。

状態ファイルが未設定または破損している場合も、既定の`1350×800`を基本として画面内へ収まるサイズで中央付近に表示し、書籍データの読み込みを妨げません。

設定画面の「ウィンドウ配置」から保存状態を初期化できます。初期化した現在のセッションでは状態を再保存せず、次回起動時に既定配置へ戻った後から保存を再開します。

### 一覧表示状態の保存と復元

書籍一覧の全13列の幅、並べ替え列および昇順・降順は、正常終了時に利用者データ領域の`list_view_state.json`へ保存されます。次回起動時には列幅と並べ替え状態を復元します。検索条件、選択中の書籍、スクロール位置、列順序は保存しません。

状態ファイルが未設定または破損している場合は、既定の列幅と登録順・降順で起動します。列構成が変わった場合は未知の列を無視し、不足する既知の列へ既定幅を補うため、利用可能な設定だけを安全に引き継げます。

設定画面の「一覧表示」から保存状態を初期化できます。初期化した現在のセッションでは状態を再保存せず、次回起動時に既定表示へ戻った後から保存を再開します。

### CSVエクスポート

登録済みの書籍情報をCSVファイルへエクスポートできます。

CSVファイルはUTF-8 BOM付きで保存され、Windows版Excelで日本語を扱いやすい形式としています。

「内容紹介」「備考」などに含まれる改行や、カンマ、ダブルクォートも保持したまま出力できます。

複数のタグはタグ列へ`|`区切りで出力され、再インポート時にも保持されます。

保存時にはファイルの保存先とファイル名を指定できます。

### CSVインポート

* Book Manager自身が出力したCSVファイルから書籍データを取り込み
* 読書ステータス・お気に入り・評価を含めてインポート
* 複数タグを含む新形式CSVと、タグ列を持たない旧形式CSVの両方に対応
* ISBNまたは雑誌コードが既存データと重複する場合はスキップ
* 既存データは自動更新せず、新しい書籍だけを登録
* 不正な行が含まれていても、正常な行の登録を継続
* 登録件数・スキップ件数・エラー件数をインポート完了後に表示

### バックアップからの復元

* GUIから復元するSQLiteバックアップファイルを選択
* 復元前にバックアップファイルの正常性を確認
* 復元前の現在のデータベースを自動的にバックアップ
* 現在のアプリケーションより新しいスキーマVersionのバックアップを拒否
* 復元完了後に書籍一覧を自動的に再読み込み
* 書籍情報・タグ・読書履歴をまとめて保持

## システム構成

```text
                         +-------------------------+
                         |  BookManagerApplication |
                         |      GUI (Tkinter)      |
                         +------------+------------+
                                      |
                                      v
                         +-------------------------+
                         |      BookService        |
                         +------+-----------+------+
                                |           |
                                |           |
                                v           v
                     +---------------+   +----------------------+
                     |BookRepository |   | BookMetadataService  |
                     +-------+-------+   +----------+-----------+
                             |                     |
                             v                     |
                        +----------+               |
                        |  SQLite  |               |
                        +----------+               |
                                                   |
                             +---------------------+----------------------+
                             |                                            |
                             v                                            v
                   Google Books API                                  openBD

                             +----------------------+
                             | CoverImageService    |
                             +----------+-----------+
                                        |
                                        v
                                 cache/covers
```

### アーキテクチャ

`book_manager` は、GUI・業務処理・データアクセスを分離した構成を採用しています。

* GUIはTkinterで実装しています。
* 業務処理は`BookService`が担当します。
* SQLiteへのデータアクセスは`BookRepository`が担当します。
* 読書履歴の業務処理は`ReadingHistoryService`が担当します。
* 読書履歴のSQLiteアクセスは`ReadingHistoryRepository`が担当します。
* 読書記録の集計と表示用データの整形は`ReadingHistoryService`が担当します。
* ISBNからの書誌情報取得は`BookMetadataService`が担当し、Google Books APIおよびopenBDを利用します。
* 表紙画像は`CoverImageService`が取得・キャッシュし、再利用します。

各コンポーネントの役割を分離することで、保守性とテスト容易性を高めています。

設計の詳細については、`docs`配下の設計書およびADRを参照してください。

## インストール

Version 2.2.0では、GitHub Releaseから次のWindowsインストーラーをダウンロードして実行します。

```text
BookManager-2.2.0-windows-x64-setup.exe
```

インストーラーは利用者単位で動作し、既定では次へ本体を配置します。

```text
%LOCALAPPDATA%\Programs\BookManager
```

書籍データ、バックアップ、表紙画像およびログは、アンインストール後も次へ保持されます。

```text
%LOCALAPPDATA%\book_manager
```

インストーラーはコード署名されていないため、Windowsが警告を表示する場合があります。公式GitHub Releaseから取得し、掲載されたSHA-256チェックサムと一致することを確認してください。

### Windowsインストーラーで導入する

1. インストーラーと同名の`.sha256.txt`を同じフォルダーへ保存する。
2. PowerShellの`Get-FileHash`でSHA-256が一致することを確認する。
3. インストーラーを実行する。
4. 必要に応じてデスクトップショートカット作成を選択する。
5. インストール完了後、スタートメニューから「Book Manager」を起動する。

インストーラーは管理者権限を要求せず、スタートメニューショートカットを作成する。

### 更新する

Book Managerを終了してから、新しいVersionのインストーラーを実行する。

固定のアプリケーション識別子と同じインストール先を使用するため、既存Versionから上書き更新される。更新しても`%LOCALAPPDATA%\book_manager`の利用者データは保持される。

### アンインストールする

Windowsの「設定」から「アプリ」→「インストールされているアプリ」を開き、「Book Manager」をアンインストールする。

アンインストールすると本体とショートカットは削除されるが、書籍データ、バックアップ、表紙画像およびログは`%LOCALAPPDATA%\book_manager`へ残る。完全に削除する場合だけ、必要なバックアップを取得した後でこのフォルダーを手動削除する。

以下は、ソースコードから起動する開発者向けの手順です。

## Google Books APIの設定

`book_manager`では、ISBNからの書誌情報取得にGoogle Books APIおよびopenBDを利用します。

メイン画面の「設定」から、Google Books APIキーの設定状態を確認し、登録・変更・削除できます。登録したAPIキーはWindowsの利用者環境変数`GOOGLE_BOOKS_API_KEY`へ保存され、アプリケーションの再起動後も使用できます。

設定画面の入力欄はマスクされ、登録済みのAPIキーそのものは表示されません。APIキーを保存または削除すると、起動中のアプリケーションにも反映されます。

同じ設定画面の「バックアップ」欄では、最後のバックアップの日時・ファイル、件数、現在有効な間隔・世代数を確認できます。「今すぐバックアップ」は設定間隔に関係なく作成します。表示はファイルの存在を示すもので、復元可能性を保証するものではありません。

「表紙画像キャッシュ」欄では、キャッシュのファイル件数と合計サイズを確認し、保存先フォルダーを開くことができます。確認後にキャッシュだけを削除でき、DB、バックアップおよび各種設定ファイルは変更しません。削除後は一覧から画像が消え、表紙画像URLを持つ書籍を選択した場合だけ、その1冊の画像を必要時に再取得します。

設定画面は高さ800ピクセル以内に収まり、内容部分を縦方向へスクロールできます。「閉じる」ボタンはスクロール領域の外に固定され、画面下部へ隠れないように配置されます。

間隔と世代数を変更して「設定を保存」を押すと、`%LOCALAPPDATA%\book_manager\backup_settings.json`へ記録され、アプリケーションの次回起動時から反映されます。`BOOK_MANAGER_HOME`を使用している場合は、指定した利用者データ領域直下に保存されます。APIキーはこのJSONファイルへ保存しません。

利用者環境変数は暗号化された秘密情報保管庫ではありません。APIキーはGitリポジトリ、ログ、画面共有および公開ファイルへ含めないでください。

### 設定画面を使用する場合

1. メイン画面の「設定」を押す。
2. Google Books APIキーを入力する。
3. 「保存」を押す。
4. 設定状態が「設定済み」になったことを確認する。

APIキーを削除する場合は「削除」を押し、確認画面で承認します。

以下は、ソース版の起動前にPowerShellから設定する場合の代替手順です。

### 現在のPowerShellセッションだけに設定する場合

```powershell
$env:GOOGLE_BOOKS_API_KEY="取得したAPIキー"
```

この方法で設定した値は、PowerShellを終了すると失われます。

### Windowsのユーザー環境変数として保存する場合

```powershell
setx GOOGLE_BOOKS_API_KEY "取得したAPIキー"
```

`setx`で設定した値は、新しく起動したPowerShellから利用できます。

設定後は現在のPowerShellを終了し、新しいPowerShellを起動してください。

APIキーはGitリポジトリへ登録しないでください。

## 基本的な使い方

### 書籍を登録する

1. 書籍名、ISBN、著者名、出版社などの情報を入力します。
2. 必要に応じて読了年月や備考を入力します。
3. 「新規登録」を実行すると、書籍情報がSQLiteデータベースへ保存されます。

ISBNを入力して「書誌情報取得」を実行すると、Google Books APIおよびopenBDから取得した書誌情報を入力フォームへ反映できます。

表紙画像が取得できる場合は、表紙画像も画面へ表示されます。

### 登録済みの書籍を編集する

書籍一覧から編集する書籍を選択すると、登録済みの内容が入力フォームへ表示されます。

内容を修正して「更新」を実行すると、登録済みの書籍情報が更新されます。

### 書籍を削除する

書籍一覧から削除する書籍を選択し、「削除」を実行します。

削除前に確認画面が表示されます。

### 読書履歴を管理する

1. 書籍一覧から対象の書籍を選択します。
2. 「読書履歴」をクリックします。
3. 読書開始日・読了日・読書メモを入力して登録します。
4. 登録済みの履歴を選択すると、内容の変更または削除ができます。

読書開始日と読了日は`YYYY-MM-DD`形式で入力します。どちらか一方だけ、または読書メモだけでも登録できます。

読書履歴を操作しても、書籍情報にある現在の読書状態と読了年月は自動的に変更されません。

### 読書記録を集計する

1. メイン画面の「読書集計」をクリックします。
2. 履歴総数・履歴のある書籍数・読了記録数・再読書籍数を確認します。
3. 読了記録が複数年にある場合は、対象年を選択します。
4. 選択年の月別読了数と棒グラフを確認します。

書籍を選択していなくても利用できます。集計画面から書籍情報や読書履歴が変更されることはありません。

### 書籍を検索する

次の項目から登録済みの書籍を検索できます。

* 書籍名
* 著者名
* 出版社
* ISBN
* 雑誌コード
* 読書状態
* お気に入り
* 評価

書籍名・著者名・出版社は部分一致検索に対応しています。

読書状態・お気に入り・評価は、それぞれ「すべて」を選択すると絞り込み条件から除外されます。

複数の項目を指定した場合は、すべての条件を満たす書籍が表示されます。

「検索条件クリア」を実行すると、すべての検索項目が初期状態へ戻り、全件表示へ戻ります。

### 一覧を並べ替える

次の項目で書籍一覧を並べ替えることができます。

* 登録順
* 書籍名
* 著者名
* 出版社
* 読了年月
* 読書状態
* お気に入り
* 評価

昇順・降順を切り替えることができます。

検索結果を表示している場合も、検索条件を維持したまま並べ替えることができます。

また、一覧のID・書籍名・著者名・出版社・読了年月・読書状態・お気に入り・評価のヘッダーをクリックして並べ替えることもできます。

同じヘッダーを再度クリックすると、昇順・降順が切り替わります。

### CSVへエクスポートする

「CSVエクスポート」を実行すると、登録済みの書籍情報をCSVファイルへ保存できます。

保存ダイアログから保存先とファイル名を指定してください。

CSVファイルはUTF-8 BOM付きで保存され、内容紹介や備考に含まれる改行も保持されます。

### CSVインポート

1. 「CSVインポート」をクリックする。
2. Book ManagerでエクスポートしたCSVファイルを選択する。
3. CSVファイルの内容が読み込まれ、新しい書籍データが登録される。
4. インポート完了後、登録件数・スキップ件数・エラー件数を確認する。

ISBNまたは雑誌コードが既存データと重複する書籍はスキップされ、既存データは更新されません。

不正な行が含まれている場合も、正常な行の登録は継続されます。

### バックアップからの復元

1. 「バックアップ復元」をクリックする。
2. 復元するSQLiteバックアップファイル（`.db`）を選択する。
3. 確認ダイアログの内容を確認し、復元を実行する。
4. 復元が完了すると、書籍一覧が自動的に再読み込みされる。

復元前には現在のデータベースが自動的にバックアップされます。

復元元のデータベースが破損している場合、Book Manager用のデータベースではない場合、または現在のアプリケーションより新しいスキーマVersionの場合は復元されません。

### 一覧を再読み込みする

「再読み込み」を実行すると、現在の検索条件と並べ替え条件を維持したまま、データベースの最新内容を一覧へ反映します。

## データ保存場所

`book_manager`では、書籍情報と表紙画像をローカル環境へ保存します。

ソース版とWindows配布版は、既定で次の利用者データフォルダーを共通して使用します。

```text
%LOCALAPPDATA%\book_manager
```

### SQLiteデータベース

書籍情報は次のSQLiteデータベースへ保存されます。

```text
%LOCALAPPDATA%\book_manager\data\books.db
```

`books.db`には登録した書籍情報、タグおよび読書履歴が保存されます。

### 表紙画像キャッシュ

取得した表紙画像は次のディレクトリへキャッシュされます。

```text
%LOCALAPPDATA%\book_manager\cache\covers\
```

キャッシュ済みの画像が存在する場合は、その画像を再利用します。

設定画面からファイル件数と合計サイズを確認し、必要な場合だけ手動で削除できます。削除対象はこのディレクトリ直下のファイルに限定され、ディレクトリ自体、DBおよび設定ファイルは保持されます。削除後の一覧表示では一括ダウンロードを行わず、選択した書籍に利用可能な表紙画像URLがある場合だけ1件を再取得します。

### データベースバックアップ

自動バックアップされたSQLiteデータベースは次のディレクトリへ保存されます。

```text
%LOCALAPPDATA%\book_manager\backups\
```

バックアップはアプリケーション起動時に必要性を判定して作成され、古いバックアップは設定された保存世代数に従って自動的に整理されます。

設定変更だけでは古いバックアップを削除しません。新規バックアップの作成・検証が成功した後に世代整理します。同じ秒に複数回作成した場合は連番を付けて既存ファイルを上書きしません。

自動バックアップで作成されたデータベースは、「バックアップ復元」から復元元として選択できます。

復元を実行する場合は、選択したバックアップで現在のデータベースを置き換える前に、現在のデータベースが新しいバックアップとして保存されます。

### ログ

起動、終了およびエラーのログは次のファイルへ記録されます。

```text
%LOCALAPPDATA%\book_manager\logs\book_manager.log
```

ログは一定サイズでローテーションされます。APIキーなどの秘密情報は記録しません。

### Version 1.9以前からのデータ移行

新しい保存先にデータベースがなく、プロジェクト内の従来の`data\books.db`が存在する場合は、初回起動時に既存データを新しい保存先へ複製します。

移行元のデータは削除せず、新しい保存先にデータベースが存在する場合は上書きしません。移行完了後の起動では、移行メッセージを繰り返し表示しません。

## 開発方針

`book_manager`では、設計・実装・テスト・ドキュメントを重視した開発を行っています。

主な方針は次のとおりです。

* 小さく完成させる。
* シンプルな設計を優先する。
* 設計してから実装する。
* ドキュメントを正式な成果物として扱う。
* 設計書と実装の整合性を維持する。
* GUI・業務処理・データアクセスの責務を分離する。
* 重要な設計判断はADRへ記録する。
* 一つのVersionで過剰な機能を追加しない。
* コミットは原則として一つの目的ごとに分ける。

詳細については、次のドキュメントを参照してください。

* [開発指針](docs/development_guidelines.md)
