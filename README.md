# book_manager

購入した書籍、雑誌、文庫、ムック、単行本、電子書籍などを、ローカル環境で管理するためのデスクトップアプリケーションです。

書籍情報はSQLiteデータベースへ保存し、書籍名による検索、書籍情報の登録・編集・削除、読了年月や備考の記録などを行えるようにします。

---

## 1. プロジェクトの目的

`book_manager` は、所有している出版物を一元管理することを目的としたローカルデスクトップアプリケーションです。

主な目的は次のとおりです。

* 所有している書籍や雑誌を一覧で管理する。
* ISBNまたは雑誌コードを利用して書籍情報を取得する。
* 書籍情報をローカルのSQLiteデータベースへ保存する。
* 書籍名の一部から対象の書籍を検索する。
* 読了年月や備考を利用者が記録できるようにする。
* WindowsとmacOSの両方で利用できる構成を目指す。
* 長期間保守しやすい設計とする。

## 2. Version 0.1の目標

Version 0.1では、必要最小限の書籍管理機能を完成させます。

予定している主な機能は次のとおりです。

* 書籍情報の登録
* 書籍情報の一覧表示
* 書籍情報の編集
* 書籍情報の削除
* 書籍名の部分検索
* ISBNの入力
* ISBNの形式確認
* 雑誌コードの入力
* SQLiteへのデータ保存
* 読了年月の入力
* 備考の入力

将来必要になる可能性だけを理由として、Version 0.1へ過剰な機能を追加しません。

## 3. 管理する書籍情報

Version 0.1では、主に次の情報を管理します。

| 項目    | 説明            |
| ----- | ------------- |
| ISBN  | 書籍のISBN       |
| 雑誌コード | 雑誌に付与されているコード |
| 書籍名   | 書籍や雑誌の名称      |
| 著者名   | 著者、編者などの名称    |
| 出版社   | 出版元           |
| 出版形態  | 文庫、単行本、電子書籍など |
| 内容紹介  | 書籍の概要         |
| 読了年月  | 利用者が読み終えた年月   |
| 備考    | 利用者が自由に入力するメモ |

詳細なカラム定義は、データベース設計書に記載します。

## 7. 想定するアプリケーション構成

現時点では、次のような責務分離を予定しています。

```text
GUI
↓
Service
↓
Repository
↓
SQLite
```

### GUI

利用者からの入力を受け取り、処理結果を画面へ表示します。

### Service

入力値の検証、データの正規化、登録や更新などの業務処理を担当します。

### Repository

SQLiteへの登録、検索、更新、削除を担当します。

### Model

書籍情報など、アプリケーション内で扱うデータ構造を表現します。

外部サービスから書籍情報を取得する機能は、Version 0.1の進行状況を確認しながら段階的に追加します。

## 8. データ保存

書籍情報は、ローカル環境のSQLiteデータベースへ保存します。

予定しているデータベースファイル名は次のとおりです。

```text
book_manager.db
```

SQLiteを採用する主な理由は次のとおりです。

* 専用のデータベースサーバーが不要である。
* 一つのファイルとして管理できる。
* Pythonから標準ライブラリで利用できる。
* 個人利用のデスクトップアプリケーションに適している。
* バックアップが比較的容易である。

詳しい設計理由は、データベース設計書およびADRへ記録します。
